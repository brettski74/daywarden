# User Voice

As a parent, I want to manage the current spelling words and the revision pool by dropping audio files into directories on the host, and I want to set how many words he must get right from each pool, so that I can update his spelling lists without rebuilding containers.

As a child, I want to hear each word, optionally replay it or hear it used in a sentence, and type my spelling into a large box, getting another chance at words I miss until my spelling is done.

# Use Cases

## Host data directory and word pool files

- A host directory for Daywarden runtime data is mounted read-only into the `decisions` container at `/var/lib/daywarden`. In `.env` and `docker-compose.yml`, the host path is `DAYWARDEN_DATA_DIR`, which defaults to `${HOME}/daywarden`. Inside the container, the root path is read from the `DAYWARDEN_DATA_DIR` environment variable (default `/var/lib/daywarden`).
- Each spelling task has two word pools: `current` (words currently being learned) and `revision` (previously learned words for periodic revision). By default, their directories are `spelling/current` and `spelling/revision` under `DAYWARDEN_DATA_DIR`. A task can set `current_dir` and `revision_dir` in its `body` to use different relative paths under `DAYWARDEN_DATA_DIR` (for example, `spelling/younger/current`).
- Supported audio file extensions are `.mp3`, `.wav`, `.ogg`, `.opus`, and `.m4a` (case-insensitive), matching `policy/sounds.py`. Hidden files (names starting with `.`) and files with other extensions (such as notes) are ignored.
- Each word entry in a pool directory is defined by file naming convention:
  - `<word>.<ext>` — the required recording of the word spoken clearly on its own.
  - `<word>.sentence.<ext>` — an optional recording of a sentence using the word.
  - To support homographs (such as present-tense and past-tense "read"), an entry may include a positive whole-number suffix: `<word>.<n>.<ext>` and `<word>.<n>.sentence.<ext>` (for example, `read.1.opus`, `read.1.sentence.opus`, `read.2.opus`, and `read.2.sentence.opus`).
- The `<word>` portion is the exact spelling of the word. It may contain letters (`a`–`z`, `A`–`Z`), dashes (`-`), and apostrophes (`'`). For homographs (`<word>.<n>`), the expected spelling is still `<word>`; `read.1` and `read.2` are distinct entries in the pool with their own audio clips, and either or both can be asked.
- An entry's word clip and sentence clip do not have to share the same extension (`rope.opus` and `rope.sentence.mp3` pair together for `rope`).
- Entry keys (`<word>` or `<word>.<n>`) are matched case-insensitively when pairing word and sentence clips and checking for duplicates, while the casing of `<word>` from the word clip's filename is kept for display.
- Scanning and caching:
  - The directories are checked when the policy is loaded at start-up, and re-scanned with `os.scandir` whenever a new run starts on an attempt.
  - Audio durations are cached in memory by `(path, mtime_ns, size)` so only new or modified files are inspected. Starting a quiz has no noticeable delay, and adding, replacing, or moving audio files on the host takes effect on the next run without restarting the container.
  - When a run starts, the entries and targets for that run are snapshotted onto the attempt's `detail`, so file changes on disk while a run is in progress do not disturb that run.

## Queue and drawing rules

- Let `m` be the number of entries in `current`, `n` be `current_required` (the required correct count for `current`), and `x` be `revision_required` (the required correct count for `revision`).
- At the start of a run, choose `x` distinct entries at random from `revision`. Combine those `x` entries with all `m` entries from `current` and shuffle them at random to form the opening queue.
- Each question pops the next entry from the front of the queue.
- Comparison of his submitted answer against `<word>` ignores leading and trailing whitespace and is case-insensitive.
- A correct spelling scores 1 point toward the pool (`current` or `revision`) the entry came from.
- A wrong submission or a timeout scores 0 points and applies the re-queue rule for that entry's pool:
  - **`current` entry**: if the `current` correct count in this run is still below `n`, the same entry is placed at the end of the queue. Once the `current` correct count has reached `n`, a missed `current` entry is not placed back on the queue; it still counts as having been asked.
  - **`revision` entry**: if the `revision` correct count in this run is still below `x`, a different `revision` entry — chosen at random from those in the `revision` pool that have not been spelled correctly in this run and are not already waiting in the queue — is placed at the end of the queue. If no such replacement entry exists in `revision`, the missed `revision` entry itself is placed at the end of the queue.
- An entry from `current` counts as having been asked once a question for it finishes (correct, wrong, or timed out).

## Screen and controls

- The start screen says "Spelling", shows his progress for both pools as `"Current: 0 / n · Revision: 0 / x"` (or his current counts when resuming), and has a focused "Start" button, as in S004.1. No timer runs on the start screen.
- The top of the question screen shows `"Current: c / n · Revision: r / x"` on the left and `"Try a different task"` on the right.
- At the top of the question area sit two large buttons:
  - Top left: **"Repeat word"**
  - Top right: **"Use in a sentence"**
- Both buttons are large and colourful when enabled: blue text (`#1d4ed8`) on a pale blue background (`#dbeafe`) with a subtle border that turns solid blue (`#2563eb`) when the mouse moves over them.
- When disabled, a button loses its colour and changes to a pale grey background (`#e5e7eb`) with light grey text (`#9ca3af`) and a grey border, and hovering over it or clicking it does nothing.
- "Repeat word" is disabled once he has used all `maximum_replays` replays for the current question (or for the whole question when `maximum_replays` is `0`).
- "Use in a sentence" is disabled for the whole question when the current entry has no `.sentence.` file or when `maximum_sentence_plays` is `0`, and becomes disabled once he has used all `maximum_sentence_plays` plays for the current question.
- Below the buttons is a single-line text input box in a large font, wide enough to fit the 16-letter word `"extemporaneously"` on one line without scrolling or clipping.
- The input box accepts letters (`a`–`z`, `A`–`Z`), dash (`-`), and apostrophe (`'`). Leading and trailing spaces are ignored on submit, and other characters (such as digits or symbols) do not appear in the box.
- A timer bar at the bottom shrinks from full to empty over the question's `timeout`.

## Audio playback, timer pausing, and server timing

- Question audio is served by the policy server from a media path under the task's URL using a fixed-length scrambled filename so the proxy rule that allows the task page also allows the audio, and the URL never reveals `<word>` or its character length to the browser:
  - To construct the scrambled stem `<token>` for an entry key (`<word>` or `<word>.<n>`, up to 22 ASCII bytes):
    1. Start with a 24-byte working buffer. Let `m = len(entry_key) + 1` (so `2 <= m <= 23`) and `n = 24 - m` (so `1 <= n <= 22`).
    2. In `buffer[0]`, encode the pool flag in the high bit (`0x00` for `current`, `0x80` for `revision`) and `len(entry_key)` (`1` to `22`) in the low 7 bits.
    3. Place the ASCII bytes of `entry_key` in `buffer[1 .. m - 1]`.
    4. Fill the remaining `n` padding bytes `buffer[m .. 23]` with random bytes drawn from the 182 byte values that have at least 3 bits set and at least 3 bits unset (`3 <= byte.bit_count() <= 5`).
    5. XOR only the first `m` bytes (`buffer[0 .. m - 1]`) by reading the `n` padding bytes backwards from the tail of the buffer (`buffer[23]`, `buffer[22]`, ..., `buffer[m]`), wrapping around to `buffer[23]` if `m > n`: for each `i` in `0 .. m - 1`, `buffer[i] ^= buffer[23 - (i % n)]`. Because every padding byte has at least 3 bits set, no byte in `buffer[0 .. m - 1]` ever remains unchanged. The `n` padding bytes in `buffer[m .. 23]` are left untouched.
    6. Encode the scrambled 24-byte buffer with URL-safe Base64 (`base64.urlsafe_b64encode`) into a constant-length 32-character `<token>` (with no `=` padding).
  - Append the unscrambled suffix to `<token>`:
    - `<token>.<ext>` for the word clip (for example, `/tasks/<name>/audio/<token>.opus`).
    - `<token>.sentence.<ext>` for the sentence clip (for example, `/tasks/<name>/audio/<token>.sentence.opus`).
  - When the browser requests that URL, the server Base64-decodes `<token>` into the 24-byte buffer and descrambles it: recovers the header byte via `header = buffer[0] ^ buffer[23]`, extracts the pool bit (`header & 0x80`) and entry key length `L = header & 0x7F` (giving `m = L + 1` and `n = 24 - m`), verifies that `1 <= L <= 22` and that all `n` padding bytes in `buffer[m .. 23]` have `3 <= bit_count <= 5`, XORs each `buffer[i]` (`1 <= i < m`) with `buffer[23 - (i % n)]` to recover `entry_key`, and serves the corresponding `<entry_key>.<ext>` or `<entry_key>.sentence.<ext>` file from that task's `current_dir` or `revision_dir` (returning `404` if the token is malformed or the file does not exist).
- When a question appears:
  - The input box is empty and disabled, both audio buttons are disabled, and the timer bar sits at 100% while the entry's word-only clip plays automatically.
  - When the initial word clip finishes playing, the input box is enabled and focused, "Repeat word" is enabled (when `maximum_replays > 0`), "Use in a sentence" is enabled (when the entry has a sentence clip and `maximum_sentence_plays > 0`), and the countdown timer starts for `timeout`.
- While he is answering, clicking an enabled "Repeat word" or "Use in a sentence" button (or activating it via Tab and Enter/Space):
  - Pauses the countdown timer at its remaining time.
  - Keeps whatever letters he has already typed in the input box, and disables the input box and both audio buttons while the clip plays so keystrokes during playback do not change the box.
  - Sends a replay notification (`POST ?do=replay` with the question `id` and `clip: "word"` or `"sentence"`) so the server records the play and extends the question's server-side deadline by that clip's duration.
  - When the clip finishes playing, re-enables each audio button that still has plays remaining (leaving a button disabled once it has reached `maximum_replays` or `maximum_sentence_plays`), re-enables and focuses the input box without clearing or overwriting his typed text (placing the caret at the end of his text), and resumes the countdown timer from where it paused.
- Tab and Shift+Tab cycle through the page's visible, enabled controls (the input box, enabled audio buttons, "Try a different task", and "Practice" when S005.2 is present) as in S011.
- Enter while focused on the input box submits the spelling when the box has at least one non-space character. Enter on an empty box does nothing, and the timer keeps running.
- When the timer bar reaches zero, the browser sends whatever is in the box, including an empty box. If the box holds the right spelling in time, it counts as correct; otherwise it is a timeout.
- On the server:
  - When a question is issued, its initial deadline is the issue time plus the initial word clip's duration plus `timeout` plus the 0.5-second network allowance from S004.1.
  - Each valid `replay` request received while the question is open and within that clip's limit (`maximum_replays` for `"word"`, `maximum_sentence_plays` for `"sentence"`) increments that clip's play count and extends the question's server-side deadline by the clip's duration. A `replay` request beyond the configured maximum (or for `"sentence"` when the entry has no sentence clip) is refused with `400` and does not extend the deadline.
  - An answer received after the server-side deadline is a timeout, whatever it says, and is still recorded.

## Feedback and finishing

- A correct answer plays a sound chosen at random from `correct/`, shows `"Correct!"` for about 1 second, and then moves to the next question (or finishes the attempt).
- A wrong submission plays a sound from `incorrect/` and shows `"Not quite"`. A timeout plays a sound from `timeout/` (never `incorrect/`) and shows `"Time ran out"`.
- Whether the expected spelling is shown on screen during wrong/timeout feedback depends on whether that entry was placed back on the queue:
  - **Re-queued** (a `current` entry missed while `current` correct is below `n`, or a `revision` entry re-queued because no other `revision` replacement was available): the expected spelling is **not** shown on screen, so he cannot copy it when the word comes back later in the run.
  - **Not re-queued** (a `current` entry missed after `n` was already reached, or a `revision` entry replaced by a different `revision` entry): the expected spelling `<word>` is shown on screen alongside the feedback message.
- Wrong/timeout feedback stays on screen for about 2.5 seconds, with no timer running and the input box disabled, and then the next question appears on its own.
- The attempt passes at the moment the server records the answer that leaves all three conditions true:
  1. Every entry in `current` (all `m` of them) has been asked and finished at least once in this run.
  2. At least `n` entries from `current` have been spelled correctly in this run.
  3. At least `x` entries from `revision` have been spelled correctly in this run.
- There is no failure outcome.
- Missed-words summary when completing or giving up:
  - The missed-words review screen displays all distinct words missed in the attempt in a three-column layout using a large font, with a focused `"Continue"` button below.
  - When the attempt passes, if he got any words wrong (incorrect or timed out) in the current attempt (even if he later spelled them right on a retry), the page first shows the missed-words review screen and pauses there. Clicking `"Continue"` or pressing Enter advances to the `"Well done"` screen from S004.1. If he had no missed words, the `"Well done"` screen is shown straight away.
  - When he confirms `"Try a different task"` and S003.2 allows abandoning the attempt, any question currently showing is closed as a timeout, the attempt is finished as `abandoned`, and if he got any words wrong in the attempt (including the question just closed as a timeout), the page shows the missed-words review screen and pauses there until he clicks `"Continue"` or presses Enter to move on to the next task (or the `"nothing else available"` screen). If he had no missed words, it moves on immediately.
- Resume, the one-hour run expiry, and "Try a different task" otherwise work as S004.1 describes. A question that was showing when he reloaded or gave up is closed as a timeout (and re-queued according to the rules above if the run resumes).

# Configuration

A spelling task is a task from S003.1 with `type: spelling`. Its fields are in the task's `body`. Every field is optional.

| Field | Default | Value |
| --- | --- | --- |
| `current_dir` | `spelling/current` | Path to the current word pool directory, relative to `DAYWARDEN_DATA_DIR`. |
| `revision_dir` | `spelling/revision` | Path to the revision word pool directory, relative to `DAYWARDEN_DATA_DIR`. |
| `alphabet_dir` | `spelling/alphabet` | Path to the alphabet audio directory used by practice mode in S005.2, relative to `DAYWARDEN_DATA_DIR`. |
| `timeout` | `30s` | The time allowed for typing each word (excluding audio playback time). A duration greater than zero, written as in S004.1, such as `30s`, `45s`, or `1m`. |
| `maximum_replays` | `3` | Maximum number of times he may click "Repeat word" on a single question. A whole number, `0` or more. |
| `maximum_sentence_plays` | `2` | Maximum number of times he may click "Use in a sentence" on a single question. A whole number, `0` or more. |
| `current_required` | All entries in `current_dir` (`m`) | How many `current` words must be spelled correctly. A whole number from `0` to `m`. |
| `revision_required` | `min(5, len(revision))` | How many `revision` words must be spelled correctly. A whole number from `0` to the number of entries in `revision_dir`. |

These are invalid configuration and fail the policy load (leaving the previous policy in force, naming the task and the field or file):

- Any unknown field, a field of the wrong type, a `timeout` of zero or a bare number, or a relative directory path that escapes `DAYWARDEN_DATA_DIR` with `..`.
- A `current_dir` or `revision_dir` that does not exist or is not a directory when its pool is used (or when the path is explicitly configured).
- A filename in `current_dir` or `revision_dir` with an audio extension whose `<word>` part is empty or contains characters other than letters, `-`, and `'`, whose entry key (`<word>` or `<word>.<n>`) is longer than 22 characters, or that has an invalid dot structure (anything other than `<word>.<ext>`, `<word>.<n>.<ext>`, `<word>.sentence.<ext>`, or `<word>.<n>.sentence.<ext>` where `<n>` is a positive integer).
- Duplicate word clips or duplicate sentence clips for the same entry key in one directory (such as `rope.opus` and `rope.mp3`), or an orphan `.sentence.` file with no matching word clip in the same directory.
- The same entry key (`<word>` or `<word>.<n>`, case-insensitively) present in both `current_dir` and `revision_dir`.
- `current_required` greater than `m` (the number of entries in `current_dir`) or negative.
- `revision_required` greater than the number of entries in `revision_dir` or negative.
- A negative or non-integer `maximum_replays` or `maximum_sentence_plays`.
- Both pools producing no work: `m == 0` and `revision_required == 0`.

This example uses the default directories under `$HOME/daywarden/spelling/`, gives 25 seconds per word, requires 8 of the current words, and requires 4 revision words:

```yaml
tasks:
  weekly-spelling:
    type: spelling
    group: younger
    pass_cooldown: 1
    body:
      timeout: 25s
      current_required: 8
      revision_required: 4
```

# Attempt Record

The attempt's `detail` from S003.1 holds `settings`, `runs`, and `last_activity` as S004.1 describes, and `questions`: every question issued in this attempt, in order. Each run entry in `runs` also records `current_total` (`m`), `current_required` (`n`), and `revision_required` (`x`) for that run. Each question in `questions` has:

- the run number
- the entry key (such as `rope` or `read.1`), the expected spelling (`rope` or `read`), and the pool (`current` or `revision`)
- whether a sentence clip was available
- the number of word replays and sentence plays during the question
- his answer as received, or nothing when the box was empty or no answer arrived
- the outcome: `correct`, `incorrect`, or `timeout`
- whether the missed entry was re-queued (`requeued: true` or `false`)
- the typing time allowed in milliseconds (`timeout`) and the total server time allowed including audio playback in milliseconds
- the time from issue to receipt in milliseconds, when an answer arrived
- the household-local time the question was issued

S003.3 shows this record in the parent attempt view.

## Queue and quiz logic

- [x] Answering a word correctly (ignoring case and leading/trailing spaces) increments only the score for the pool (`current` or `revision`) that entry came from.
- [x] While `current` correct is below `n`, missing or timing out on a `current` entry places that same entry at the end of the queue.
- [x] Once `current` correct reaches `n`, missing or timing out on a remaining `current` entry does not place it back on the queue, and still marks that entry as having been asked.
- [x] While `revision` correct is below `x`, missing or timing out on a `revision` entry appends a different `revision` entry that has not been spelled correctly in this run and is not already in the queue, or appends the same entry when no other candidate exists in `revision`.

## Change Summary

- **Word pools.** Each pool is a directory of `<word>.<ext>` / `<word>.<n>.<ext>` recordings with optional `.sentence.` clips, matched without regard to case. All the story's invalid configurations fail the load, naming the task, field, and file. A default directory that is missing is an empty pool. A directory the body names, or one whose target is above zero, must exist.
- **Rescanning.** Directories are scanned when the policy loads and at the start of every run, and recording lengths are cached by `(path, mtime_ns, size)`. A run keeps its words, targets (`current_total`, `current_required`, `revision_required`), and queue on the attempt. If a directory goes bad after the load, the next run keeps the last list that scanned cleanly and the service logs why.
- **Audio tokens.** Audio URLs carry the 24-byte scrambled buffer the story describes, as a 32-character URL-safe Base64 token. The server reads the pool and entry key back from it, checks the padding bytes, and serves the file only for a task the client group may open now. Any other token is a `404`.
- **Queue and scoring.** The opening queue is all current words plus `revision_required` random revision words, shuffled. The re-queue rules, the choice of a replacement revision word, showing the spelling only when the word won't return, and the three-condition pass all follow the story. There is no failure.
- **Timing.** The server allows the word clip plus `timeout` plus the 0.5-second network allowance. Each accepted `?do=replay` adds that clip's length. Replays past the limit, of a missing sentence, or after the time is up are refused with `400`.
- **Page.** The word plays with the controls disabled and the timer at 100%. Replays pause the timer, keep what he has typed, and return focus with the caret at the end. A button greys out at its limit. The box is a monospace input sized to 18 characters and accepts only letters, `-`, and `'`.
- **Missed words.** They are listed in up to three columns, after a pass on the page and after a give-up as a server-rendered page. "Continue" or Enter moves on to "Well done", the next task, or "There is nothing else available right now."

Verified in a browser against a local server with generated recordings: control states while listening, timer pause and resume around replays, button limits, the colours in both states, feedback with and without the spelling, the box width for `extemporaneously`, and both missed-words screens with Enter.

## Suggested Acceptance Testing

1. Put real recordings in `~/daywarden/spelling/current` (for example `rope.opus`, `rope.sentence.opus`, and `read.1.opus` / `read.2.opus`) and a few in `~/daywarden/spelling/revision`. Add the example `weekly-spelling` task to `config/policy.yaml`, run `make up`, and open the task. Check the start screen shows `Current: 0 / n · Revision: 0 / x`, and that after Start each word plays before the box and buttons turn on and the timer starts.
2. During a question, type a few letters and click "Repeat word". Check the timer stops, the box locks with your letters kept, and when the word finishes the box is focused with the caret after your letters and the timer carries on. Repeat until "Repeat word" turns grey (3 by default). Do the same for "Use in a sentence" (2 by default), and check it is grey from the start for a word with no `.sentence.` file.
