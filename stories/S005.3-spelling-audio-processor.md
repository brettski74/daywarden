# User Voice

As a parent, I want to record letters, words and sentences for spelling quizzes in one take and have them cut into clean, separately named clips with minimal effort, so that adding a new alphabet or a week's word list takes minutes instead of an evening in an audio editor.

For example, I record myself saying the alphabet plus "dash" and "apostrophe" with a second or two of silence between each, run one command, type the name of each clip as it is found, and end up with 28 `.opus` files in `spelling/alphabet` that S005.2 can string together without clicks or pops.

Later I want to record new spelling lists in the browser, so the cutting and fading should live in a library that a web page can reuse, with this story's command-line tool as a thin layer over it.

# Use Cases

## Running the tool

- The tool runs on the machine that runs Compose, not in a container: `bin/cut-clips <recording> --out <directory>`. Like `bin/rm-attempts`, it works from any directory, including through a symlink in `~/bin`. It runs `python -m policy.clips` with the repository on the module path.
- It needs `ffmpeg` built with `libopus` on the path, plus `pydub` and `audioop-lts`, which are added to `policy/requirements.txt`. If ffmpeg is missing or cannot encode with libopus, the tool stops before analysing anything and says so. If `pydub` is missing, the error names `pip install -r policy/requirements.txt`.
- The recording can be any format ffmpeg can decode, including `.wav`, `.mp3`, `.ogg`, `.opus`, `.m4a`, `.flac`, and `.webm`. It is converted to mono, 48 kHz, 16-bit before it is cut. Stereo recordings are mixed down.

| Option | Default | Meaning |
| --- | --- | --- |
| `recording` | (required) | The recording to cut. |
| `--out DIR` | Current directory | Where clips are written. Created if it does not exist. |
| `--min-silence MS` | `700` | How long a quiet stretch must last before it separates two clips. Shorter pauses, such as those between the words of a sentence, stay inside one clip. Must be at least `200`. |
| `--threshold DB` | `35` | How many decibels below the loudest point in the recording a stretch must be to count as silence. |
| `--min-speech MS` | `150` | A sound shorter than this, such as a click or a bump, is treated as noise and is not offered as a clip. |
| `--bitrate RATE` | `32k` | The Opus bitrate. |
| `--play` | Off | Play each clip (through `ffplay`) before asking for its name. |
| `--list` | Off | Print the clips found (number, start time, and length) and the number of short sounds ignored, then exit without asking for names or writing anything. Useful for tuning `--min-silence` and `--threshold`. |

## Finding and cutting clips

- A clip is one stretch of speech: audio louder than the threshold, with no quiet gap of `--min-silence` or longer inside it, lasting at least `--min-speech`.
- Each clip written out is a 100 ms guard, then the speech, then another 100 ms guard. The guards come from the recording on either side of the speech. When the speech starts or ends less than 100 ms from the edge of the recording, the guard is padded with digital silence so it is always 100 ms long.
- The leading guard fades in and the trailing guard fades out over its full 100 ms. Before encoding, the first and last samples of every clip are zero, and the speech between the guards is unchanged.
- Each clip is written as Ogg Opus (`<name>.opus`) using `libopus`, mono, 48 kHz.

## Naming clips

- Before the first prompt, the tool prints how many clips it found, so a wrong count is obvious before any typing (for example, 27 clips from a 28-character alphabet recording).
- The tool asks for a name for each clip in recording order, showing its number, start time, and length: `Clip 3 of 28 at 0:05.20 (0.48 s):`. With `--play`, the clip plays before the prompt, and entering `?` plays it again.
- The name is the file name without `.opus`. It must follow the S005.1 file naming rules, checked by the same code the policy load uses rather than a copy: `<word>`, `<word>.<n>`, `<word>.sentence`, or `<word>.<n>.sentence`, where `<word>` contains only letters, `-`, and `'`, and the entry key is at most 22 characters. The alphabet names from S005.2 (`a` to `z`, `dash`, and `apostrophe`) are valid under these rules. An invalid name is explained and the prompt is asked again.
- Entering an empty name skips that clip without writing it.
- If `<name>.opus` already exists, the tool asks `Replace rope.opus? [y/N]`. Answering no returns to the name prompt for the same clip.
- If the directory already holds a different audio file for the same entry key, ignoring case and extension (such as `rope.mp3` or `Rope.opus` when the name is `rope`), keeping both would make the policy refuse to load. The tool asks `rope.mp3 is already the clip for rope. Replace it? [y/N]`. Answering yes writes `rope.opus` and then removes the old file. Answering no returns to the name prompt.
- Each clip is written to a hidden temporary file in the output directory and then renamed into place. A run that starts scanning the directory partway through a write never sees a half-written clip, because S005.1 skips hidden files.
- Ctrl-C or end of input at any prompt stops the tool. Clips already written are kept, and no temporary file is left behind.
- When the tool finishes, it prints how many clips were written and skipped. It then checks the output directory with the S005.1 pool rules (badly formed names, two clips for the same entry key, and sentence clips with no word clip) and prints any problem as a warning. The warnings do not change the exit status.

## Reuse from a web page later

- The cutting, fading, naming checks, and writing live in `policy/clips.py` as plain functions with no prompts, printing, or terminal input. The command-line tool is a separate entry point that supplies names interactively.
- The library loads a recording from a file path or from bytes with an optional format hint, because a browser's `MediaRecorder` uploads WebM or Ogg Opus bytes rather than a file.
- Finding clips returns the start and end of each stretch of speech. Cutting one stretch returns the faded audio. Writing a clip takes a directory and a name. A web page can show the clips found, let the parent name or discard each one, and write the clips into a pool directory, with no changes to the library.
- The guard length (100 ms) and the detection settings are parameters with the defaults above, so a web page can use the same defaults.

# Acceptance Criteria

## Cutting

- [ ] For a synthetic recording of tones separated by gaps of at least `--min-silence`, the library finds one clip per tone. Each clip's speech starts and ends within 10 ms of its tone.
- [ ] A tone with a 300 ms quiet gap inside it is one clip under the default 700 ms `--min-silence`, and becomes two clips when `--min-silence` is `200`.
- [ ] A sound shorter than `--min-speech` is not returned as a clip, and `--list` reports how many were ignored.
- [ ] Silence is measured relative to the recording's loudest point, so the same recording played back 20 dB quieter yields the same clips.
- [ ] Each cut clip is 100 ms of guard, the speech, and 100 ms of guard. Its length is within 1 ms of the speech length plus 200 ms, including when the speech begins or ends less than 100 ms from the edge of the recording.
- [ ] Before encoding, the first and last samples of every clip are zero, the level rises through the leading guard and falls through the trailing guard, and the samples between the guards match the source recording exactly after it is converted to mono, 48 kHz.
- [ ] A written clip is an Ogg Opus file encoded with `libopus` at mono, 48 kHz. When ffmpeg decodes it, its length is within 10 ms of the cut clip and its first and last 5 ms are below −50 dBFS. Tests that need ffmpeg are skipped when it is not installed, as the existing spelling tests are.
- [ ] Mono and stereo `.wav`, `.mp3`, `.m4a`, and `.opus` recordings all load and produce the same clip count from the same source audio. A recording supplied as bytes with a format hint (WebM or Ogg Opus) also loads.

## Naming and writing

- [ ] The tool prints the number of clips found, then prompts for each clip in recording order with its number, start time, and length. Each name writes `<name>.opus` to `--out` (creating the directory when it is missing).
- [ ] A name that breaks the S005.1 naming rules (for example `rope!`, `rope.0`, `rope.sentence.1`, or a key longer than 22 characters) is explained and asked again. `a`, `dash`, `apostrophe`, `read.2`, and `read.2.sentence` are accepted.
- [ ] An empty name skips the clip and nothing is written for it.
- [ ] Entering the name of an existing `<name>.opus` asks before replacing it. Entering the key of an existing clip with a different extension or casing asks before replacing it, and answering yes leaves only the new `.opus`. Answering no to either question prompts for the same clip's name again.
- [ ] Clips are written to a hidden temporary file and renamed into place. Interrupting the tool with Ctrl-C or end of input keeps the clips already written and leaves no temporary file.
- [ ] After the last clip, the tool prints how many clips were written and skipped, and warns about any S005.1 pool rule the output directory now breaks, such as an orphan `rope.sentence.opus`.
- [ ] `--list` prints each clip's number, start time, and length and writes nothing. `--play` plays each clip before its prompt, and `?` replays it.
- [ ] Without ffmpeg, or with an ffmpeg that cannot encode `libopus`, the tool stops with a clear message before reading the recording.

## Library and documentation

- [ ] `policy/clips.py` exposes loading (from a path or from bytes), finding clips, cutting a clip, checking a name, and writing a clip. None of these prompt, print, or read the terminal, and the command-line tool uses only these functions for audio work.
- [ ] `policy/requirements.txt` adds `pydub` and `audioop-lts`. The policy service does not import `policy.clips` in this story.
- [ ] The README explains how to install what the tool needs, record a take (with a pause of a second or more between items), run `bin/cut-clips`, tune `--min-silence` and `--threshold` with `--list`, and name alphabet, word, homograph, and sentence clips.
- [ ] Run against the parent's own alphabet recording with the default settings, the tool finds 28 clips, and S005.2 practice mode plays a spelling assembled from them without audible clicks at the joins.

# Notes

Depends on S005.1 for the file naming and pool rules. The alphabet names come from S005.2, but this story does not need S005.2 to be done.

Out of scope: recording in the browser, writing clips from the policy server, adding ffmpeg to the policy image, loudness normalisation, noise reduction, and naming clips automatically with speech recognition. The web recording story will need ffmpeg in the `decisions` image and a writable data directory mount, which today is read-only.

Decisions made during refinement:

- **Run on the host.** The `decisions` container mounts the data directory read-only and has no ffmpeg. The host already has ffmpeg with libopus and can see both the recording and `~/daywarden`.
- **pydub needs `audioop-lts`.** Python 3.13 removed the `audioop` module that pydub uses, and the host and the policy image both run Python 3.14.
- **Silence relative to the peak, not the average.** A take that is mostly silence drags the average level towards the noise floor, so a threshold relative to the average would treat background hiss as speech. Measuring from the loudest point keeps quiet tails such as the "s" in "ess" while ignoring room noise.
- **Fades.** pydub's `fade_in` and `fade_out` start from −120 dB, which rounds to zero in 16-bit audio, giving the "collapse to zero" ends the parent asked for. Fading only the guards keeps the speech itself at full level.
- **Speed.** Running pydub's `detect_nonsilent` with a 10 ms seek step keeps a several-minute take to a few seconds. A 1 ms step makes no audible difference with a 100 ms guard.
- **Default thresholds.** The defaults (700 ms of silence, 35 dB below peak, 150 ms of speech) are starting values. Tune them against the parent's real alphabet recording during implementation, and update the table above if they change.
