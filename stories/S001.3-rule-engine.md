# User Voice

As a parent, I want each site group to run an ordered list of rules, so that bedtime is a refusal, school hours are a redirect to revision, and the evening is allowed only when later conditions say so.

# Use Cases

- A rule has a condition and two actions, `when_true` and `when_false`.
- An action is `continue`, `deny` with a message, `redirect` to an absolute URL, or `allow`.
- The redirect target may also be the token `revision_task`. Until S003 exists, that token resolves to a configured placeholder URL so the rule engine can be tested.
- The first action other than `continue` is the decision. If every rule continues, the decision is deny.
- A `time_window` condition is true when the household-local time falls inside the window. A window lists weekdays, or applies to every day. A window may cross midnight, such as `22:00–07:00`.
- Weekday-specific windows and an everyday window can both exist. A request is inside the condition if it is inside any one of the windows.

# Acceptance Criteria

- [x] Allow stops the list and returns an allow decision.
- [x] Deny stops the list and returns `403` with the configured message.
- [x] Redirect stops the list and returns `302` with an absolute URL.
- [x] Continue evaluates the next rule.
- [x] An empty rule list denies the request.
- [x] A window of `00:00–07:00` on Monday through Thursday matches 06:59 on a Wednesday and does not match 07:00.
- [x] A window of `22:00–07:00` matches 23:30 and matches 06:30, and does not match 12:00.
- [x] A window limited to Saturday does not match on Wednesday.
- [x] The five-rule entertainment schedule below is an automated test. Times are household-local, the day is a Wednesday, no tasks are complete, and the quota is still remaining. The placeholder stands in for a revision task.

| Local time | Expected decision |
| --- | --- |
| 06:30 | Deny |
| 10:00 | Redirect to the placeholder |
| 16:00 | Redirect to the placeholder |
| 20:00 | Deny |

- [x] The same schedule at 16:00, when the task-completion condition is forced true and the quota condition is forced true, allows the request. Forcing those two conditions is a test hook in this story. S001.4 and S001.5 replace the hook with real counts.

The schedule under test is:

1. Window `00:00–07:00`, Monday to Thursday. True: deny "It's bedtime." False: continue.
2. Window `07:00–15:00`, Monday to Thursday. True: redirect to `revision_task`. False: continue.
3. Window `15:00–19:00`, Monday to Thursday. True: continue. False: deny "YouTube is closed for today."
4. Tasks complete. True: continue. False: redirect to `revision_task`. In this story the test hook supplies the boolean.
5. Quota remaining. True: allow. False: deny "Time is up for today." In this story the test hook supplies the boolean.

# Notes

Depends on S001.2. End times are exclusive, so `07:00–15:00` and `15:00–19:00` do not both match at 15:00. The boundary belongs to the later window.

## Change Summary

A group's rules are `[[groups.rules]]` tables under that group in `config/policy.toml`. Each rule has a `condition` and two actions, `when_true` and `when_false`. An action is `continue`, `deny` with a message, `redirect` to an absolute `http` or `https` URL or the token `revision_task`, or `allow`. There is also an `always` condition, so a group such as school work can end in an unconditional allow. `tasks_complete` and `quota_remaining` are accepted as conditions and are not given counts yet.

`policy/rules.py` walks the list. The first action other than `continue` is the decision. An empty list, or a list that only continues, is `{"action": "deny", "status": 403, "message": "No rule allowed this request."}`. A redirect to `revision_task` is replaced with `household.revision_task` before the answer leaves the service, so the addon only ever sees an absolute URL. If that setting is missing while a rule uses the token, the file is rejected at load. If the token is reached with no URL anyway, the answer is a 403, "The revision task page is not configured."

The test hook is the `tasks_complete` and `quota_remaining` arguments of `evaluate` and `decide`. The service passes the defaults: no task is complete, and the quota is still remaining. S001.4 and S001.5 replace those two booleans with stored counts. Forcing both true is covered in `tests/test_policy_rules.py`, not over HTTP.

A `time_window` is true when the household-local time sits in any of its windows. The start is included and the end is excluded. A window with no `days` applies every day. A window whose end is earlier than its start crosses midnight: the evening belongs to the named weekday, and the following morning belongs to that same window. So Saturday `22:00–07:00` matches Saturday 23:30 and Sunday 06:30, and does not match Saturday 06:30. That reading is what makes a bedtime window span one night rather than two mornings.

Rules are stored in schema version 3, in `rules`, `rule_windows`, and `rule_actions`, and replaced on each load. A group keeps its row id. The placeholder URL is a `settings` row, `revision_task`, and is cleared when the file omits it. A version-2 database gains the empty rule tables and keeps its groups.

`config/decision.json` is no longer the household decision, and the file has been removed. The sample `Everything else` group has no rules, so every site is now denied with "No rule allowed this request." The addon tests still need to hand the proxy an arbitrary document, including one the engine would never produce, so they set `DECISION_STUB=1` via `tests/decision-stub.compose.yml` and the service replays the file for a grouped URL. A URL in no group is still the ungrouped deny, stub or not.

The five-rule Wednesday schedule is checked as parsed TOML in `tests/test_policy_rules.py`, including the 15:00 boundary with both hooks forced true (school hours still redirect at 14:59, and 15:00 is allowed). The same four clock times are also posted to the service in `tests/test_policy_service.py`, with the placeholder coming back from the database, and again after the container is recreated without the file.

## Suggested Acceptance Testing

- Run `python -m pytest tests/test_policy_rules.py tests/test_policy_decisions.py tests/test_policy_groups.py`. No Docker is needed. These cover the window edges, the Wednesday schedule, both hooks forced true, invalid rules, the SQLite round trip, and a version-2 database upgrade.
- Run `python -m pytest tests/test_policy_service.py`. It loads the same entertainment schedule, checks the four Wednesday times against YouTube, checks that Classroom is allowed, checks that `decision.json` is ignored, and recreates the container without the file.
- On the real stack, `docker compose restart decisions` and read `docker compose logs decisions`. Expect `group Everything else: default, 0 rules` and no revision-task line. A browse should show "No rule allowed this request." rather than the old "Too late. Go to bed!"
- Uncomment a small rule under `Everything else`, set `household.revision_task` if the rule uses the token, and restart. The log should show `1 rule` and the placeholder URL. A request inside the window should follow that rule; `docker compose exec decisions tail -n 1 /tmp/decisions.jsonl` should show the group and the decision.
- Give a rule `location = "revision_task"` and leave `household.revision_task` unset. `make up` should fail, and `docker compose logs decisions` should say the placeholder is not set.
- Give two windows the same edge, `07:00–15:00` then `15:00–19:00`, and confirm 14:59 takes the first and 15:00 takes the second.
- Known, and unchanged in outcome: two tests in `tests/test_run_proxy.py` still fail. They use the repo `config/`, whose only group has no rules, so the request is denied before it reaches the origin.
