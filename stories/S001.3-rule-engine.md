# User Voice

As a parent, I want each site group to run an ordered list of rules, so that bedtime is a refusal, school hours are a redirect to revision, and the evening is allowed only when later conditions say so.

# Use Cases

- A rule has a condition and two actions, `when_true` and `when_false`.
- An action is `continue`, `deny` with a message, `redirect` to an absolute URL, or `allow`.
- The redirect target may also be the token `revision_task`. Until S003 exists, that token resolves to a configured placeholder URL so the rule engine can be tested.
- The first action other than `continue` is the decision. If every rule continues, the decision is deny.
- A `time_window` condition is true when the household-local time falls inside the window. A window lists weekdays, or applies to every day. A window may cross midnight, such as `22:00–07:00`.
- Weekday-specific windows and an everyday window can both exist. A request is inside the condition if it is inside any one of the windows.

# Acceptance Criteria

- [ ] Allow stops the list and returns an allow decision.
- [ ] Deny stops the list and returns `403` with the configured message.
- [ ] Redirect stops the list and returns `302` with an absolute URL.
- [ ] Continue evaluates the next rule.
- [ ] An empty rule list denies the request.
- [ ] A window of `00:00–07:00` on Monday through Thursday matches 06:59 on a Wednesday and does not match 07:00.
- [ ] A window of `22:00–07:00` matches 23:30 and matches 06:30, and does not match 12:00.
- [ ] A window limited to Saturday does not match on Wednesday.
- [ ] The five-rule entertainment schedule below is an automated test. Times are household-local, the day is a Wednesday, no tasks are complete, and the quota is still remaining. The placeholder stands in for a revision task.

| Local time | Expected decision |
| --- | --- |
| 06:30 | Deny |
| 10:00 | Redirect to the placeholder |
| 16:00 | Redirect to the placeholder |
| 20:00 | Deny |

- [ ] The same schedule at 16:00, when the task-completion condition is forced true and the quota condition is forced true, allows the request. Forcing those two conditions is a test hook in this story. S001.4 and S001.5 replace the hook with real counts.

The schedule under test is:

1. Window `00:00–07:00`, Monday to Thursday. True: deny "It's bedtime." False: continue.
2. Window `07:00–15:00`, Monday to Thursday. True: redirect to `revision_task`. False: continue.
3. Window `15:00–19:00`, Monday to Thursday. True: continue. False: deny "YouTube is closed for today."
4. Tasks complete. True: continue. False: redirect to `revision_task`. In this story the test hook supplies the boolean.
5. Quota remaining. True: allow. False: deny "Time is up for today." In this story the test hook supplies the boolean.

# Notes

Depends on S001.2. End times are exclusive, so `07:00–15:00` and `15:00–19:00` do not both match at 15:00. The boundary belongs to the later window.
