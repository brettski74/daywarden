# User Voice

As a parent, I want to see usage for a site group, a client group, or a quota, so that Classroom, an unknown computer, and the YouTube limit are each visible.

# Use Cases

- Choose a site group, a client group, or a quota.
- A site-group or client-group view shows the day's buckets, the time they represent, the clock times, and the bytes.
- A quota view is per client group. Opening a quota without a client group shows each client group's balance for it.
- `default` is a selectable group for both site and client. A quiet day is an empty day, not an error.

# Acceptance Criteria

- [x] After observations have marked buckets, the site-group page shows them on the correct local day for that client group and site group, including a group that no quota accepts.
- [x] The same buckets are reachable from the client-group view.
- [x] A quota page shows that client group's ended time against the time limit and the stored bytes against the byte limit. A limit of zero is shown as zero, not hidden.
- [x] Selecting a quota with no client group lists every client group that has a balance, including `default`.
- [x] A day with no traffic is shown as no usage.
- [x] Times are in the household timezone. Byte totals for each bucket are still visible.
- [x] The page keeps the parent barrier from S002.2. The child cannot open it with no barrier.

## Change Summary

`GET /usage` on a YAML policy is the wider report. The parent chooses a site group, a client group, or a quota. `default` is in both group lists. A site group needs a client group as well, and shows the last 14 household-local days for that pair. A client group shows the same buckets for every site group, with the site group named on each row. Each day lists the clock times, the stored length, and the bytes. A bucket that has not ended is listed and left out of the counted time. A day with no rows says no usage. School traffic that no quota accepts is on the site-group page and the client-group page. The counted time on a client-group day is the sum of the buckets shown, so school and YouTube in the same five minutes both contribute.

A quota page is today's balance, because the quota resets at local midnight. With a client group it shows that group's ended time against the time limit and the stored bytes against the byte limit. An open bucket adds bytes and does not add time yet. A limit of zero is written out as zero. With no client group it lists every client group that has a stored row for that quota, including `default`, and shows each one's balance for today. A group that only has yesterday's row is still listed, with today's figures at zero. A quota nobody has used says no client group has a balance, and still shows a zero limit.

The parent barrier is unchanged. With no `PARENT_PASSWORD` the page is closed and shows no groups and no buckets. A wrong password, a forged cookie, and a password in the query string do not open it. The TOML policy still serves the older one-client, one-site-group page. S008.5 is what points the household file at YAML. The README still describes that older page.

## Suggested Acceptance Testing

- Run `python -m pytest tests/test_usage_report.py`. No Docker is needed. These cover a UTC observation landing on the Sydney day and clock, Classroom staying on the school site group while YouTube is on entertainment, the same buckets on the client-group page and the other child's buckets staying off it, an open bucket shown and not counted while its bytes already sit on the quota, yesterday's quota balance reading as zero today while the site-group page still shows that day, a zero time limit and a zero byte limit written out before and after use, a quota with no client group listing `default` and `younger` and leaving `older` out, an empty fortnight saying no usage, `default` for an unknown computer and an unknown site, a bucket that reaches midnight staying on the day it started, a bucket older than 14 days left out, escaped names, an unset timezone labelled as the machine's, and the closed page, wrong password, right password, forged cookie, and query-string password.
- The last test posts `/usage` through the decisions service. It runs when FastAPI is installed, which is the policy image. Without FastAPI that one test is skipped and the others still run.
- Run `python -m pytest tests/test_policy_report.py tests/test_policy_volume.py`. The TOML report is unchanged: one client, one site group, the byte limit beside the day's bytes, and the same parent barrier.
- Point `POLICY_FILE` at a small YAML policy, export `PARENT_PASSWORD`, and run `docker compose up -d decisions`. Open `http://<this machine>:8090/usage`. The password form should show no buckets. After the password, choose Site group, the younger child's client group, and the entertainment site group. A quiet day says no usage. After some YouTube, that day lists the bucket's clock, the time it represents, and the bytes. Choose the school site group and confirm Classroom is listed there. Choose Client group for the same child and confirm both buckets are on that page. Choose Quota and the entertainment quota with no client group and confirm each child who has used it is listed, including an unknown computer under `default`. A quota with no time and no byte limit should show `0s` and `0 bytes`.
- Unset `PARENT_PASSWORD` and create the decisions container again. The page should be closed. `docker compose restart` does not pick up a new password.
