# User Voice

As a parent, I want the proxy to notice that traffic for a site is still moving, so that a long video counts for each five-minute bucket it actually occupies and not only for the bucket in which it started.

# Use Cases

- When a request is allowed and forwarded, the addon reports an observation: client IP, absolute URL, time, and the number of bytes just seen.
- While a flow stays open and more bytes move, the addon reports again, about once a minute.
- When the flow ends, the addon reports once more.
- An idle connection, with no new bytes since the last report, produces no further observations.
- A failed report never changes the allow, deny, or redirect decision.

# Acceptance Criteria

- [x] A short allowed request produces at least one observation containing the client IP, URL, a timestamp, and a byte count greater than zero.
- [x] A response that streams for longer than one reporting interval produces more than one observation, and the later observation is not delayed until the response ends.
- [x] A flow that is open but transfers no further bytes does not produce an extra observation.
- [x] Stopping the observation endpoint does not turn an allowed request into a `403` or a `302`.
- [x] Denied and redirected requests are not forwarded, so they do not produce upstream byte observations. They may produce a single observation of the attempted request so the ledger can show a hit; the story is done either way as long as the behaviour is tested and written down.

# Notes

Depends on S000.2. The ledger that stores these observations is S002.1. This story only requires that the HTTP call is made and that a test double records it.

`POST /v1/observations` carries `client_ip`, `url`, `occurred_at`, and `bytes`. `bytes` is the body size seen since the previous report for that flow, request and response together, not a running total. A report is sent about once a minute while new bytes are arriving (`OBSERVATION_INTERVAL`, default 60), and any remainder is sent when the flow ends. Nothing is sent when the count would be zero, so an open idle connection does not mark a bucket. Denied and redirected requests are not reported at all; the decision log is the record of the attempt. A bypassed host is forwarded, so it is reported. The call is fail-open: `observations/stub.py` records it until S002.1, and a refused connection is logged and ignored.

## Change Summary

The addon counts body bytes on flows it forwards and posts them to the observation service. Response bodies are streamed, so a long transfer is reported before it finishes. The Compose service `observations` is the test double and can be stopped on its own. A stopped service leaves the allow, deny, or redirect decision alone.

## Suggested Acceptance Testing

- Run `python -m pytest tests/test_observe.py tests/test_report_observations.py`.
- With the stack up and `config/decision.json` set to allow, request a page through the proxy and confirm `docker compose logs observations` shows one line with a client IP, the absolute URL, a timestamp, and a byte count greater than zero.
- Point a long download at the proxy and confirm more than one observation appears before the download finishes.
- Stop the `observations` container and confirm an allowed page still returns the origin body, not a `403` or a `302`. Start it again afterwards.
- Set a deny and a redirect and confirm the observation log stays empty and the origin records no request.
