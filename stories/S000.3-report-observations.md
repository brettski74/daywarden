# User Voice

As a parent, I want the proxy to notice that traffic for a site is still moving, so that a long video counts for each five-minute bucket it actually occupies and not only for the bucket in which it started.

# Use Cases

- When a request is allowed and forwarded, the addon reports an observation: client IP, absolute URL, time, and the number of bytes just seen.
- While a flow stays open and more bytes move, the addon reports again, about once a minute.
- When the flow ends, the addon reports once more.
- An idle connection, with no new bytes since the last report, produces no further observations.
- A failed report never changes the allow, deny, or redirect decision.

# Acceptance Criteria

- [ ] A short allowed request produces at least one observation containing the client IP, URL, a timestamp, and a byte count greater than zero.
- [ ] A response that streams for longer than one reporting interval produces more than one observation, and the later observation is not delayed until the response ends.
- [ ] A flow that is open but transfers no further bytes does not produce an extra observation.
- [ ] Stopping the observation endpoint does not turn an allowed request into a `403` or a `302`.
- [ ] Denied and redirected requests are not forwarded, so they do not produce upstream byte observations. They may produce a single observation of the attempted request so the ledger can show a hit; the story is done either way as long as the behaviour is tested and written down.

# Notes

Depends on S000.2. The ledger that stores these observations is S002.1. This story only requires that the HTTP call is made and that a test double records it.
