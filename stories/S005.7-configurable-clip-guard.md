Title: Configurable clip guard

# User Voice

As a parent, I want to set how long the faded guard is at each end of a clip cut by `cut-clips`, so that I can experiment with shorter or longer guards and fades until the letters of a spelling join cleanly without a gap or a click.

# Use Cases

- S005.3 cuts every clip with a fixed 100 ms guard either side of the speech, faded in over the leading guard and out over the trailing guard. The guard length becomes an option, still `100` ms by default.

| Option | Default | Meaning |
| --- | --- | --- |
| `--guard MS` | `100` | How much of the recording to keep either side of each clip's speech. Must be at least `10`. |

- The fade in and fade out always last the whole guard, so a 50 ms guard fades over 50 ms and a 100 ms guard over 100 ms. The speech between the guards is never faded.
- The 10 ms minimum leaves room for a fade without fading any of the speech. A smaller value, or anything that is not a whole number, is refused before the recording is read.
- The library's `cut_clip` takes the same guard length, with the same default and minimum, so a later web page can offer the same setting.
- Where the recording runs out before a full guard, the guard is padded with digital silence as in S005.3, so the guard is always the length asked for.

# Acceptance Criteria

- [x] With no `--guard`, each clip is 100 ms of guard, the speech, and 100 ms of guard, faded over each full guard, as in S005.3.
- [x] With `--guard 30`, each written clip decodes to within 10 ms of the speech length plus 60 ms.
- [x] For guards of 10, 50, 100, and 250 ms, including speech near the edges of the recording, the first and last samples of the cut clip are zero, the level rises through the whole leading guard and falls through the whole trailing guard, and the speech samples match the recording exactly.
- [x] `--guard 9` and `--guard fifty` are refused with a message naming `--guard`. `cut_clip` with a guard below 10 ms raises `ValueError`.
- [x] The README describes `--guard`, its default, and its minimum.

# Notes

Follows S005.3. The `--list` output is unchanged, because the guard does not affect which clips are found.

A guard longer than the pause between two items reaches into the next item. That stretch is faded with the rest of the guard, but it can still be heard. No maximum is enforced, because that is the kind of thing this option is for trying.

Removed: none.

## Change Summary

- `cut_clip` already faded over the whole guard with an exact linear ramp, so the fade length follows the guard length with no change to `_fade`. The only library change is the 10 ms minimum.
- `--guard` uses the same whole-milliseconds parser as `--min-silence` and `--min-speech`, so a bad value is refused by argparse before the tools are checked or the recording is read.

## Suggested Acceptance Testing

1. Cut the same alphabet take three times into scratch directories with `--guard 100`, `--guard 50`, and `--guard 20`. Spell a few words from each set in S005.2 practice mode, or play letter clips back to back, and listen for clicks, gaps, and clipped starts or endings such as the "s" in "ess".
2. Run `cut-clips <take> --out /tmp/g30 --guard 30`, name one clip, and check with `ffprobe -show_entries format=duration` that it is about 60 ms longer than the speech length printed in the prompt.
3. Run `cut-clips <take> --guard 9` and `cut-clips <take> --guard fifty`. Each should stop at once with an error naming `--guard`, and write nothing.
4. Run `cut-clips --help` and check that `--guard` shows its default of 100 and its minimum of 10.
5. Run `cut-clips <take> --out /tmp/g10 --guard 10` and listen to a clip. It should start and end without a click even with the shortest fade.
6. Try a guard longer than your pauses, such as `--guard 800` on a take with one-second pauses, and confirm you can hear the faded edge of the neighbouring item. That is the expected trade-off.
