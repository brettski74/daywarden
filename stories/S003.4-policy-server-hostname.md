Title: Policy server hostname for task URLs

# User Voice

As a parent, I want a revision redirect to use the name and port I already type to open the policy pages, so that I do not keep a separate task-site URL that nothing is serving.

# Use Cases

- The household policy has an optional top-level `hostname`. It is the DNS name external clients use to reach the policy server. It is a host, not a URL, and it does not include a port. The scheme of a generated task URL is always `https`.
- Leaving `hostname` out uses the hostname reported by the operating system. A comment in the sample policy says to set `hostname` when that operating-system name is not the name clients use, and that the value is the name in the browser's address bar for the policy pages.
- The household policy has an optional top-level `port`. It is the port external clients use. Leaving it out uses the port the policy server is published on. A comment in the sample says to set `port` when a reverse proxy presents the pages on a different port from that published port, and to leave it out otherwise.
- That published port is the host port in Compose. Today the variable is `REPORT_PORT` (8090 in `.env`). Compose publishes it to port 8443 inside the decisions container, which is where the HTTPS listener is bound. External clients open the host port, not 8443. `REPORT_PORT` is a misleading name, because the same port serves the usage report, the attempt review, and the task pages. This story renames it to `POLICY_PORT` in `.env`, Compose, and the docs. The container bind port stays 8443. The decisions service is given `POLICY_PORT` so a generated URL can use it. A task URL does not use 8443.
- A redirect to the `revision_task` token is `https://<hostname>:<port>/tasks/<name>` for the task chosen for the client group. Port 443 is left off the URL. Any other port is included. The path is the one this service already serves. It is not another setting.
- `https://<hostname>:<port>/tasks/next` is the picker. Opening it sends him to the chosen task when one is eligible, and the page says there is nothing to revise only when none is. A revision redirect with nothing eligible lands on that same URL, which then shows that message.
- The household file does not contain a full `revision_task` URL. Rules still redirect to the `revision_task` token. The sample and the proxy bypass comment name the host from `hostname`, not `192.168.1.10`.

# Acceptance Criteria

- [x] With `hostname` set to `garden` and `port` left out, and `POLICY_PORT` set to 8090, a revision redirect for an eligible task is `https://garden:8090/tasks/<name>` for the classified client group. Opening `https://garden:8090/tasks/next` while a task is eligible redirects to that same kind of URL and starts the task. With nothing eligible, that URL is the page that says there is nothing to revise, and a revision redirect lands there.
- [x] With `hostname` omitted, those URLs use the hostname of the machine running Compose, read from that machine's `/etc/hostname`. The container's own name is not used. The port and the path are unchanged.
- [x] With `port` set to 443, the URL is `https://<hostname>/tasks/<name>` and does not include `:443`. With `port` set to 8443 while `POLICY_PORT` is 8090, the URL uses 8443. That is the reverse-proxy case.
- [x] A `hostname` that includes a scheme, a port, a path, or a space is a load error, and the previous policy stays in force. An empty value is the same error. A `port` that is not a whole number from 1 to 65535 is the same kind of error.
- [x] The sample policy no longer sets `revision_task`. A file that still sets it fails to load. The rule token `revision_task` still redirects.
- [x] The comment above `hostname` says it is the name external clients use to open the policy server. The comment above `port` says to set it when a reverse proxy changes the port, and that the default is the published policy port.
- [x] `REPORT_PORT` is renamed to `POLICY_PORT`. A stack started with `POLICY_PORT=8090` publishes the policy pages on 8090. The decisions container still binds HTTPS on 8443.

# Notes

Depends on S003.2. This story replaces the placeholder origin that S003.2 copies out of `revision_task`. The picker, the required-task rules, and the task pages stay as they are. `PARENT_NAMES` is still the certificate list. This story does not issue certificates. The quiz pass rule stays with S004.

`REPORT_PORT` is not the port the process binds. The published mapping is host `REPORT_PORT` to container 8443. URL generation uses the published port, under the new name `POLICY_PORT`, unless `port` in the policy file says otherwise.

## Change Summary

A revision redirect no longer copies a URL out of the household file. The scheme is always `https`. The host is `hostname`, or the hostname of the machine running Compose when that is left out. Compose mounts that machine's `/etc/hostname`, because the name inside the decisions container is a container id. The port is `port`, or `POLICY_PORT` when that is left out. Port 443 is omitted. The path is `/tasks/<name>` for the task chosen for the classified client group, and `/tasks/next` when nothing is eligible. Opening that picker starts the chosen task, or says there is nothing to revise.

A hostname that contains a scheme, a port, a path, or a space is a load error, as is an empty hostname. A port that is not a whole number from 1 to 65535 is the same kind of error. The previous policy object is left as it was. A file that still sets `revision_task` fails to load. Rules still redirect to that token.

`POLICY_PORT` is the host port Compose publishes. The decisions container still binds HTTPS on 8443 and plain HTTP on 8090. Task URLs use the published port.

5. Put `revision_task:` back in the household file and confirm the load fails. Confirm a rule whose location is the token `revision_task` still redirects.
6. Read the sample policy. Confirm it does not set `revision_task`, the comment above `hostname` says it is the name external clients use to open the policy server, and the comment above `port` says to set it when a reverse proxy changes the port and that the default is the published policy port. Confirm `config/bypass.txt` names `garden`, not `192.168.1.10`.
