# User Voice

As a parent, I want a page for each task in the parent portal where I can change its settings and look after its
spelling words, so that small changes during the term do not mean editing YAML and moving files by hand.

# Use Cases

## UC1 - Task Administration in the sidebar

- The sidebar has a Task Administration entry among the top-level entries. Clicking it expands a list of every
  configured task, in name order, indented beneath it. Clicking it again collapses the list.
- Task Administration is a `<button>` with `aria-expanded`, because it expands and collapses the list rather than going
  anywhere. Each task under it is a real link to `/parent/tasks/<name>`.
- Whether it is expanded is kept in `localStorage`, as the sidebar width is. It is always expanded while a task page is
  open, and the open task is marked as the open page is.
- When the entries do not fit, the part between the logo and the bottom cluster (signed-in user and Sign out) scrolls.
  The logo and the bottom cluster stay in place.
- The collapsed sidebar strip does not show the task list.

## UC2 - Common settings at the top of every task page

- `/parent/tasks/<name>` shows the task's name in the context bar, as Tasks › spelling, with Save in the context bar.
- The common settings are at the top of the content pane in three columns, grouped:
  - **Task:** name and type, shown but not editable, and the client groups it is assigned to.
  - **Cooldowns and limits:** `pass_cooldown`, `failure_cooldown`, `max_skips`, `max_passes`.
  - **Dates:** `available_from`, `due_date`.
- A field left empty is left out of the YAML. For most fields that leaves the rule off. `pass_cooldown` is no longer
  required: left out, it is 1, which the page shows as a placeholder in the empty box.
- A `parent_check` task does not show `available_from`, `due_date`, `max_skips`, or `max_passes`.
- Under the common settings is a centred divider about 60% of the content pane's width. The type's own administration
  goes below it. A type with no administration page yet shows "Task-specific administration for <type> tasks is not
  built yet." there.

## UC3 - Saving

- Save, or Ctrl+S anywhere on the page, saves every unsaved change on the page at once: the common settings, the
  spelling settings, and the pool changes from UC6. Ctrl+S does not open the browser's save dialog.
- The service rewrites that task in whichever policy file defines it. It keeps the file's comments, its layout, and
  every other entry as they were. It checks the whole policy with the changed file, exactly as `dw check` would, before
  anything is written. A policy that would not load is refused, the status bar lists each error, and no file changes.
- A good save is applied to every service as `dw reload` applies it, and the status bar says so.
- When the policy file has changed on disk since the page was opened, for example after an edit by hand, the save is
  refused with a message saying so. The parent reloads the page and makes the change again.
- Saving a task that has a `due_date`, when one or more client groups already have a pass for it, warns before
  anything is written. The warning names those groups and says that this save does not ask them to do the task again.
  Confirming writes the edit, and Cancel leaves the stored task unchanged. A task with no `due_date` saves without that
  warning.
- With unsaved changes, following a sidebar link, Back, Forward, and Reload ask whether to leave and lose the changes,
  with Stay as the default.

## UC4 - Each save is a version in the config history

- Every save that writes a policy file commits it to the config history from S023.1. The message is the
  household-local time, the signed-in parent, and what was saved, such as
  `2026-11-08 21:15 -0500 brett: saved task spelling`. The commit author is the parent's username.
- Before it writes, a save looks for uncommitted hand edits in the config directory. When it finds some, it checks the
  config directory as it is on disk, exactly as `dw check` would:
  - When that check fails, the save is refused. The status bar says the hand edits on the server do not pass
    `dw check`, and lists the errors. Nothing is written. The parent fixes the files on the server before saving again.
  - When it passes, the hand edits are committed first, as their own version with the message
    `<time> hand edits found before a portal save`, and then the save goes ahead. The hand edits are applied with it.
- When the commit fails, the save still stands and is applied. The status bar warns that it is not in the history,
  and the service logs why.
- A retire or a pool move only moves files in the data directory, so it makes no commit. A save that also changes a
  target, such as `current_required`, commits the policy file.
- Where the config directory has no history of its own, as in a clone of the daywarden repository, saves still work
  and make no commit.

## UC5 - The spelling settings and word list

- The spelling area starts with the spelling task's own settings: `timeout`, `maximum_replays`,
  `maximum_sentence_plays`, `current_required`, `revision_required`, `letter_pause`, and `word_pause`, saved with the
  rest of the page. The directories, `current_dir`, `revision_dir`, `attic_dir`, and `alphabet_dir`, are shown but not
  editable.
- Below them is the word list, with a pool filter in the context bar: Current, Revision, Current and revision, and
  Attic. The filter is in the query string, such as `?pool=attic`, so Back, Reload, and a bookmark keep it. Current and
  revision is the default.
- Each row is one entry, such as `read.1`, with:
  - **Word.** Clicking it plays the word clip in the browser.
  - **Pool.** A pull-down of Current, Revision, and Attic.
  - **Sentence.** Whether the word has a sentence clip. When it does, clicking it plays the sentence.
  - **Actions.** Re-record word and sentence, Re-record word, Re-record sentence, and Retire. The three recording
    buttons are delivered by S023.3. Until then they are not shown. Their Lucide icons are `mic` for word and
    sentence, `whole-word` for the word only, and `message-square-text` for the sentence only.
- The column headers stay in view while the rows scroll. The status bar shows how many words are listed in each pool.
- Words in the alphabet directory are not listed.

## UC6 - Moving and retiring words

- Changing a word's pool pull-down marks the row as changed. Nothing moves until the page is saved. On save, the word
  clip and its sentence clip move together into the new pool's directory, keeping their file names.
- A word moved to Current or Revision from the attic is reinstated.
- Retire asks "Retire <word>? Its recordings move to the attic." and, once confirmed, moves the word clip and its
  sentence clip into the attic at once. It does not wait for Save. A word in the attic has no Retire button.
- A save or a retire that would leave the policy unable to load is refused with a message that says why, and no file
  moves. For example, `current_required: 8` with only 7 current words left. The parent can lower `current_required` or
  `revision_required` in the same save, and then it goes through.
- A word is only ever in one of a task's three pools (UC7), so the pool it moves into never already holds it. A clash
  made by hand on the server after the load, such as copying `rope.opus` into the attic, fails the policy check every
  save and retire runs first, so the save is refused with that error and nothing moves.
- The portal never deletes a recording. The attic is cleaned by hand.

## UC7 - The attic

- A spelling task has a new optional body field, `attic_dir`. A body that does not set it uses an `attic` directory
  beside the default pool directories, `spelling/attic`, under the data directory.
- `attic_dir` follows the same rules as the other directories: a relative path that stays under the data directory.
  The service creates it the first time it retires a word into it. It is not an error for it to be missing at load.
- The quiz never asks an attic word.
- Each word belongs to exactly one of a task's three pools. A word in Current is not in Revision or the Attic. A word
  in Revision is not in Current or the Attic. A word in the Attic is not in Current or Revision. Words are compared by
  entry key, ignoring case, as the pools already are. `read.1` and `read.2` are different entries, so they may be in
  different pools.
- The load checks this. The attic is scanned at load with the same file-name rules as the other two pools. A word in
  more than one pool fails the load, and the error names the task, the field, and both files, such as
  `attic_dir: rope.opus is also in current_dir; a word belongs to one pool`. As with every load error, the whole policy
  is refused and the policy already loaded stays in force. `dw check`, `dw reload`, and `dw up` report it the same way.
- After the load, a pool that goes bad keeps the last word list that scanned cleanly, as the current and revision pools
  already do, and the service logs why.

## UC8 - A run in progress keeps its audio

- A spelling run keeps the words it started with. When the parent moves or retires one of those words during the run,
  the quiz page still plays it, because the audio lookup also searches the task's other pool and its attic when the
  clip is not in the directory the run expected.

# Notes

Depends on S023.1, S007.1, S007.4, S005, and S016. The task pages are routes under the portal layout in
`policy/portal/src/routes.tsx`, and their sidebar entry is in `policy/portal/src/components/Sidebar.tsx`.
`docs/parent-portal.md` gains the expandable sidebar group, Ctrl+S, and the unsaved-changes prompt.

`pass_cooldown` has been required since S003.1, when a cooldown of 0 still re-offered a task on the day it was passed.
Since S018 a task passed today is never offered again today, so 0 and 1 behave the same, and a default of 1 is safe.
The loader defaults it to 1, and the Common task attributes table in `docs/hierarchical-policy.md` says so. Existing
policies that set it keep working unchanged.

Writing:

- The decisions service needs the config directory and the data directory writable. Both are read-only mounts today.
  Only the decisions service gets write access, and only to those two mounts. `docs/hierarchical-policy.md` and the
  comments in `docker-compose.yml` say that the portal now writes there.
- The decisions container runs as root today. Everything it writes into those mounts, including the policy files,
  the `.git` objects, the pool moves, and the attic, must be owned by the host user who installed daywarden.
  Otherwise hand edits, `git`, and `bin/cut-clips` stop working without `sudo`. For example, the container can run as
  that user's uid and gid, which `install.sh` and `make up` record in `.env`.
- Commits from the portal use the helper and the locking described in S023.1.
- The policy is rewritten with a round-trip YAML library that keeps comments and layout, such as `ruamel.yaml`, pinned in
  `policy/requirements.txt`. It must not bring back YAML anchors or merge duplicate keys, which the loader rejects.
- `dw reload` runs inside each container and each service accepts a reload only from its own loopback address. A
  portal save needs another way to tell the observations and autoconfig services to reload. Working that out is part of
  this story. Whatever it is must not let the child, or anything else on the household network, trigger a reload.
- A file move is a rename within the data directory, so a quiz scan never sees half a word. A word clip and its
  sentence clip move together. If the second move fails, the first one is moved back.

Two spelling tasks may share pool directories. A change on one task's page then shows on the other's, as it would after
moving the files by hand. The page does not need to warn about it.

## Change Summary

Task Administration in the sidebar expands a list of every task, each a link to `/parent/tasks/<name>`. The page shows
the task's common settings in three groups, a divider, and the type's own administration, which only spelling has. The
spelling section has its seven settings, the four directories, and the word list with a pool filter in the address.
Save and Ctrl+S send every change at once. Retire acts at once after a question. Leaving with unsaved changes asks
first, and a due-dated task a group has passed asks before saving.

A save finds the file that defines the task, refuses if that file changed since the page loaded, checks hand edits in
the config directory, and loads the whole policy with the changed text and the words already in their new pools. Only
then are the hand edits committed, the words renamed, the file replaced, every service reloaded, and the save
committed as the parent. A failed commit is a warning, and the save stands.

Choices that go beyond, or differ from, the story's notes:

- `ruamel.yaml` is not used. Its round trip re-spaces every flow mapping in the file, `{ action: allow }` becoming
  `{action: allow}`, and drops trailing spaces, which would change entries the parent did not touch. The editor
  instead rewrites only the changed fields' text, using the positions PyYAML reports. A flow mapping it does change,
  such as `body: { timeout: 30s }`, keeps its untouched entries as written. No new package is needed.
- The decisions container still runs as root, and `.env` has no new settings. A rewritten file keeps the owner and
  mode of the file it replaces, a new directory such as the attic takes the owner of the directory it is made in, a
  renamed recording keeps its owner, and git runs as the owner of `.git`. On an installed machine all of those are the
  host user.
- The other services reload through Unix sockets in a `control` volume that lives in memory, with mode 1777 because
  autoconfig runs as nobody. Only the decisions, observations, and autoconfig containers mount it. Nothing on the
  network, and nothing the proxy forwards, can reach a socket. `dw reload` still reaches observations over its loopback
  address, and autoconfig through the same socket as before, now in that volume.
- The settings are labelled in words, such as Pass Cooldown and Required Correct (Current Pool). Each label's title
  is the policy file's field name, which is what the errors name. Dates are text boxes, so a date in another form can
  be typed and is refused naming the field.
- Save sits at the right-hand end of the context bar and is disabled until something changes. While there are unsaved
  changes, an Unsaved changes marker sits beside it, and Ctrl+S with nothing changed does nothing.
- The client groups are a multi-select pull-down. Closed, it shows the chosen groups separated by commas. Open, the
  chosen groups are highlighted with a tick, and one click toggles a group on or off. When a task moves from one group
  to several, `group:` is replaced by `groups: [...]` at the end of the task.
- A move only checks pools that would end up valid. A recording that is already at the destination is never replaced,
  and a word found in two pools on disk refuses every save and Retire with the load's own error.
- After a refused save the page does not fetch the task again, so a file changed on the server keeps the page refused
  until it is reloaded.
- A word's Pool pull-down offers Attic only for a word already in the attic. A current or revision word reaches the
  attic only through Retire, so the question is always asked, and the service refuses a save that tries to move one
  there.
- The word list is Current, then Revision, then Attic, each in key order. A word whose pool was changed stays under
  its old pool, marked, until it is saved.

16. Start a spelling run on the child's computer, then retire or move one of its words from the portal. The word still
    plays on his quiz page for the rest of that run.
17. Copy a word's file by hand into a second pool: current and revision, then current and attic, then revision and
    attic. Each time `dw check` and `dw reload` fail naming the spelling task, the field, and both files, and the
    policy already loaded stays in force. With the clash on disk, a save or a Retire on the spelling page is refused
    with that error, and no file moves.
18. Put a file named `rope two.opus` in `spelling/attic`. `dw check` fails naming `attic_dir` and the file.

    `spelling/old-words`, which is created owned by the host user. Set `attic_dir` to an absolute path, then to one
    with `..`. `dw check` fails naming `attic_dir` each time.
20. Click Task Administration in the sidebar. Every task is listed, indented, in name order. Click it again and they
    hide, with the same animation as the sidebar. Reload and change pages: the choice is kept.

    `https://<host>:<port>/parent/tasks/<name>`.

31. The settings are labelled in words, such as Pass Cooldown, Required Correct (Current Pool), and Attic Directory.

32. On the spelling page, a current or revision word's Pool pull-down offers only Current and Revision. Under Attic, an
    attic word's pull-down offers Current, Revision, and Attic. Retire is the only way to send a word to the attic.
