# User Voice

As a parent, I want a site group to close for the day once its time quota is used, even if revision is already finished.

# Use Cases

- A group may have a daily quota, stored as a duration in seconds, minutes, or hours. `2h` and `120m` are the same value. The configuration does not store a number of buckets.
- The condition `quota_remaining` is true when today's consumed time for this client and this group is strictly below that duration. Consumed time is the sum of the lengths of buckets that contained traffic and have already ended.
- Changing the bucket length does not change the stored duration.
- A group with no quota configured makes the condition true.
- Until S002.1 is filling buckets from real traffic, the consumed time is whatever the ledger store says, including a value written by a test.

# Acceptance Criteria

- [ ] A quota written as `2h` is stored as two hours. The same value written as `120m` or `7200s` compares equal to it. A quota written as a bare bucket count is rejected.
- [ ] With a `2h` quota and five-minute buckets, 23 ended buckets (115 minutes) leave the condition true, and 24 ended buckets (120 minutes) make it false.
- [ ] Changing the bucket length from five minutes to ten minutes leaves that stored quota at two hours. Buckets already counted still contribute five minutes each. A new ended bucket contributes ten minutes.
- [ ] A bucket whose end time is still in the future is not counted, even if it is marked active.
- [ ] Yesterday's buckets are not counted today.
- [ ] Another group's buckets are not counted against this group.
- [ ] Another client's buckets are not counted against this client.
- [ ] A group with no quota configured allows the condition to pass.
- [ ] Plugged into the sample schedule from S001.3, at 16:00 on Wednesday with tasks already complete, remaining quota allows the request and exhausted quota denies it with the rule's message.

# Notes

Depends on S001.3. The real definition of a counted bucket is owned by S002.1. This story owns the condition and a small store that S002.1 will write to. Agree the store shape with S002.1 before implementing both.
