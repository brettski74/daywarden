# User Voice

As a parent, I want the reports and the editors behind a password, so that he cannot mark his own revision finished or raise his own YouTube quota.

# Use Cases

- A parent sets a password out of band, in the service configuration, not in a page the child can open.
- Parent pages require a signed-in session.
- Quiz pages, the decision API, and the observation API do not use that session.
- The usage report and the attempt review use this sign-in and drop any temporary barrier from earlier stories.

# Acceptance Criteria

- [ ] Opening a parent page with no session asks for the password and shows no report data and no editor.
- [ ] The correct password starts a session and the next parent page opens without asking again until the session ends.
- [ ] A wrong password does not start a session.
- [ ] Ending the session, or restarting the browser, requires the password again.
- [ ] The password is not stored in plain text in SQLite.
- [ ] The decision API and the observation API still work with no parent session, from the proxy only. They are not a way to edit policy.
- [ ] A quiz page loads with no parent session.
