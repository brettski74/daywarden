# User Voice

As a child, I want one question in the middle of the screen, a box that is ready for my answer, and a bar that shows how much time I have left, so that I can practice without hunting around the page.

As a parent, I want each outcome to play one of several sound effects at random, so that the hundredth correct answer does not necessarily sound exactly like the first.

As a parent, I want the server, not the browser, to decide whether an answer beat the timer, and I want a reload to be neither a way to skip a hard question nor a way to lose a session he was halfway through.

# Use Cases

## Questions

- The task configuration includes a maximum timeout, a minimum timeout, the number of correct answers required, and a list of whole numbers, each with a positive whole-number weight. The Configuration section below gives the field names.
- Each question draws two values, `m` and `n`, independently. `m` is the first operand drawn. `n` is the second.
- An optional second weighted list, `first`, applies to `m` only. When it is set, `m` is drawn from `first` and `n` from `operands`. When it is left out, both are drawn from `operands`. This lets a parent drill one fact family, such as the seven times table, without narrowing the other operand.
- A question is the operation and the ordered pair `(m, n)`. `6 + 7` and `7 + 6` are different questions.
- None of the last three questions issued in this attempt is issued again. A question more than three questions old may come back. The draw is the weighted draw with those recent questions left out, so the remaining questions keep their relative weights.
- When the lists allow so few distinct questions that every one of them is recent, the oldest of the recent questions is allowed back first, then the next oldest. The question just asked is the last to be allowed back. A single-question configuration therefore still works.

## Start screen

- Opening the task shows a start screen before any question. It shows the operation, such as "Addition", and his progress, such as "0 / 20 correct", or "7 / 20 correct" when he is resuming.
- The Start button is focused. Pressing Enter or clicking it shows the first question. No timer runs on the start screen.
- The start screen exists so that his first key press unlocks the browser's audio. Browsers block a page's sound until the person has interacted with it.

## Answering

- The question is shown in very large text in the centre of the screen. Under it is a moderately large text box, focused when the question appears.
- Correct answers out of the target, such as "7 / 20", are shown small near the top of the screen.
- A timer bar at the bottom shows the time remaining for this question. It shrinks from full to empty over the question's time.
- The box accepts digits only. Other characters do not appear in it. An answer of `013` is the number 13.
- Enter submits the contents of the box. Enter on an empty box does nothing, and the timer keeps running.
- A correct answer scores one point, shows that it was correct, and plays a correct sound.
- An incorrect answer does not change the score, shows the full question with the right answer, such as `6 + 7 = 13`, and plays an incorrect sound.
- If the timer reaches zero, a box that already holds the right answer is treated as correct. An empty or wrong box is a timeout: same as incorrect, but it says the time ran out and a timeout sound plays instead.
- After `k` correct answers, with `N` required and `N > 1`, the next timeout is `Tmax * (Tmin / Tmax) ^ (k / (N - 1))`. It is `Tmax` at `k = 0` and `Tmin` at `k = N - 1`. When `N` is 1, the timeout is `Tmax`. Incorrect answers and timeouts do not change `k`, so they do not shorten the next question's time.

## Feedback

- Feedback stays on screen for about 1 second after a correct answer and about 2.5 seconds after an incorrect answer or a timeout. Then the next question appears on its own. He does not press anything to continue.
- No timer runs during feedback. The box is disabled, and keys pressed during feedback are not carried into the next question.
- A sound keeps playing after the next question appears. A new sound stops the one before it, so two sounds never overlap.

## Timing on the server

- The server decides every outcome. The browser draws the timer bar, but it does not decide whether an answer was in time.
- The browser asks the server for each question when the start screen or the previous feedback ends. The server records when it issued the question. That moment starts the question's time.
- The browser is not sent the expected answer with the question. It learns the answer only in the server's response to his submission.
- An answer is in time when the server receives it no later than the question's time plus an allowance of 0.5 seconds for network delay. An answer that arrives later is a timeout, whatever it says. The late answer is still recorded.
- When the timer bar reaches zero, the browser sends whatever is in the box, including an empty box. The server applies the rule above: the right answer in time is correct, and anything else is a timeout.

## Resume and expiry

- Progress is stored on the attempt on the server as each answer is recorded. A reload, a closed tab, or a closed browser does not lose it.
- Activity is a page load, a question being issued, or an answer being recorded. Coming back within one hour of his last activity resumes the attempt. The start screen shows his progress, and the correct count carries on from where it was.
- A question that was issued and not answered when he left counts as a timeout. That is recorded when he comes back, or when the attempt expires. Reloading is not a way to skip a hard question.
- Coming back more than one hour after his last activity starts the same attempt again from zero correct answers. No abandonment and no skip day is recorded. Earlier answers stay in the attempt record, marked as an expired run.
- The hour is fixed. It is not a configuration setting.
- An attempt uses the task settings stored on it when it started. Editing the task while it is in progress does not change that attempt, as S007.3 also says. A run that starts after an expiry uses the task settings in force at that moment.

## Finishing and giving up

- When the server records the answer that reaches the required number of correct answers, it finishes the attempt as a pass at that moment. The correct sound for that answer plays.
- A "Well done" screen follows. When another task is eligible for this client group, it shows a "Next task" button that goes to the task S003.2 would pick. When none is, it says "All done for now".
- "Try a different task" uses the give-up behaviour from S003.2. On the start screen and during questions it is a small button in a top corner. Enter does not trigger it. Clicking it asks "Are you sure?" before giving up. The timer keeps running while he decides, and a question whose time runs out during that step is a timeout as usual.
- When S003.2 does not allow giving up because this is the only required task, the page says the task has to be finished, and he returns to the start screen with his progress kept. A question that was showing when he chose to give up counts as a timeout.

## Sound sets

- There are three sound sets, one per outcome. Each set is a directory under `policy/static/sounds/`:
  - `correct/`
  - `incorrect/`
  - `timeout/`
- The policy server serves these files under `/static/sounds/` on the task host.
- Every time an outcome plays a sound, one file is chosen at random from that outcome's set. Each file in the set is equally likely. Consecutive answers may repeat a file.
- A set is the audio files in that directory: `.mp3`, `.wav`, `.ogg`, `.opus`, and `.m4a`. Any other file, such as an attribution note, is not a sound and is never played.
- Adding or removing a sound is a file change in that directory. It needs no code change and no policy file change. The directory is part of the policy image, so the change takes effect when the image is rebuilt.
- A set with no audio files plays no sound for that outcome, and the quiz otherwise works the same. The policy service logs a warning naming the empty set when it starts.
- The sets are shared by every quiz type. A timeout never plays a file from `incorrect/`, and an incorrect answer never plays a file from `timeout/`.
- The page has no mute control. The computer's own volume is the control.

# Configuration

An arithmetic task is a task from S003.1 with `type: arithmetic`. The quiz fields are in the task's `body`:

| Field | Required | Value |
| --- | --- | --- |
| `operation` | Yes | `addition`, `subtraction`, `multiplication`, or `division`. S004.2 through S004.5 define each one. |
| `max_timeout` | Yes | `Tmax`, the time allowed for the first question. A duration greater than zero. |
| `min_timeout` | Yes | `Tmin`, the time allowed once `N - 1` answers are correct. A duration greater than zero and no longer than `max_timeout`. When the two are equal, every question has the same time. |
| `correct_answers_required` | Yes | `N`, the number of correct answers that pass the attempt. A whole number, 1 or more. |
| `operands` | Yes | The weighted list `n` is drawn from. `m` is drawn from it too when `first` is left out. A list of one or more entries, described below. |
| `first` | No | The weighted list `m` is drawn from. Same structure and rules as `operands`. When it is left out, `m` is drawn from `operands`. |

S004.2 through S004.5 say where `m` and `n` appear in each question. For addition and multiplication, `m` is always the number on the left. For subtraction and division, `m` is the number being taken away or divided by, and `n` is the answer.

A duration is written the way the rest of the policy file writes one: a whole number with a unit, such as `10s` or `1m`. `ms` is also accepted here, so `7500ms` is seven and a half seconds. A bare number such as `10` is rejected, so seconds and milliseconds cannot be confused.

Each `operands` or `first` entry has a `weight` and either one `value` or an inclusive `from`/`to` range:

| Field | Value |
| --- | --- |
| `value` | One whole number, 0 or more. |
| `from`, `to` | Whole numbers, 0 or more, with `from` no larger than `to`. Every number from `from` to `to`, including both ends, is in the list. Each one gets the entry's full weight. The weight is not split across the range. |
| `weight` | A whole number, 1 or more. A value's chance of being drawn is its weight divided by the total weight of the list. |

Operands are never negative, so no answer to any of the four operations is negative and the answer box needs no minus sign. A negative `value`, `from`, or `to` is invalid configuration.

Within one list, a value may appear only once across all entries. A repeated `value`, or ranges that overlap each other or a `value`, is invalid configuration. An entry with both `value` and `from`/`to`, with neither, or with only one of `from` and `to` is invalid configuration. Any field not listed here is invalid configuration. `first` and `operands` are separate lists. The same value may appear in both, with a different weight in each. `first`, when present, must have at least one entry. An empty `first` is invalid configuration, not the same as leaving it out.

Invalid arithmetic configuration fails the policy load, the same as a bad date or an unknown client group, and leaves the previous policy in force. The error names the task and the field.

This example gives weight 5 to 1, weight 7 to 2, weight 10 to every integer from 3 to 9, and weight 5 to 10. It allows 10 seconds for the first question, shrinks to 4 seconds, and passes after 20 correct answers:

```yaml
tasks:
  times-tables:
    type: arithmetic
    group: kids
    pass_cooldown: 1
    body:
      operation: multiplication
      max_timeout: 10s
      min_timeout: 4s
      correct_answers_required: 20
      operands:
        - { value: 1, weight: 5 }
        - { value: 2, weight: 7 }
        - { from: 3, to: 9, weight: 10 }
        - { value: 10, weight: 5 }
```

This example drills the seven times table. Every question is `7 × n`, and `n` runs from 1 to 12 with 1 and 10 drawn less often:

```yaml
tasks:
  sevens:
    type: arithmetic
    group: kids
    pass_cooldown: 7
    body:
      operation: multiplication
      max_timeout: 8s
      min_timeout: 3s
      correct_answers_required: 15
      first:
        - { value: 7, weight: 1 }
      operands:
        - { value: 1, weight: 2 }
        - { from: 2, to: 9, weight: 5 }
        - { value: 10, weight: 2 }
        - { from: 11, to: 12, weight: 5 }
```

# Attempt Record

The attempt's `detail` from S003.1 holds:

- `settings`: the task body this run is using, copied when the run started.
- `runs`: one entry per run, numbered from 1, with the time it started and, for an expired run, the time it expired. The last run is the current one.
- `questions`: every question issued in this attempt, in order. Each one has:
  - the run number
  - `m` and `n`
  - the question as displayed, such as `6 + 7 =`
  - the expected answer
  - his answer as received, or nothing when the box was empty or no answer arrived
  - the outcome: `correct`, `incorrect`, or `timeout`
  - the time allowed in milliseconds
  - the time he took in milliseconds, from issue to receipt, or the time allowed when no answer arrived
  - the household-local time the question was issued

The correct count is the number of `correct` questions in the current run. The last three questions issued come from this list, across runs.

S003.3 already shows a list of answers one at a time, so the parent can read this record as soon as this story is done. S004.6 adds a summary and a formatted view.

# Acceptance Criteria

## Configuration and draws

- [ ] With weights 5 for 1, 7 for 2, 5 for 10, and 10 for each integer from 3 to 9, a large sample of draws falls inside that distribution. A test checks the frequencies within a stated tolerance, not a single draw.
- [ ] A `from: 3, to: 9, weight: 10` entry gives each of 3 through 9 weight 10, the same as seven separate `value` entries.
- [ ] With `first` left out, `m` and `n` are both drawn from `operands`, and a large sample of each follows the `operands` weights.
- [ ] With `first` set to the single value 7 and `operands` set to 1 through 12, every question has `m = 7`, and a large sample of `n` follows the `operands` weights.
- [ ] With `first` set to 2 at weight 1 and 3 at weight 3, a large sample of `m` is about one quarter 2 and three quarters 3, while `n` still follows `operands`. Values in `operands` and not in `first` never appear as `m`.
- [ ] The same value may appear in both `first` and `operands` with different weights. That is not a repeated value.
- [ ] `first` is checked by the same rules as `operands`. An empty `first` list, a repeated value inside `first`, or a weight of zero in `first` is rejected as invalid configuration.
- [ ] A weight of zero or a negative weight is rejected as invalid configuration. A positive weight is accepted.
- [ ] A negative `value`, `from`, or `to` is rejected as invalid configuration. A value of 0 is accepted.
- [ ] A value listed twice, overlapping ranges, a range with `from` greater than `to`, and an entry with both `value` and `from` are each rejected as invalid configuration.
- [ ] A missing `max_timeout`, `min_timeout`, `correct_answers_required`, or `operands`, a `min_timeout` longer than `max_timeout`, a timeout of zero, a bare-number timeout such as `10`, and a `correct_answers_required` of zero are each rejected as invalid configuration. The policy load fails and the previous policy stays in force.
- [ ] `max_timeout: 7500ms` allows seven and a half seconds, and `max_timeout: 10s` allows ten.
- [ ] The operand list is not limited to the integers 1 through 10. A configured value of 12 can appear.
- [ ] Over a long run of questions, no question repeats any of the three questions issued before it. A question four or more back can be issued again.
- [ ] With the three most recent questions left out, a large sample of the next question follows the remaining weights, in proportion to each other.
- [ ] `6 + 7` may be issued straight after `7 + 6`.
- [ ] A configuration that allows only two distinct questions alternates between them. A configuration that allows only one still issues it every time.

## Session flow

- [ ] Opening the task shows the start screen with the operation and "0 / N correct", and no timer runs. Enter on the start screen shows the first question.
- [ ] The input is focused when each question is shown.
- [ ] Letters and symbols typed into the box do not appear. Enter on an empty box does not submit, and the timer keeps running.
- [ ] Submitting the right answer increases the correct count by one, updates the "k / N" display, and plays a sound from `correct/`. `013` for an answer of 13 is correct.
- [ ] Submitting a wrong answer leaves the correct count unchanged, shows the full question with the expected answer, and plays a sound from `incorrect/`.
- [ ] When the timer expires with the right answer already in the box, it counts as correct and plays a sound from `correct/`.
- [ ] When the timer expires with an empty or wrong box, it counts as a timeout and plays a sound from `timeout/`, never one from `incorrect/`.
- [ ] Feedback lasts about 1 second after a correct answer and about 2.5 seconds after an incorrect answer or timeout, then the next question appears without a key press. Keys pressed during feedback do not appear in the next question's box.
- [ ] A long correct sound keeps playing into the next question, and the next sound stops it.
- [ ] With `Tmax` 10 seconds, `Tmin` 4 seconds, and 5 correct answers required, the first question has 10 seconds and the question after 4 correct answers has 4 seconds. The timeouts in between follow the formula. An incorrect answer does not shorten the next question's time.
- [ ] The page is usable from the keyboard: Enter to start, type an answer, Enter to submit, see the next question.

## Server timing and resume

- [ ] The question sent to the browser does not include the expected answer.
- [ ] An answer the server receives within the question's time plus 0.5 seconds is judged on its value. A right answer received after that is a timeout. A test drives the server's clock, not a browser.
- [ ] Reloading while a question is showing records that question as a timeout. After the reload, the start screen shows the same correct count, and the next question is a new one.
- [ ] Closing the browser and coming back 59 minutes after the last activity resumes at the same correct count.
- [ ] Coming back 61 minutes after the last activity resets the correct count to zero on the same attempt. The earlier questions are still in the record as an expired run. No abandonment and no skip day is recorded.
- [ ] A long session never expires while he keeps answering, even when it runs well over an hour from its start.
- [ ] Changing `correct_answers_required` in the policy while an attempt is in progress leaves that attempt's target unchanged. A run that starts after expiry uses the new value.

## Finishing and giving up

- [ ] Reaching the required number of correct answers records the attempt as a pass at the time of that answer and increments today's revision count.
- [ ] The "Well done" screen shows "Next task" when another task is eligible, and that button opens the task S003.2 picks. With nothing else eligible, it says "All done for now".
- [ ] Wrong answers and timeouts never mark the attempt failed.
- [ ] Enter never activates "Try a different task". Clicking it asks for confirmation. Cancelling leaves the question and timer running. Confirming follows S003.2.
- [ ] On the only required task, confirming "Try a different task" leaves the attempt in progress, says the task has to be finished, and returns to the start screen with progress kept. A question that was showing counts as a timeout.

## Sounds

- [ ] With three audio files in a sound set, a large sample of choices picks each of the three, within a stated tolerance of one third each. Nothing outside that set is chosen.
- [ ] A non-audio file in a sound directory, such as `ATTRIBUTION.md`, is never offered as a sound.
- [ ] Adding a fourth audio file to a set makes it one of the choices without a code or policy change.
- [ ] With an empty sound set, that outcome plays no sound, the quiz still records the answer and moves on, and the service logs a warning naming the empty set at start-up.
- [ ] The sound files load from `/static/sounds/` on the task host through the proxy, under the same policy rule that allows the task page.

## Record and docs

- [ ] Each question is stored with its run, `m`, `n`, displayed question, expected answer, his answer, outcome, time allowed, time taken, and issue time, and is visible in the S003.3 attempt view.
- [ ] `docs/hierarchical-policy.md` describes the arithmetic task fields and the sound sets.

# Notes

Depends on S003.2. S004.2 through S004.5 supply the question text and the expected answer. This story is built and tested with addition from S004.2 as the only operation. The later stories add the other three without changing the shell. S004.6 adds the formatted parent review.

The sound sets are UI assets that ship in the policy image. They are not household data and are not configured in the policy file. Spelling clips recorded by the parent in S005 are household data and live with the policy file, not here.

The task layer from S003.1 stores `body` without reading it. This story adds a check for `type: arithmetic` bodies at load time, so a bad operand list is caught when the file is loaded rather than when the child opens the task.

The 0.5-second allowance and the 1-second and 2.5-second feedback times are starting values. They are constants in the code, not configuration. They can be tuned once he has used the quiz.

The 4.4-second fanfare will still be playing during the next question. That was chosen over holding the next question back.
