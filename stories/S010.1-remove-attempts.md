# User Voice

As a parent testing a quiz, I want to remove stored attempts by client group, task, task type, or age, so that a task I just passed is offered again without waiting out its cooldown and without editing the database by hand.

# Use Cases

- `rm-attempts`, run on the machine running Compose from any directory, takes these filters. Each may be given more than once:
  - `--client GROUP`: attempts by that client group.
  - `--task NAME`: attempts on that task.
  - `--type TYPE`: attempts on any task of that type in the policy file. A row stored under the built-in name `parent_check`, with no task of that name in the file, is a `parent_check` row.
  - `--older-than AGE` and `--newer-than AGE`: the age of the attempt is measured from its finish, or from its start while it is still in progress. An age is a whole number with `m`, `h`, or `d`, such as `30m`, `2h`, or `7d`.
- Several values for the same filter match any of them. Different filters must all match.
- Without `--yes`, the command lists the attempts that match and removes nothing. With `--yes`, it lists them and removes them.
- With no filter, the command refuses and says so. `--all` matches every attempt.
- Removing an attempt is permanent. Its answers are gone from `/attempts`. A removed pass no longer counts toward today's `tasks_required`. A removed pass or failure no longer starts a cooldown. A removed failure or abandonment is no longer a skip day.
- Removing an in-progress attempt means the next page load starts a new attempt.
- The parent-check audit log that sits beside the accounts is not changed.

# Acceptance Criteria

- [x] `rm-attempts` runs from any directory on the Compose machine, through a symlink in `~/bin`, and its arguments reach `remove-attempts` in the decisions container unchanged.

- [x] With attempts for two client groups and two tasks, `--client younger --task sums` matches only the younger group's `sums` attempts.
- [x] Two `--task` values match attempts on either task.
- [x] `--type arithmetic` matches attempts on every arithmetic task in the policy file and no other task. A `--type` that no task in the policy file has matches nothing and says that no task has that type.
- [x] `--type parent_check` matches rows recorded under the name `parent_check`.
- [x] `--newer-than 1h` matches an attempt finished 30 minutes ago and not one finished 2 hours ago. `--older-than 1h` is the reverse. An in-progress attempt's age is measured from its start.
- [x] Without `--yes` nothing is removed, and the output says how many attempts would be removed. With `--yes` they are removed.
- [x] With no filter and no `--all`, the command exits with an error and removes nothing. `--all --yes` removes everything.
- [x] An age such as `10`, `1w`, or `-1h` is rejected with a usage error.
- [x] After removing a passed attempt, that task is eligible again for that client group, and today's pass count drops by one.

# Notes

The policy file is read only for `--type` and for the household timezone. A stored time without an offset is read in that timezone.

# Implementation

## Files Added/Changed/Removed

- Added `bin/rm-attempts`, the host script. It finds the repository from its own path, through a symlink, and runs `docker compose exec decisions python -m policy.maintenance remove-attempts` with the arguments it was given. It passes `-T` when it is not attached to a terminal, so it also works from another script.
- Added `policy/maintenance.py`, which holds the `remove-attempts` job the script runs.
- Added `tests/test_maintenance.py` and `tests/test_rm_attempts.py`.
- Changed `policy/tasks.py` to add `AttemptStore.everything` and `AttemptStore.remove`.
- Changed `README.md` to add a Maintenance section.
- Added `stories/S010-maintenance.md`, the epic this story starts.

## Change Summary

`rm-attempts` is what the parent types. It is linked into `~/bin`, which is on the `PATH`, so it needs no directory, no `docker compose exec`, and no `python -m`. Behind it, `policy.maintenance` is an `argparse` program with one subcommand per maintenance job, so a later command is another script in `bin/` and another subcommand. It reads `POLICY_DB`, `POLICY_FILE`, and `MACHINE_LOCALTIME` the same way the service does.

`remove-attempts` filters on client group, task name, task type, and age. Repeated values of one filter are alternatives, and different filters must all match. Task type comes from the policy file. Rows stored under the built-in name `parent_check` with no task of that name in the file count as `parent_check`. Age is measured from the finish, or from the start of an attempt in progress. Ages are `m`, `h`, or `d`, and zero, bare numbers, fractions, negatives, and other units are usage errors.

The command always lists the matching attempts first. Without `--yes` it says how many would be removed and stops. With no filter it exits with a usage error unless `--all` is given. If `--type` is used and the policy file is missing or does not load, it stops before touching the database. Otherwise a bad policy file only means the machine timezone is used.

Eligibility, cooldowns, skip days, and pass counts are all read from the attempt rows, so a removal takes effect on the next request. The decisions service does not need a restart. The parent-check audit table is left alone.

A dry run against a copy of the household database listed the passed `sums` attempt and the two `parent_check` rows as expected. The live database was not changed.

## Suggested Acceptance Testing

### Acceptance test cases for S010.1

1. Rebuild with `make up`. From any directory, run `rm-attempts --client younger --task sums`. Confirm it lists the passed `sums` attempt, says "1 attempt would be removed", and that `/attempts` still shows it.
2. Run the same command with `--yes`. Confirm it says "removed 1 attempt", the attempt is gone from `/attempts`, today's revision count dropped by one, and opening the task now starts a fresh attempt without a restart.
3. Run `rm-attempts --yes` with no filter and confirm it refuses with a usage error and removes nothing.
4. Pass a quiz, then run `rm-attempts --type arithmetic --newer-than 1h` and confirm it lists that attempt. Run it with `--older-than 1h` and confirm it does not.
5. Run `rm-attempts --type parent_check` and confirm it lists the parent-check passes recorded from `/attempts`.
6. Run `rm-attempts --type division` and confirm it says no task in the policy file has that type and that no attempts match.
7. Try `rm-attempts --older-than 10`, `--older-than 1w`, and `--older-than -1h`. Confirm each is a usage error.
8. Run `rm-attempts --help` and confirm every option is described.
