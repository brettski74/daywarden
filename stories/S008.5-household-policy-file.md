# User Voice

As a parent, I want the file the service actually loads to be the household schedule in the new shape, so that we can try it on real sites.

# Use Cases

- Replace `config/policy.toml` with a YAML policy the service loads on startup.
- One client group is the younger child, with a clearly marked placeholder address. The older child is not required in this file.
- School sites are allowed for that child at any time.
- Entertainment uses the Monday-to-Thursday schedule: bedtime denies, school hours redirect to revision, the evening continues only when today's successes reach 2, and a `2h` quota then allows or denies. Friday, Saturday, and Sunday are present and marked as a suggestion, with a wider evening.
- Sites in no configured group are `default` and use the same hours and the same revision count, with no time quota.
- An address in no configured client group is `default` and is not granted access by this file.

# Acceptance Criteria

- [ ] Loading the file and evaluating the Wednesday times from S001.3 against `https://www.youtube.com/watch?v=abc` for the younger child's address returns that story's decisions.
- [ ] The same Wednesday morning request to a Classroom URL in the starter list is allowed for that child.
- [ ] A URL that matches no configured site group is decided by the `default` site rules, not by the YouTube messages.
- [ ] A request from an address in no client group is denied with "No rule granted access.", including a Classroom URL asked of the policy service.
- [ ] The entertainment quota is `2h`. With the revision count already satisfied, 24 ended five-minute buckets deny YouTube in the evening with the quota message.
- [ ] The README describes the YAML file, the implicit `default` groups, and how to restart the decisions service after an edit. It no longer tells the parent to add `[[groups.rules.windows]]` tables.
- [ ] `config/policy.toml` is not loaded. The proxy bypass list is left as a proxy file. This story does not generate it.
