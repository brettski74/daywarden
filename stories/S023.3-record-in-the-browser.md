Title: Record a word or sentence in the browser

# User Voice

As a parent, I want to re-record a word or its sentence from the spelling page using my computer's microphone, hear
the result, and decide whether to keep it, so that fixing a bad recording takes a minute and not a session with
`bin/cut-clips`.

# Use Cases

## UC1 - Re-record from a word's row

- Each row of the spelling word list from S023.2 has three recording buttons: Re-record word and sentence, Re-record
  word, and Re-record sentence. Each is an icon button with an `aria-label` and a `title`. The icons are Lucide's
  `mic` for word and sentence, `whole-word` for the word only, and `message-square-text` for the sentence only.
- Pressing one opens a modal recording dialog for that word. The dialog shows what to say, one line for each clip, such
  as "rope" and then "Sentence for rope".

## UC2 - Recording without key chatter

- The dialog asks for the microphone the first time. When the browser refuses it, or there is no microphone, the
  dialog says so and records nothing.
- "Press any key to start recording" starts the recording on any key press, or on the Start button.
- While recording, the dialog shows the lines to say and a clear recording indicator. Nothing needs to be typed while
  recording. Enter, or the Stop button, ends it.
- Escape before recording starts, or Cancel, closes the dialog and changes nothing.

## UC3 - Cutting on the server

- The recording is sent to the service, which cuts it with the same library as `bin/cut-clips`: loudness
  normalization, finding the clips, faded guards, and Ogg Opus encoding, with the same defaults.
- The cut clips are held as pending on the service. Nothing in a pool directory changes until the parent keeps a clip.
- A collapsed Advanced section in the dialog shows minimum silence, threshold, minimum speech, guard, and loudness, at
  the `bin/cut-clips` defaults. Changing them and pressing Cut again cuts the same recording again without
  re-recording it.
- **Threshold** is a slider with an editable number beside it, in dB below the loudest point, default 35 dB. The two
  stay in step: dragging the slider updates the number, and typing a number moves the slider. The slider runs from 10
  to 80 dB in 1 dB steps. The number accepts anything `bin/cut-clips --threshold` accepts, above 0 and below 200 dB.
  A number beyond the slider's range leaves the slider at that end.
- **Loudness** is a slider with an editable number beside it, in LUFS, default −18 LUFS. They stay in step the same
  way. Both run from −40 to −10 LUFS, the range `bin/cut-clips --loudness` accepts, in 1 LUFS steps.
- Minimum silence, minimum speech, and guard are number boxes in milliseconds, with the same lower limits as
  `bin/cut-clips`: 200, 0, and 10 ms.
- A value outside its range is shown as an error beside the field, and Cut stays disabled until it is fixed.
- Each Advanced field can be put back to its `bin/cut-clips` default:
  - **A reset button** beside the field, with a Lucide `RotateCcw` icon and an `aria-label` and `title` that name the
    field and its default, such as "Reset threshold to 35 dB". It shows only while the field differs from its default.
  - **A double-click** on a slider resets it.
  - **Alt+R**, with the focus on a field, resets that field.
- For a slider and its number, resetting either one resets both.
- Every field can be put back at once:
  - **A "Reset all" button** in the Advanced heading, shown only while any field differs from its default.
  - **Alt+Shift+R**, with the focus anywhere in the Advanced section.
- Escape does in the Advanced section what it does anywhere else in the dialog, as in UC2.
- The review shortcut keys from UC4 do nothing while the focus is in an Advanced field, so typing a number never
  keeps, junks, or replays a clip.
- Putting fields back to their defaults does not cut again. Cut does that.

## UC4 - Review, keep, or discard

- The dialog plays each clip as soon as it is cut, showing clearly what is playing, such as "Playing: rope (word)" or
  "Playing: rope (sentence)".
- For Re-record word and sentence, the first clip is the word and the second is the sentence.
- The review controls are the ones S023.4 uses for a whole week's recording, here with only one or two items:
  - **Keep:** this clip becomes the recording for this item. Move to the next item and the next clip.
  - **Junk:** this clip is noise or something else. Discard it and play the next clip, still for the same item.
  - **Discard:** this clip is the item but is poor or badly cut. Discard it and move to the next item and the next clip.
  - **Missing:** this item was not said, or was run into the clip before it. Move to the next item, staying on this
    clip.
  - **Replay:** play this clip again.
  - **Back:** undo the last decision and return to that clip and item.
- Each control has a one-key shortcut shown on its button: K keep, J junk, D discard, M missing, R replay, B back. The
  shortcuts work only during review, never while recording.
- When the cutter finds no clips, the dialog says so and offers Record again and Advanced.
- When the items run out with clips still unreviewed, the dialog says how many were left over and ignores them.
- At the end, the dialog lists each item with Kept, Discarded, or Missing. Confirm writes the kept clips. Cancel
  throws them all away.

## UC5 - Writing a kept clip

- A confirmed clip replaces the word's old clip of that kind, in the word's own pool directory, written as
  `<key>.opus` or `<key>.sentence.opus`. An older recording of the same kind in another format, such as `rope.mp3`, is
  removed when the new clip is in place, as `bin/cut-clips` does when it replaces one.
- A sentence clip can be recorded for a word that has none.
- A clip is written to a hidden file and renamed into place, so a quiz run never sees half a clip.
- Pending clips that are never confirmed are thrown away. Pending clips older than a day are removed when the service
  starts, and the next time anything is recorded.

## UC6 - The session ends while recording

- A long recording can outlast the parent session's idle limit. When the upload is refused because the session has
  ended, the dialog keeps the recording in the page and says "Your session has ended. Sign in again in another tab,
  then press Upload." Pressing Upload sends it again. The portal never resends it on its own.

# Acceptance Criteria

- [ ] Re-record word on a current word, then Start, saying the word, and Enter plays back the new clip with
      "Playing: <word> (word)" on screen. Keep and Confirm replace `<word>.opus` in `spelling/current`. The quiz plays
      the new recording from the next question that asks the word.
- [ ] Re-record word and sentence, saying the word then a sentence, plays back the word clip and then the sentence
      clip, each labelled. Confirming both replaces `<word>.opus` and `<word>.sentence.opus`.
- [ ] Re-record sentence on a word with no sentence adds `<word>.sentence.opus`. The word list then shows a sentence
      for it, and clicking that indicator plays it.
- [ ] Discard, or Cancel at the end, leaves the word's files on disk exactly as they were.
- [ ] A recording with a cough before the word, reviewed with Junk on the cough and then Keep on the word, keeps the
      word.
- [ ] Missing on the word during a word-and-sentence recording, where only the sentence was said, moves straight to
      the sentence with the same clip, and Keep keeps it as the sentence.
- [ ] Back after a wrong Keep returns to that clip and item, and the earlier choice is undone.
- [ ] Replay plays the clip again. The K, J, D, M, R, and B keys do the same as the buttons during review.
- [ ] A key pressed while recording, other than Enter, does nothing.
- [ ] Re-recording a word whose old clip is `rope.mp3` leaves only `rope.opus` once confirmed.
- [ ] Recording silence reports that no clips were found and offers Record again. Nothing is written.
- [ ] Changing the Advanced threshold and pressing Cut cuts the same recording again, and the clips found change,
      without recording again.
- [ ] Dragging the threshold slider updates its number, and typing 42 in the number moves the slider to 42 dB.
      Typing 120 is accepted and leaves the slider at its 80 dB end.
- [ ] The loudness slider and its number move together from −40 to −10 LUFS. Typing −5 shows an error, and Cut is
      disabled until it is fixed.
- [ ] Changing the threshold shows a reset button beside it, titled "Reset threshold to 35 dB". Pressing it puts the
      threshold back to 35 dB, the slider and the number both, and the button disappears. The loudness keeps any value
      it was changed to.
- [ ] Double-clicking the loudness slider puts it back to −18 LUFS, and its number follows.
- [ ] Alt+R with the focus on the minimum silence box puts only that box back to 700 ms.
- [ ] After changing several fields, "Reset all" in the Advanced heading, or Alt+Shift+R anywhere in the Advanced
      section, puts all five back to the `bin/cut-clips` defaults. "Reset all" is not shown when nothing differs.
- [ ] The reset buttons are reached with Tab and work with Enter and Space.
- [ ] Escape with the focus in the Advanced section behaves exactly as it does elsewhere in the dialog.
- [ ] Pressing K, J, D, M, R, or B while the focus is in an Advanced field does not act on the clip under review.
- [ ] A browser that refuses the microphone shows a message in the dialog. Nothing is uploaded.
- [ ] Changing an Advanced setting and pressing Cut on a long take cuts again straight away. The browser's network
      panel shows a small cut request and no second upload of the recording.
- [ ] A clip is normalized and encoded as `bin/cut-clips` would. `bin/cut-clips --list` on the same take, and the
      clip the portal wrote, have matching loudness.
- [ ] Letting the session expire before Stop, then signing in in another tab and pressing Upload, cuts the recording
      without recording it again.
- [ ] A word re-recorded in a revision or attic word's row is written into that word's own pool directory.
- [ ] Recording works in the current Firefox and Chromium on the household network, with nothing loaded from outside
      the parent port.

# Notes

Depends on S023.2 and S005.3, S005.7, S005.8, and S005.9 for the clip library.

- The policy image needs ffmpeg built with libopus, which `policy.clips` needs and the image does not have today.
  `pydub` and `audioop-lts` are already in `policy/requirements.txt`.
- The browser records with `MediaRecorder`, which gives Opus in WebM in Chromium and Opus in Ogg in Firefox.
  `policy.clips.load_recording` already takes a format hint such as `audio/webm;codecs=opus`. The microphone needs a
  secure context, which the HTTPS parent port provides.
- A recording is uploaded as a raw audio body, not base64 inside JSON. `docs/parent-portal.md` says every
  state-changing request is a JSON POST, so a form on another site cannot act with the parent's cookie. That rule is
  widened in the same change:
  - The recording upload endpoint, and only that one, accepts a POST whose `Content-Type` is `audio/webm` or
    `audio/ogg`, with or without a `codecs` parameter. Anything else, including `multipart/form-data`,
    `application/x-www-form-urlencoded`, and `text/plain`, is refused with 415, as a non-JSON body is refused today.
    Every other state-changing endpoint stays JSON-only.
  - A cross-site HTML form can send only those three refused types. A script on another site that sends an audio
    type needs a CORS preflight, which the service never approves. The `SameSite=Lax` cookie is not sent on a
    cross-site POST either.
  - An upload has a size limit well above the longest weekly take, such as 20 MB. A larger body is refused with 413
    before it is decoded, and the dialog says the recording is too long.
- Uploading and cutting are two requests. The upload stores the take as pending and answers with its id. Cut is a JSON
  POST naming that id and the Advanced settings, and answers with the clips. Cutting again with other settings reuses
  the stored take, so a long recording is uploaded once. Pending takes are cleaned up as pending clips are (UC5).
- Pending clips live in a hidden directory under the data directory, so the pool scans skip them and keeping a clip is
  a rename on the same file system.
- The cut, the review state, and the decisions are kept in the page while the dialog is open. Leaving the page throws
  the pending clips away.
