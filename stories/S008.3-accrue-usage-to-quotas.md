# User Voice

As a parent, I want today's YouTube time and bytes charged to the quota I named, per child, so that one child's two hours are not another child's two hours.

# Use Cases

- An observation is stored once under the classified client group and site group, including `default`.
- Each quota's rule set is evaluated on that observation. `allow` and `continue` accrue to that client group's balance. `deny` and `redirect` do not. Falling off the end of the quota's rule set is a continue, so it accrues.
- Time accrued is ended buckets. Bytes include the open bucket. Buckets keep the length they were opened with. The length still divides the local day. Yesterday and other client groups do not count.
- A quota with no byte limit still accrues bytes when its rule set accepts the traffic. The access check against that side stays false, as S008.2 defined.
- School traffic that no quota accepts remains visible on the site group.

# Acceptance Criteria

- [ ] A quota rule set that continues for the entertainment site group and denies otherwise accrues a forwarded YouTube observation and does not accrue Classroom.
- [ ] Two client groups that reference one quota definition have separate balances. One group's ended buckets do not exhaust the other's `time_remaining`.
- [ ] Two quotas whose rule sets both accept the same observation each accrue it once. Overlapping site patterns do not, because classification already picked one site group.
- [ ] With a `2h` limit and five-minute buckets, 23 ended buckets leave `time_remaining` true and 24 make it false. Changing the bucket length to ten minutes leaves the limit at two hours and leaves the stored bucket lengths alone.
- [ ] Bytes already on an open bucket count toward `volume_remaining`. A missing byte limit stores zero and the check stays false, while the bytes are still stored for the report.
- [ ] A denied or redirected decision produces no observation. The proxy's own `403` or `302` is not accrued. The browser's next request is judged on its own.
- [ ] A failed observation does not change the access decision and does not cut the transfer. Grace is stored. S008.6 is what acts on it.
- [ ] Old usage rows keyed only by the previous client and site-group shape do not have to be kept. The store built here is the one S008.4 reads.
