# User Voice

As a parent, I want to see which tasks he attempted, what he answered, and whether he passed, so that I can see what he has learned and where he is stuck.

# Use Cases

- A page lists attempts for a client group, newest first, with the task name, start time, outcome, and duration.
- Opening an attempt shows the stored answers and results in a readable form. Quiz stories add type-specific detail. This story must at least show the raw record cleanly for `parent_check` and for a generic answer list.
- The page is not available to the child. It is served over HTTPS with the parent session from S007.1. A missing session, an idle session, and a session past its lifetime all show the sign-in form and no attempts.
- From this page, a parent records a `parent_check` pass for a client group without the child opening a task. That is the credit described in S003.2.

# Acceptance Criteria

- [ ] A pass, a failure, and an abandonment each appear with the correct outcome and household-local times.
- [ ] An attempt with a list of answers shows each answer, not only the final outcome.
- [ ] The page is protected by the parent session from S007.1. With no valid session it shows the sign-in form and no attempts, including when the idle limit or the lifetime has run out.
- [ ] The parent records a `parent_check` pass for a chosen client group from this page, without the child opening a task. That action is the only way that task type reaches a pass. The new row appears in the list as a pass.

# Notes

Depends on S003.1, S003.2, and S007.1. The client on the page is the client group the attempt was recorded for. Later quiz stories extend the detail view rather than building a second history. The temporary usage-report password from S002.2 is not a session for this page.
