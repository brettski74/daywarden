# User Voice

As a parent, I want each revision task to remember which client group it is for and when it may be used again, so that a quiz he already knows does not come back every afternoon, and a quiz he failed can come back sooner.

# Use Cases

- A task has a type, a name, a body of type-specific configuration, a success cooldown in whole local days, and an optional failure cooldown in whole local days.
- A task is assigned to one or more client groups. Every address in an assigned group is eligible. An address in another group is not.
- An attempt records the client group, the task, the start time, the finish time, the outcome (`in_progress`, `success`, `failure`, or `abandoned`), and a JSON blob of answers and results that the quiz type fills in.
- A task is eligible when it is assigned to that client group and the cooldown for the last finished attempt has elapsed. The success cooldown applies after success. The failure cooldown applies after failure. An abandoned attempt does not start a cooldown. No previous attempt means eligible.
- A cooldown of N days means the task is eligible again on the local date that is N midnights after the finish date. A cooldown of 0 means it is eligible again immediately. A cooldown of 1 means it is eligible again on the next local date.

# Acceptance Criteria

- [ ] A task assigned to one client group is not eligible for a different client group. Two addresses in the assigned group are both eligible, and they see the same attempt history.
- [ ] After a success with a 21-day cooldown, the task is not eligible on day 20 and is eligible on day 21, measured in the household timezone.
- [ ] After a failure with a 1-day failure cooldown and a 21-day success cooldown, the task is eligible again on the next local date.
- [ ] After an abandonment, the task stays eligible.
- [ ] An in-progress attempt for that client group and task is returned if the child comes back, rather than starting a second parallel attempt.
- [ ] Today's success count used by `tasks_required` equals the number of attempts for that client group that reached `success` on the current local date. One success adds one point.
- [ ] A success recorded at 00:10 local time counts toward the new day, not the previous one.
- [ ] Attempt rows survive a restart.
