# User Voice

As a parent, I want the household policy in files I can split by child, so that a nested rule is written once and rejected loudly when a name is wrong.

# Use Cases

- Load one YAML document, including files and one directory level of `*.yaml` and `*.yml` in lexicographic order.
- Define site groups, client groups, time windows, quotas, and rule sets. Each name is unique in its own namespace. The same spelling may be used in two namespaces.
- `entry` names the rule set where access decisions will start. It is required.
- A file already loaded is skipped. An include cycle is not an error. An `evaluate` cycle is.
- DNS names on client groups are resolved at load. A name that fails keeps the addresses from the last successful load.

# Acceptance Criteria

- [x] A missing `entry`, an unknown reference, a second definition of the same name, a duplicate key, and a YAML anchor or alias each fail the load. The previously stored policy stays in force.
- [x] A household setting or a named entity may appear in an included file. A second copy anywhere in the load is an error. A later file does not override an earlier one.
- [x] `default` is rejected as a site-group name and as a client-group name.
- [x] Two site groups with the same priority are rejected. Overlapping site patterns are accepted.
- [x] The same resolved address in two client groups, or twice in one group, is rejected. An IPv4 address and its IPv4-mapped IPv6 form count as the same address.
- [x] A time-window period accepts `day` or `days`, quoted `HH:MM` or `HHMM`, a weekday range such as `monday-thursday` and `friday-tuesday`, and an end suffix `+n` for a whole number of zero or more. Both `day` and `days`, an empty day list, a range whose ends are the same day, a negative `+n`, and an unquoted clock that YAML has turned into a number are rejected.
- [x] A quota accepts a time duration such as `2h` and a byte size such as `720b`, `720k`, `720M`, `720G`, or `720T`. The suffixes are case-sensitive. `720MB`, `720m` as a size, and a bare number are rejected. Omitting either limit stores that limit as zero. Grace defaults to five minutes and `1M` when the file and the quota both omit them. A quota's own grace wins. Zero is allowed. A negative grace is rejected.
- [x] `group` and `groups` are the singular and plural of one list, and so are `window` and `windows`. Specifying both forms, or an empty list, is rejected.
- [x] A missing root file leaves the stored policy in place. A missing included path, when the root file is present, fails the load.
- [x] The decision path may still answer from the previous engine until S008.2. This story's tests cover the loader.

## Change Summary

`policy.hierarchy.load` reads one YAML file and every file it includes. A directory include loads the `*.yaml` and `*.yml` names in that directory, lexicographically, and does not open subdirectories. The loader remembers each file by its canonical path, so a second include of the same file is skipped. An include cycle is that skip. An `evaluate` cycle is a load error.

Household keys (`entry`, `timezone`, `revision_task`, `bucket_length`, `time_grace`, `volume_grace`) and the five namespaces are merged across the files. A second `bucket_length`, a second `entry`, or a second name in the same namespace fails the load. A later file does not replace an earlier definition. Duplicate keys inside one mapping are the same failure. YAML anchors and aliases are rejected, including a merge that would need an alias.

`entry` is required and must name a rule set. References are checked after every file has been read. `default` is a legal reference in a `site_group` or `client_group` condition and is rejected as a name in those two namespaces. Other namespaces may use the spelling. The same spelling may be used in two namespaces; a condition only looks in its own namespace.

The byte limit is written `bytes`. The design shows `time` for the time limit and never names the byte-limit key; `bytes` sits next to `time`, and `volume_grace` stays the grace. An omitted `time` or `bytes` is stored as zero. Grace is five minutes and `1M` (1,048,576 bytes) when both the file and the quota omit it. A quota's own grace wins, including an explicit zero. A negative grace, a bare number, `720MB`, and `720m` as a size are rejected. Duration suffixes are `h`, `m`, and `s`, case-sensitive, same as the size suffixes `b`, `k`, `M`, `G`, and `T`.

Clocks must be quoted `HH:MM` or `HHMM`. An integer that PyYAML made from an unquoted `14:00` or `0700` is rejected, and so is an unquoted `07:00` that the same loader happened to leave as a string. `day` is one weekday. `days` is one weekday, a range such as `friday-tuesday`, or a list of those. The stored weekdays use Monday as 0. A period whose start clock equals its end clock is kept; it is a 24-hour span, not an empty one. `+n` on the end is a whole number of zero or more extra days.

`group` and `groups` are one list, and so are `window` and `windows`. Inline `evaluate` uses `rules`; a named set uses `ruleset`. One of those, not both. An omitted action is continue.

DNS names on client groups are resolved at load through the same helper the TOML loader uses, so an IPv4 address and its IPv4-mapped IPv6 form are one address. A name that does not resolve keeps the addresses stored for that same group and that same written name on the previous policy. With no earlier success, the name contributes no address and the load warns. An empty `addresses` list and an empty `patterns` list are rejected. `bucket_length` still has to divide a 24-hour day. The default remains five minutes.

The load is atomic in the caller's hands. A missing root file returns the `previous` argument unchanged, including when that argument is `None`. Any other problem raises `ConfigError` and does not modify `previous`. Nothing is written to the SQLite policy database. S008.2 is what starts answering decisions from this model.

## Suggested Acceptance Testing

- Run `python -m pytest tests/test_hierarchy.py`. No Docker is needed. This covers the design illustration in `docs/hierarchical-policy.md`, split files, one directory level in lexicographic order, skipped files, include cycles, evaluate cycles, reserved `default`, shared priorities, overlapping patterns, canonical addresses, a DNS name that keeps its last good addresses, clocks and weekday ranges, quota sizes and grace, singular and plural lists, duplicate keys, anchors, aliases, and a failed load leaving the previous policy object in place.
- Run `python -m pytest tests/test_policy_rules.py tests/test_policy_decisions.py`. Those still describe the TOML engine. They should pass unchanged, because this story does not put the YAML loader on the decision path.
- Point `load` at a missing path with a policy already in hand and confirm you get that same object back. Point it at a file that includes a missing path and confirm `ConfigError` and that the object you passed as `previous` still has its old `entry`.
- The byte-limit key to try in a file is `bytes`, for example `bytes: 720M`. `volume` and `byte_limit` are unknown settings and the load will say so.
