# User Voice

As a parent, I want the file the service actually loads to be the household schedule in the new shape, so that we can try it on real sites.

# Use Cases

- Replace `config/policy.toml` with a YAML policy the service loads on startup.
- One client group is the younger child, with a clearly marked placeholder address. The older child is not required in this file.
- School sites are allowed for that child at any time.
- Entertainment uses the Monday-to-Thursday schedule: bedtime denies, school hours redirect to revision, the evening continues only when today's successes reach 2, and a `2h` quota then allows or denies. Friday, Saturday, and Sunday are present and marked as a suggestion, with a wider evening.
- Sites in no configured group are `default` and use the same hours and the same revision count, with no time quota.
- An address in no configured client group is `default` and is not granted access by this file.

## Change Summary

`config/policy.yaml` is the file the decisions service and the observations service load. `entry` is `household`. The timezone is `America/Toronto`. The younger child is the only client group, at the placeholder `192.168.1.40`. The older child stays in a comment that says how to add them. School is priority 10 and is allowed at any time for that child. The patterns are the same Classroom starter list as the old sample. Entertainment is priority 30, quota `2h`, and the Monday-to-Thursday schedule: bedtime denies, school hours redirect to revision, the evening continues only when today's successes reach 2, and the quota then allows or denies. Friday, Saturday, and Sunday are extra periods on those same windows, commented as a starting suggestion, with bedtime until 08:00, revision until 12:00, and evening until 21:00.

A URL in no configured site group is the implicit site group `default`. It uses those same windows and the same revision count, then allows, with no time quota. Outside the evening the message is "The internet is closed for today." An address in no client group is the implicit client group `default`. Nothing in `household` grants that group access, so the request is denied with "No rule granted access.", including Classroom.

The entertainment quota's rule set accepts only the entertainment site group, so school traffic is stored and does not move the two-hour balance. `config/bypass.txt` is still the proxy's own list. Its comment now names the YAML file. The host globs are the ones already there.

`docker compose` defaults `POLICY_FILE` to `/etc/daywarden/policy.yaml` for both services. A `.toml` path is still the previous engine. The addon tests and the S001 service test set that variable to the file they write, so they keep the decision stub and the old ledger. The shipped `config/policy.toml` is gone and is not on that path. The epic line that says no TOML loader remains is not closed by this: the previous engine is still in the process for a `.toml` file a test points at.
