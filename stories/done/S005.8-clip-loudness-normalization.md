# User Voice

As a parent, I want `cut-clips` to bring every recording to the same perceived loudness before it cuts it into clips, so that letters, words, and sentences recorded on different days, in different rooms, or on different microphones play at the same volume, and a spelling assembled from them does not jump between loud and quiet letters.

# Use Cases

- Normalization runs over the whole recording first. The clips are then found in the normalized recording and cut with faded guards as in S005.3 and S005.7, so every step after it sees the normalized audio.
- Loudness is perceived loudness, not peak level: EBU R128 integrated loudness in LUFS, as measured by ffmpeg's `loudnorm` filter. The pauses between items are left out of the measurement by its gating, so a take with long pauses measures the same as one with short pauses. A mono recording is measured as dual mono, which is how it sounds through both speakers.
- One gain is applied to the whole recording. Items keep their loudness relative to each other, and the pauses stay as quiet relative to the speech, so `--threshold` finds the same clips.
- When the gain would push a peak above -1 dBFS, a limiter holds back just those peaks. The gain is not reduced, so the recording still reaches its target loudness.
- A recording that is silent, or shorter than the 400 ms one measurement needs, is left as it is.

| Option | Default | Meaning |
| --- | --- | --- |
| `--loudness LUFS` | `-18` | The perceived loudness the whole recording is brought to before it is cut. From `-40` to `-10`. |
| `--no-normalize` | Off | Cut the recording at the loudness it was recorded, as before this story. |

- The tool prints one line before the clip count or the `--list` output, such as `Loudness -29.4 LUFS, raised 11.4 dB to -18.0 LUFS.`, ending `with peaks limited to -1 dBFS.` when the limiter was used.
- The library offers `measure_loudness` and `normalize`, with the same default target, so a later web page can normalize a browser recording before it offers the clips.

# Acceptance Criteria

- [x] Recordings of the same items at three very different levels are each normalized to within 0.5 LU of -18 LUFS by default, and to within 0.5 LU of -12 LUFS when the target is -12.
- [x] Normalization applies one gain to the whole recording. Two items recorded 12 dB apart are still 12 dB apart afterwards (within 0.1 dB), the recording is the same length, and the same clips are found in it as before normalization.
- [x] A quiet recording with one sharp peak still reaches -18 LUFS (within 0.5 LU), with no sample above -1 dBFS, and the speech away from the peak is raised by the full gain.
- [x] A silent recording, and one shorter than 400 ms, are returned unchanged with a gain of 0.
- [x] Each written clip carries the gain that normalized the whole recording, within 0.5 dB. With `--loudness -24` it carries that target's gain, and with `--no-normalize` it is at the recorded level.
- [x] The loudness line reports the measured loudness, whether the recording was raised or lowered and by how much, the loudness reached, and whether peaks were limited. A recording that cannot be measured is reported as left as it is.
- [x] `--loudness -41`, `--loudness -9`, and `--loudness loud` are refused with a message naming `--loudness`. `normalize` with a target out of range raises `ValueError`.
- [x] The README describes normalization, `--loudness`, the limiter, and `--no-normalize`.
- [ ] Clips cut from two real takes recorded at different levels sound equally loud when S005.2 practice mode spells with them.

# Notes

Follows S005.3 and S005.7, and takes loudness normalization out of S005.3's out-of-scope list.

**Perceived loudness, not peak.** Peak normalization brings the loudest sample of each take to the same level, so a take with one loud plosive ends up quieter than a take without one. Measuring integrated loudness brings takes to the same perceived level, whatever their peaks.

**Why not `loudnorm` to apply the gain.** ffmpeg's `loudnorm` filter in its linear mode drops into dynamic mode whenever the gain would exceed its true-peak limit. Dynamic mode changes the gain through the recording, which would change items' loudness relative to each other and to the pauses that clip detection relies on. Instead, `loudnorm` only measures, ffmpeg's `volume` filter applies one gain, and `alimiter` (with auto-levelling off and latency compensation on, so samples stay aligned) is added only when a peak needs it.

**Target.** -18 LUFS sits between the -16 LUFS that speech podcasts use and the -23 LUFS of broadcast audio, and leaves room for speech peaks below -1 dBFS without limiting most takes. Quieter targets give more headroom, louder ones limit more peaks.

The limiter lowers the loudest peak, and clip detection measures its threshold from the loudest point. A limited recording can therefore treat slightly quieter sounds as speech than the same recording cut with `--no-normalize`.

## Change Summary

- `measure_loudness` pipes the mono 48 kHz samples to `ffmpeg -af loudnorm=print_format=json:dual_mono=true -f null -` and reads `input_i` (integrated LUFS) and `input_tp` (true peak, dBTP) from the JSON it logs. Both are `-inf` for silence, and `input_i` is `-inf` for audio shorter than 400 ms.
- `normalize` computes the gain as the target minus the measured loudness. It applies the gain with `volume`, adding `alimiter=limit=<-1 dBFS>:level=false:latency=true` only when the measured true peak plus the gain is above -1 dB. It then measures the result again, so the reported loudness is what was reached, not what was intended. The output is trimmed to the input's length.
- The command line runs normalization between loading and finding clips, inside the same error handling, so an ffmpeg failure or Ctrl-C there behaves like one during loading. Cutting, fading, and writing are unchanged and work on the normalized audio.

## Suggested Acceptance Testing

1. Record the same few letters twice, once close to the microphone and once from across the room. Cut both into scratch directories with the defaults, and check that each run's first line reports reaching about -18 LUFS. Play a letter from each take back to back, or spell with them in S005.2 practice mode, and confirm they sound equally loud.
2. Run `cut-clips <take> --list` and `cut-clips <take> --list --no-normalize` on a real alphabet take. The first should start with a `Loudness ...` line and the second should not. Both should normally find the same clips.
3. Cut one take with `--loudness -24` and again with the default, name the same item in each, and confirm the `-24` clip is clearly quieter. Then try `--loudness -12` and listen for any harshness in loud consonants where the limiter worked hard.
4. Record a take with one deliberately loud item or a sharp "p", run `cut-clips <take> --list --loudness -12`, and check whether the line ends `with peaks limited to -1 dBFS.` Cut it and listen to that item for distortion.
5. Run `cut-clips <take> --loudness -41`, `--loudness -9`, and `--loudness loud`. Each should stop at once with an error naming `--loudness`, and write nothing.
6. Run `cut-clips --help` and check that `--loudness` shows its default of -18 and its range, and that `--no-normalize` is listed.
7. Make three seconds of digital silence with `ffmpeg -f lavfi -i anullsrc=r=48000:cl=mono -t 3 /tmp/silent.wav` and run `cut-clips /tmp/silent.wav --list`. The first line should say the loudness could not be measured and the recording is left as it is, followed by `0 clips found`. A real recording of a quiet room is usually loud enough to measure, and would be raised to the target.
