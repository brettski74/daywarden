# User Voice

As a parent, I want the proxy to do exactly what the authorization service says for each request: let it through, refuse it with a message, or send the browser to another URL.

# Use Cases

- The addon calls `POST /v1/decisions` with the client IP, method, absolute URL, and time.
- The decision is taken from the request headers, before any request body is forwarded.
- A bypass list of host globs never calls the decision API and is always allowed. This list holds the task site and the Classroom hosts that must work while the policy service is down.
- If the decision API cannot be reached, or returns something other than a recognized decision, the proxy answers `403` for every host that is not on the bypass list.

# Acceptance Criteria

- [x] Given a test double that returns allow, a request through the proxy returns the origin response.
- [x] Given a test double that returns deny with a message, the browser receives HTTP `403` and the response body contains that message. The origin sees no request.
- [x] Given a test double that returns redirect with a location, the browser receives HTTP `302` and a `Location` header with that absolute URL. The origin sees no request.
- [x] A host on the bypass list is forwarded even when the decision API is not running.
- [x] A host not on the bypass list receives `403` when the decision API is not running.
- [x] The addon does not try to answer the `CONNECT` itself with a `302`. The redirect is applied to the decrypted HTTP request.
- [x] Automated tests cover the three decisions and both failure behaviours. A manual check through a browser is recorded in the story notes when this story is implemented.

# Notes

Depends on S000.1. The policy service from S001 can replace the test double later. Until then, a tiny stub that returns a configured decision is enough.

`proxy/addon.py` runs inside mitmdump. `connection_strategy` is `lazy`, so a deny or a redirect does not open an upstream connection. The decision is taken in the request-headers hook. `http_connect` leaves the tunnel acknowledgement alone, and the `302` is written on the decrypted request. `config/bypass.txt` holds the host globs. `decisions/stub.py` answers `POST /v1/decisions` with the bytes in `config/decision.json`, which ships as allow. An unreachable stub, or a body that is not one of the three decisions, becomes `403` with a short HTML page. S001 replaces the stub and leaves the addon in place.

Manual check on 2026-10-18 with Chromium 151.0.7922.108, headless, pointed at the proxy. The origin was the test server, and `tasks.daywarden.test` was on the bypass list.

- Allow: the page showed `daywarden-origin-ok /index.html`. The origin recorded that GET.
- Deny, message `Browser check says no.`: the page showed that sentence. The origin recorded no request for that load.
- Redirect to `http://tasks.daywarden.test/landed`: Chromium followed the `302` and showed `daywarden-origin-ok /landed`. The decision log contains `http://origin/go` and has no entry for the bypassed landing host.
