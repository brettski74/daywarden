# User Voice

As a parent, I want a starting policy that matches the worked example, so that we can try the system on real sites before anyone has built a configuration screen.

# Use Cases

- Load a sample policy from a file in the repository into SQLite.
- The sample enrols one client, the younger child, with a clearly marked placeholder for that computer's reserved IP. The older child's IP is not enrolled. A comment in the file says how to add them later.
- The sample contains three groups: school work, entertainment, and everything else.
- School work is allowed at any time and has no quota.
- Entertainment uses the Monday-to-Thursday schedule from S001.3, a daily revision requirement of 2, and a quota written as `2h`. The file does not store that quota as a number of buckets. Friday, Saturday, and Sunday are present in the file and clearly marked as a starting suggestion, using the same shape of rule with wider evening hours.
- Everything else is the default group. It uses time windows and the same daily revision requirement, and it has no quota.
- The entertainment patterns include `*.youtube.com`, `youtu.be`, `*.youtube-nocookie.com`, `*.googlevideo.com`, `*.ytimg.com`, and `youtubei.googleapis.com`.
- The school-work patterns are a starter list for Google Classroom and the Google hosts a Classroom session actually loads. The file says the list is a starter, not a promise that every school site is covered.

# Acceptance Criteria

- [x] Loading the sample on an empty database, then evaluating the Wednesday times from S001.3 against `https://www.youtube.com/watch?v=abc`, returns the decisions in that table.
- [x] The same Wednesday morning request to a Classroom URL in the starter list is allowed.
- [x] A URL that matches none of the specific patterns is evaluated with the default group's rules.
- [x] Loading the sample twice does not duplicate groups or clients.
- [x] After loading, exactly one client exists, and a decision for that client's IP is the one evaluated in the tests above.
- [x] The addon bypass list is documented next to the sample, listing the school-work hosts and the task-site host. Generating that file automatically can wait for S007.2.

## Change Summary

`config/policy.toml` is now the household's starting policy, not a commented sketch. It still enrols only the younger child, at the placeholder address `192.168.1.40`, and the older child stays in a comment that says how to add them. `household.revision_task` is set to `http://192.168.1.10:8080/tasks/next`, also marked as a placeholder, because the entertainment and default rules redirect to that token and the file will not load without it.

School work is priority 10, has no quota, and its only rule is an unconditional allow. The patterns are a starter for Classroom and the Google hosts a session actually loads: the app, sign-in, Docs, Drive, Sheets, Slides, Forms, and the static and image hosts those pages request. The file says that list is a starter, not every school site and not all of Google. It does not use `*.googleapis.com` or `*.google.com`, so `youtubei.googleapis.com` stays in Entertainment.

Entertainment is priority 30, quota `2h` (stored as 7200 seconds, not a bucket count), and the five Monday-to-Thursday rules from S001.3. The patterns are `*.youtube.com`, `youtube.com` (the star form does not match the bare host), `youtu.be`, `*.youtube-nocookie.com`, `*.googlevideo.com`, `*.ytimg.com`, and `youtubei.googleapis.com`. Friday, Saturday, and Sunday are extra windows on those same three time rules, marked as a starting suggestion: bedtime `00:00–08:00`, revision `08:00–12:00`, and a wider evening `12:00–21:00`. Wednesday is unchanged, so 20:00 is still "YouTube is closed for today." and 20:00 on Friday, Saturday, or Sunday still reaches the revision rule.

Everything else is the default group. It uses those same windows and `tasks_complete` with `required = 2`, then allows. It has no quota. Outside the open window the message is "The internet is closed for today.", so a request that missed every specific pattern is visibly this group's decision.

`config/bypass.txt` lists the School work host globs and `192.168.1.10`, the host of the revision-task placeholder. The temporary `*github.com` line is gone. The two files are kept in step by hand. The comment in each one says so. Generating the bypass list from the policy waits for S007.2.

Loading the file into an empty database, then deciding `https://www.youtube.com/watch?v=abc` for the younger child's IP, returns the Wednesday table: 06:30 bedtime, 10:00 and 16:00 redirect to the placeholder, 20:00 closed. The same Wednesday morning request to `https://classroom.google.com/u/0/h` is allowed. `https://example.org/` is Everything else. A second load keeps the one client and the three groups, ids included. With two revision successes and 24 ended Entertainment buckets, YouTube at 16:00 is "Time is up for today." and the default group still allows.

## Suggested Acceptance Testing

- Run `python -m pytest tests/test_policy_sample.py tests/test_policy_rules.py tests/test_policy_groups.py tests/test_policy_clients.py`. No Docker is needed. These cover the Wednesday YouTube table against the sample file, Classroom allowed on Wednesday morning, an unmatched URL judged by Everything else, one client and no duplicates on a second load, the `2h` quota, the wider Friday-to-Sunday evening, and the bypass list matching the School work hosts plus the task-site host.
- On the real stack, `docker compose up -d --build decisions`. `docker compose logs decisions` should show one client, `Younger child`, the revision-task placeholder, `group School work` with `1 rule` and `no quota`, `group Entertainment` with `5 rules` and `quota 2h`, and `group Everything else` as `default` with `5 rules` and `no quota`.
- With an empty ledger and no revision completions, a Wednesday-evening request to YouTube should redirect to the placeholder. The same request to a Classroom host in the starter list should be allowed. A request to a site in neither list should be denied or redirected by the Everything else hours, not by the YouTube messages.
- Replace `192.168.1.40` with the younger child's real reservation and restart. The log should show that address. Leave the older child commented out and confirm the log still lists one client.
- Add a Classroom host to School work and forget `config/bypass.txt`. The decisions service will allow it, and the proxy will still ask the policy service for it. Add the same glob to `bypass.txt` and the proxy should log `bypass` for that host instead.
- Leave the unit off a quota, `quota = 24`, and confirm the decisions service fails to start. The seconds spelling of the same two hours is `quota = "7200s"`. The sample ships `quota = "2h"`.
