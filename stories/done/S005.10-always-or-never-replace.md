Title: Always or never replace clips

# User Voice

As a parent re-cutting an alphabet or a word list into a directory that already has clips, I want to answer "always" or "never" the first time `cut-clips` asks whether to replace an existing clip, so that I do not have to answer the same question for every one of the 28 letters.

# Use Cases

- The replace question from S005.3 offers four answers: `Replace rope.opus? [y]es/[N]o/[a]lways/ne[v]er`. The same answers are offered when another file is already the clip for the entry, as in `Rope.wav is already the clip for rope. Replace it? [y]es/[N]o/[a]lways/ne[v]er`.

| Answer | Meaning |
| --- | --- |
| `y` or `yes` | Replace this one. |
| `n`, `no`, Enter, or anything else | Keep this one and ask for the clip's name again, as in S005.3. |
| `a` or `always` | Replace this one and every later existing clip without asking. |
| `v` or `never` | Keep this one and every later existing clip without asking. |

- Answers are not case sensitive.
- Always or never lasts for the rest of the run, including later recordings in a S005.9 run, and covers both kinds of replace question.
- Instead of asking again, the tool prints `  Replacing b.opus.` or `  Keeping b.opus.`, so you can see what happened to each existing clip.
- After never, the clip's name prompt is shown again, as after no, so another name can be given or the clip skipped with an empty name.

# Acceptance Criteria

- [x] Answering `a`, `always`, or `A` replaces that clip, and every later existing clip in the run is replaced with a `Replacing <file>.` line and no question.
- [x] Answering `v`, `never`, or `NEVER` keeps that clip, and every later existing clip is kept with a `Keeping <file>.` line and no question. Each time, the name prompt is shown again, and clips with new names are still written.
- [x] Always given in the first recording of a run still applies in the second, including to a clip in another format, such as `dash.mp3` replaced by `dash.opus`.
- [x] `y`, `n`, and Enter behave as before.
- [x] The README describes always and never.

# Notes

Follows S005.3 and S005.9. There is no command-line option to answer in advance. One could be added later if a parent wants to script a re-cut.

# Implementation

## Files Added/Changed/Removed

Added:

- `stories/S005.10-always-or-never-replace.md`: this story.

Changed:

- `policy/clips.py`: new `REPLACE_CHOICES` prompt suffix. `_replace` takes the run's arguments, uses `args.replacing` when always or never was answered earlier in the run, and sets it on `a`/`always` or `v`/`never`. `main` starts each run with no standing answer.
- `tests/test_clips.py`: new tests for always and never in their short, long, and upper-case forms, and for always lasting into a later recording and covering a clip in another format. The two existing replace tests match the new prompt.
- `README.md`: the paragraph on replacing clips describes always and never.
- `stories/S005-spelling.md`: S005.10 is added to the child stories.

Removed: none.

## Change Summary

- The standing answer is kept on the parsed arguments, which already reach every naming function, so it lasts across recordings without changing their signatures.
- Never behaves exactly like answering no each time, including showing the name prompt again, so a re-cut can still write clips under new names.

## Suggested Acceptance Testing

1. Re-cut an alphabet take into `spelling/alphabet` where all 28 clips already exist. Name `a`, answer `a` (always), then name the rest. Each later letter should print `Replacing <letter>.opus.` with no question, and all 28 clips should be new.
2. Re-cut the same take and answer `v` (never) at the first question. Each later existing letter should print `Keeping <letter>.opus.` and show the name prompt again. Press Enter to skip it, and confirm the original clips are untouched.
3. Run two recordings in one command. Answer always in the first, then name a clip in the second that already exists as a `.mp3`. It should be replaced without asking, and only the `.opus` should remain.
4. Answer `y`, `n`, and Enter at separate replace questions and confirm they behave as before: yes replaces, and no or Enter asks for the name again.
5. Answer `ALWAYS` or `Never` in mixed case and confirm they work the same as lower case.
6. Answer something unexpected, such as `maybe`, and confirm it is treated as no.
