# User Voice

As a child doing the spelling quiz, I want a word I have typed correctly to count when the timer runs out, so that I am not marked as timed out on a word I spelled right.

# Use Cases

- He types the word correctly and waits for the timer bar to run out. The page sends what is in the box, and the server counts it as correct.
- He replays the word or hears it in a sentence before the timer runs out. A correct spelling sent when the timer runs out still counts.
- An answer that arrives well after the page's timer could have run out is still a timeout, whatever it says.

# Background

The server starts timing a question when it issues it. The page starts its timer only after the word has been fetched, started, and heard to the end, and it pauses the timer for each replay. The server allowed each clip's length but only half a second in total for everything else. On the household network, answers sent when the timer ran out arrived 0.7 to 1.3 seconds past the clip lengths and the timeout, so every one was judged a timeout, even `plate` typed as `plate`.

# Acceptance Criteria

- [x] Each play of a clip, the first play of the word included, adds that clip's length plus 1.5 seconds to the time the server allows.
- [x] A correct spelling sent when the timer runs out, arriving 1.3 seconds after the word clip plus the timeout, is correct.
- [x] After two word replays and a sentence play, each 1.3 seconds slower than its clip, a correct spelling sent when the timer runs out is correct.
- [x] An answer more than half a second past the allowed time is still a timeout.
- [x] The arithmetic and skip-counting quizzes are unchanged.

# Implementation

## Files Added/Changed/Removed

- Changed `policy/spelling.py`: added `PLAY_ALLOWANCE_MS = 1500`. A new question's `allowed_ms` is the word clip plus the play allowance plus the timeout, and each accepted replay adds that clip's length plus the play allowance.
- Changed `tests/test_spelling.py`: two new tests, one for a correct spelling sent when the timer runs out on the first play and one after replays, both with the 1.3-second overhead seen on the household network. The existing timing tests now include the play allowance.
- Changed `docs/hierarchical-policy.md` to describe the play allowance.

## Change Summary

Every audio play costs more than its length before the page's timer starts or resumes: the clip has to be fetched and started, the "ended" event fires a little after the sound stops, and the requests travel both ways. The server now allows 1.5 seconds for that on each play, on top of the clip's length, as well as the existing half second for the network. The box is disabled while audio plays, so this adds no typing time on screen. The extra time only exists on the server.

Without the allowance, both new tests fail. Questions already issued keep the `allowed_ms` they were issued with, so the change applies from the next word after the service restarts.

## Suggested Acceptance Testing

### Acceptance test cases for S005.5

1. Rebuild with `make up` and open a spelling task. Type a word correctly and wait for the timer bar to run out. Confirm the "correct" sound plays, "Correct!" shows, and the current count goes up.
2. On the next word, press "Repeat word" twice and "Use in a sentence" once (if it has one), type the word correctly, and let the timer run out. Confirm it counts as correct.
3. Type a wrong spelling and let the timer run out. Confirm it is a timeout and the count does not change.
4. Leave the box empty and let the timer run out. Confirm it is a timeout.
5. Type a word correctly and press Enter well before the timer runs out. Confirm it is still correct.
6. Open `/attempts` as a parent, look at the spelling attempt, and confirm the correct answers from cases 1 and 2 are recorded as correct.
