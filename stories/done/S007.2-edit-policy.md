# User Voice

As a parent, I want to change bedtime, the evening window, a site group's patterns, a child's quota, and the household
settings from the parent portal, so that a normal change does not mean editing `policy.yaml` by hand.

# Behaviour

## Pages

The policy pages are a new sidebar group, Policy, holding Client Groups, Site Groups, Time Windows, Quotas, and
Household, at `/parent/policy/client-groups`, `/parent/policy/site-groups`, `/parent/policy/time-windows`,
`/parent/policy/quotas`, and `/parent/policy/household`. Each page edits its whole section at once.

- [ ] Each page shows every item in its section as `config/policy.yaml` and its included files write it, including
      items in an included file. An item outside `policy.yaml` names its file. Site groups are listed by priority,
      the others in file order.
- [ ] Changing a field and changing it back leaves Save disabled. Nothing is written and nothing is committed.
- [ ] Save, Ctrl+S, the Unsaved changes marker, the marks on changed fields, and the leave prompt work as on a task
      page in S023.2.
- [ ] One Save writes every change on the page, to any number of items, as one check, one reload, and one commit
      named for the page, such as `2026-11-18 21:15 -0500 brett: saved site groups`. A save that would not load
      is refused, the status bar lists `dw check`'s reasons word for word, and nothing changes. The check, the hand
      edits found before a save, and the refusal when a file changed after the page opened all work as a task
      save does in S023.2.
- [ ] Each item changed is written in the file that defines it. A new item goes where S036.3 puts one. Comments and
      layout outside the changed entries are kept, so `git diff` after a save shows only the changed lines.
- [ ] Add (Alt+N) adds an empty item at the end of the page with its name box focused. A new item's name can be
      edited until it is saved. After that the name is shown but not editable, because renaming is S007.6.
- [ ] Delete on an item marks it to be removed at the next save, and Undo on the marked item takes the mark away.
      A save that deletes something still in use is refused, and the reason names each thing that uses it, as in
      S036.3, such as `Time window bedtime is used by rule set entertainment_hours, rule 1.`
- [ ] The implicit `default` client group and site group are shown last, read-only, with no Delete. The text says
      `default` holds every address, or every site, that no other group holds. Typing `default` as a new group's
      name is refused with the loader's reason.
- [ ] A saved change is used by the next request through the proxy with no restart, and the page says nothing about
      restarting.
- [ ] Saving never changes `config/bypass.txt`.
- [ ] Without the parent session from S007.1, each page goes to sign-in and comes back to the same page. Its data
      address answers 401 and its save is refused. The child's computer cannot open these pages any more than
      another parent page.

## Client groups

- [ ] Each group has a name and a list of addresses. Each address is an IP or a DNS name, with Add address and a
      remove button on each one. After the address of a computer in `default` is added to `younger`, that computer's
      next request follows `younger`'s rules.
- [ ] One address in two groups, or twice in one group, is refused, and the reason names both places.

## Site groups

- [ ] Each group has a name, a priority (a whole number), and a list of patterns, with Add pattern and a remove button
      on each one. After `*.minecraft.net` is added to `entertainment`, a visit to `www.minecraft.net` counts against
      the entertainment quota on the usage graph and is blocked once that quota is spent.
- [ ] Two groups can swap priorities in one save. Two groups left with one priority are refused, naming both.
- There is no control that makes a site group the default, and a site group has no quota of its own.

## Time windows

- [ ] Each window has a name and one or more periods. A period has a start clock, an end clock, extra days, and the
      weekdays it may start on. Add period and a remove button on each period change the list.
- [ ] Moving the start of Friday's `bedtime` period an hour later lets a site that the window denies load during the
      hour gained, on the next request.
- [ ] A clock box takes `HH:MM`, `H:MM`, or `HHMM` with no quotes. Without a colon it must be four digits. Tabbing
      into a clock box selects all of its text, as other portal fields do. When the box loses focus, its text is
      rewritten as `HH:MM`, so `7:05` and `0705` both become `07:05`. Text that cannot be read as a clock, such as
      `25:00`, `705`, or `7pm`, is left as typed, and Save refuses it with `dw check`'s reason.
- [ ] Save writes each clock quoted in the file, such as `start: "07:05"`. A clock that was not changed keeps its
      text.
- [ ] Extra days is a whole number, 0 or more, that is written as the end's `+n` suffix. 0 is not written. A start of
      `12:00`, an end of `21:00`, extra days `2`, and Friday are written as `end: "21:00+2"` and `days: friday`.
- [ ] A period whose start equals its end is saved, and stays in force for 24 hours from its start.
- [ ] The weekdays are seven toggles, Monday to Sunday. With none on, the period may start on any day, and no `day`
      or `days` is written. A single day is written as `day`. A run of days, wrapping past Sunday if needed, is
      written as a range, such as `days: friday-tuesday`. Any other set is written as a list, such as
      `days: [monday, wednesday, friday]`. A period whose days did not change keeps the text it had.

## Quotas

- [ ] Each quota has a name, a time limit, a byte limit, a time grace, a volume grace, and a rule set chosen from a
      pull-down of every rule set. Raising `entertainment` from `45m` to `60m` on a day when 50 minutes are used lets
      entertainment sites load again until 60 minutes are used.
- [ ] A blank limit or grace is left out of the file. A blank grace shows the household's grace greyed in the box. A
      blank limit shows `Not set`, and its title says that a rule checking that side always takes its false branch.
- [ ] Time is a duration such as `2h`, `90m`, or `7200s`. Bytes take `b`, `k`, `M`, `G`, or `T`, such as `720M`. A
      bare number, `720MB`, and a negative grace are refused with `dw check`'s reasons.

## Household

- [ ] The page edits `entry`, a pull-down of every rule set, and `timezone`, `bucket_length`, `time_grace`,
      `volume_grace`, `host_retention`, and `request_retention`. A blank field is taken out of the file, so its
      default applies, and the default is shown greyed in the box. `entry` cannot be blank.
- [ ] A timezone that is not an IANA name, a bucket length that does not divide a day, such as `7m`, and a retention
      that is not a whole number of days, such as `12h`, are refused with `dw check`'s reasons.
- [ ] Proxy Configuration has the five `direct` switches, `localhost`, `plain_host_names`, `policy_server`,
      `local_subnets`, and `local_domains`, as checkboxes that are on when not written, and the `extra` list with Add
      and remove. Turning `local_subnets` off and adding `*.home.arpa` to `extra` changes what the next fetch of
      the proxy auto-configuration file sends direct. When every switch is on and `extra` is empty,
      `proxy_configuration` is taken out of the file.
- [ ] A setting that is not yet written goes where S036.3 puts it.
- [ ] *For agents:* `update_household` from S036.3 takes `time_grace`, `volume_grace`, `host_retention`,
      `request_retention`, and `proxy_configuration` too. `get_household` lists them, and `null` takes each one out.

# Notes

Depends on S007.1, S007.4, S023.2, and S036.3. Save through `PolicyChanges` in `policy/policy_admin.py`, extended to
take several creates, updates, and deletes as one change. Do not build a second write path. The household fields are
added to `HOUSEHOLD` there, which extends the MCP tool at the same time.

Rule sets are edited in S007.5. Until that story is done, a quota's rule set and `entry` are chosen from the rule sets
already in the file. Renaming is S007.6. `hostname` and `port` stay hand-edited, because a wrong value breaks the
address the parent uses to reach these pages.

A site group's patterns and `config/bypass.txt` are separate. The comment in `policy.yaml` that asks for school hosts in
both is still the parent's job.

Sized at 13: five pages on the same section-editing pattern, a multi-item save on the existing write path, the weekday
and extra-day period controls, and the household and proxy configuration fields. The checks themselves already exist in
`dw check`.

## Change Summary

A policy page reads its section from the files with `PolicyChanges.page`, which finds each item in the file that defines it, and saves with `save_page`, which turns the page's changed items and deleted names into one `PolicyChanges.change`. That is one check, one reload, and one commit named for the page, through the existing `TaskAdmin.change`. There is no second write path, and the MCP tools use the same `change`.

The page sends only the items it changed, and a save writes only the fields whose text differs from the file. A list, such as a group's addresses, is matched to the file's items, so an item left alone keeps its line and comment when another is removed or added. A period's clocks and days keep their text when they did not change: the page sends each period's `origin`, and the service reuses the file's text for every part that reads the same. The `version` of a page is a hash of the policy file and every file that holds an item or a setting, so a hand edit made after the page opened is refused with 409.

Household's blank fields are sent as empty text and taken out of the file. Blank limits and graces on Quotas are handled the same way. The proxy configuration is sent as its switches and `extra`, and only off switches are written. When all are on and `extra` is empty the section is removed.

Not changed: `hostname` and `port` stay hand-edited, and rule sets are still S007.5.

### Acceptance test cases for S007.2

1. **Client Groups and Site Groups** (Pages, Client groups, Site groups). Sign in and open each page from the Policy group. With a site group in an included file, check its file is named and the groups are in priority order. Add a pattern, add a group with Alt+N, delete another, and Save once. Check `git log` and `git diff` in `config`: one commit, `saved site groups`, only the changed lines. Check a swap of two priorities saves and equal ones are refused naming both.
2. **Saving rules** (Pages). Change a field and change it back, then check Save stays disabled. Try Ctrl+S, the Unsaved changes marker, the marks on changed fields, and the leave prompt with Stay as the default. Edit `policy.yaml` by hand after opening a page and check the save is refused. Make a save that would not load, such as `7m` for the bucket length, and check the status bar lists `dw check`'s reasons and nothing changes.
3. **Delete and default** (Pages). Delete `bedtime` while a rule set uses it and check the reason names the rule set and rule. Check Undo, that `default` is shown last with no Delete, and that a new group named `default` is refused.
4. **Time Windows** (Time windows). Move the start of Friday's `bedtime` an hour later and check a denied site loads in the hour gained. Type `7:05`, `0705`, `25:00`, `705`, and `7pm` into a clock box, tab away, and check which are rewritten and that Save refuses the rest. Check extra days `2` with start `12:00`, end `21:00`, and Friday writes `end: "21:00+2"` and `days: friday`, and the weekday toggles write a day, a run such as `friday-tuesday`, and a list.
5. **Quotas** (Quotas). Raise `entertainment` from `45m` to `60m` on a day with 50 minutes used and check entertainment loads again. Clear a limit and check `Not set` and its title, clear a grace and check the household's grace is greyed in, and try `90`, `720MB`, and a negative grace.
6. **Household and Proxy Configuration** (Household). Clear `time_grace`, set `request_retention` to `12h`, and check the refusal. Turn off `local_subnets`, add `*.home.arpa` to extra, save, and fetch the proxy auto-configuration file. Turn everything back on, clear extra, and check `proxy_configuration` is gone from the file.
7. **Sessions** (Pages). Without a session, open each policy page and check sign-in returns to it. Request `/parent/api/policy/site-groups` without a session and check 401. Check `config/bypass.txt` is unchanged after a save.
8. **MCP household tools** (For agents). Call `get_household` and `update_household` with the graces, retentions, and `proxy_configuration`, then with `null` for each.
