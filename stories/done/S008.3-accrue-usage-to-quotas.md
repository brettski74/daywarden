# User Voice

As a parent, I want today's YouTube time and bytes charged to the quota I named, per child, so that one child's two hours are not another child's two hours.

# Use Cases

- An observation is stored once under the classified client group and site group, including `default`.
- Each quota's rule set is evaluated on that observation. `allow` and `continue` accrue to that client group's balance. `deny` and `redirect` do not. Falling off the end of the quota's rule set is a continue, so it accrues.
- Time accrued is ended buckets. Bytes include the open bucket. Buckets keep the length they were opened with. The length still divides the local day. Yesterday and other client groups do not count.
- A quota with no byte limit still accrues bytes when its rule set accepts the traffic. The access check against that side stays false, as S008.2 defined.
- School traffic that no quota accepts remains visible on the site group.

# Acceptance Criteria

- [x] A quota rule set that continues for the entertainment site group and denies otherwise accrues a forwarded YouTube observation and does not accrue Classroom.
- [x] Two client groups that reference one quota definition have separate balances. One group's ended buckets do not exhaust the other's `time_remaining`.
- [x] Two quotas whose rule sets both accept the same observation each accrue it once. Overlapping site patterns do not, because classification already picked one site group.
- [x] With a `2h` limit and five-minute buckets, 23 ended buckets leave `time_remaining` true and 24 make it false. Changing the bucket length to ten minutes leaves the limit at two hours and leaves the stored bucket lengths alone.
- [x] Bytes already on an open bucket count toward `volume_remaining`. A missing byte limit stores zero and the check stays false, while the bytes are still stored for the report.
- [x] A denied or redirected decision produces no observation. The proxy's own `403` or `302` is not accrued. The browser's next request is judged on its own.
- [x] A failed observation does not change the access decision and does not cut the transfer. Grace is stored. S008.6 is what acts on it.
- [x] Old usage rows keyed only by the previous client and site-group shape do not have to be kept. The store built here is the one S008.4 reads.

## Change Summary

An observation is classified once, with the same site-group and client-group rules the decision path uses. It is stored once under that pair, including `default`. Each quota's rule set is then evaluated on that observation, before anything is written. `allow` and `continue` accrue to that client group's balance. `deny` and `redirect` do not. Falling off the end of the set is a continue, so it accrues. A rule that names entertainment and leaves the false branch as continue therefore accrues Classroom too. School traffic that no quota accepts is still on the site-group row.

Time is ended buckets. Bytes include the open bucket. A second report in the same bucket adds bytes and does not open another row or change the length. Yesterday and another client group are left out. Two client groups that share one quota definition have separate rows, so one group's ended time does not move the other's `time_remaining`. Two quotas that both accept the observation each get it once. Overlapping patterns do not, because classification has already picked one site group.

The bucket length stays household-wide and still has to divide the day. The decisions service installs it at startup. The first load only sets the midnight grid. The same length does not close anything. A new length shortens a bucket that is still open, on the site-group rows and the quota rows, and leaves a bucket that has already ended at the length it stored. The quota's `2h` stays two hours. `time_remaining` and `volume_remaining` read this ledger. Both checks are strictly under the limit. An omitted byte limit is zero, so that check stays false, and the bytes are stored anyway. Grace is the value on the quota. It is not added to either check, and a balance past the limit plus the grace is kept. The observation answer is empty. It is not a cut. A failed write rolls back and the access decision is unchanged.

`decide` does not write a row. A redirect or a deny is not an observation. The next request is classified from its own URL. The addon already arms metering only for a flow it is forwarding, so the proxy's own `403` or `302` is not posted.

The new rows are `group_buckets` and `quota_buckets` in the policy database, with the length history in `hierarchy_settings`. The older `usage_buckets` table is not read or written by this path. S008.4 reads `site_buckets`, `client_buckets`, `quota_buckets`, `quota_clients`, `ended_seconds`, and `stored_bytes`. The TOML observation path is unchanged. `docker-compose.yml` gives the observations service the same `POLICY_FILE` and config directory as decisions, so a YAML file is loaded in both processes. The decisions service is the one that installs a new bucket length.
