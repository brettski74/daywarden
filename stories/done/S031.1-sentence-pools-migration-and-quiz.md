# User Voice

As a parent, I want parts-of-speech sentences kept in named pools that tasks reference by name, so that one pool can
feed several tasks and the policy load refuses a task that asks for more correct answers than the pool can supply.

As a child, I want each run to draw unseen sentences from those pools until I pass or the run fails, with the rows
and the time the parent configured for that task.

# Behaviour

## Sentence pools

A sentence pool is a named collection of sorted sentences for `parts_of_speech` tasks. How pools are stored on disk is
the implementer's choice, provided all of the following hold. Unused pools are not loaded into the running policy.
Loading the same file twice is avoided when practical. Each pool has a user-visible name that parents choose. The
service can list every available pool for the portal (S031.2 and S031.3).

- [ ] A pool has a unique user-visible name, a `level_of_difficulty` (a number from 0.5 through 10 inclusive; `1` when
      omitted), and a list of one or more sentences. Sentence shape is as in S006.1 (`sentence`, `parts`, occurrence
      rules, empty rows allowed, at least one word sorted somewhere), except that a sentence may set
      `level_of_difficulty` with the same bounds, which replaces the pool's difficulty for that sentence only, and a
      sentence no longer has a `timeout`.
- [ ] `dw check` loads only pools that at least one `parts_of_speech` task names. A pool file that no task names is
      left out of the policy and is not a load error by itself.
- [ ] Two pools with the same user-visible name are a load error that names both places.

## Task body

A `parts_of_speech` task's `body` no longer has `sentences`. Inline `sentences` is a load error after migration below.

| Field | Default | Value |
| --- | --- | --- |
| `pools` | Required | One or more pool names. Order does not affect selection. |
| `timeout` | `90s` | Base time for a sentence. A duration greater than zero, as today. |
| `parts_of_speech` | Omitted | When set, one or more part names: the rows every sentence in the run uses, in this order. When omitted, each sentence uses the parts it defines in its pool, as today. |
| `correct_answers_required` | Below | Points needed to pass. A whole number from 1 to the runnable size. |
| `minimum_questions` | `correct_answers_required` | Questions finished before a pass or an early failure. From 1 to the runnable size. May be greater than `correct_answers_required`. |
| `maximum_questions` | The runnable size | Questions after which the attempt fails if it has not passed. From the larger of `minimum_questions` and `correct_answers_required` through the runnable size. |

The **runnable size** is the number of sentences across the named pools. Every sentence in those pools is eligible,
including one whose `parts` share no name with a set `parts_of_speech` filter.

Defaults when a field is left out, with `size` the runnable size: `correct_answers_required` is
`min(7, ceil(0.7 × size))`, then `minimum_questions` is that value, then `maximum_questions` is `size`. Each default
is never above `size` or below 1 when `size` ≥ 1.

- [ ] A task that names no pools, names an unknown pool, or names a pool with no sentences, fails the load and names
      the task and the field or pool.
- [ ] A `parts_of_speech` filter entry that is empty, longer than 20 characters, or the same as another apart from case,
      fails the load and names the task and the entry.
- [ ] `correct_answers_required`, `minimum_questions`, or `maximum_questions` outside the ranges above, or a
      `timeout` of zero or a bare number, fails the load and names the task and the field.
- [ ] `level_of_difficulty` on a pool or sentence outside 0.5 through 10 fails the load and names the pool or sentence.
- [ ] A hand-written task that still has `body.sentences`, or a sentence that still has `timeout`, fails the load and
      names the task. Migration below rewrites those before an ordinary start.

## Migration

There is only one installation to move. The rewrite runs when the policy is checked or loaded, before the new rules
refuse the old shape, and commits like other config rewrites when the config history is in use.

- [ ] For each `parts_of_speech` task that still has `body.sentences`, the service writes one new pool whose
      user-visible name is `<task name> sentences`, with a serial suffix such as ` 2` when that name is already taken,
      moves those sentences into it, sets the task's `pools` to that name, and removes `sentences`.
- [ ] A migrated sentence that had its own `timeout` gets `level_of_difficulty` of
      `clamp(sentence_timeout / task_timeout, 0.5, 10)`, omitted when the result is 1. The task's `timeout` stays. The
      pool's `level_of_difficulty` is omitted (default 1).
- [ ] After migration, `dw check` passes on the household files that previously used inline sentences, and the child's
      next run uses the new pools.

## Filter and rows

- [ ] When the task sets `parts_of_speech`, every question shows exactly those rows in that order. Words the pool lists
      under another part belong in no row. A filtered part the sentence does not use is still shown as an empty row, so
      a sentence with no nouns still offers a noun row when `noun` is in the filter.
- [ ] When the task omits `parts_of_speech`, each question's rows are that sentence's parts in pool order, as in S006.2.
- [ ] A sentence whose pool parts share no name with the filter is still asked; every filter row is empty and every word
      belongs in no row.

## Selection and timeouts

A run never asks the same sentence twice. Selection is uniform among the unseen runnable sentences. The code path that
chooses among them should leave room for a later per-pool weight without rewriting the quiz.

- [ ] Each new question is chosen uniformly at random from the runnable sentences not yet asked in this run.
- [ ] The time allowed for a sentence is `ceil(difficulty × task_timeout)` as a whole number of seconds, then the usual
      half-second network allowance. `difficulty` is the sentence's `level_of_difficulty` when set, otherwise the
      pool's. Tries and reloads do not move the deadline, as today.
- [ ] With task `timeout: 60s`, a pool at difficulty `1.5` and no sentence override, that sentence gets 90 seconds. A
      sentence in the same pool with `level_of_difficulty: 0.5` gets 30 seconds.
- [ ] Sorting, tries, points (1 / 0.5 / 0.25), sounds, red marks, the answer display, reload within the deadline, and
      give-up work as in S006.2 and S006.3, against the rows this story defines.

## Pass and fail

End conditions follow the skip-counting model for this task type only. Other task types are unchanged.

- [ ] The attempt **passes** when his points are at least `correct_answers_required` and the number of finished
      questions is at least `minimum_questions`. That counts toward today's revision and shows "Well done".
- [ ] The attempt **fails**, with `failure_cooldown` and a skip day, when his points are still under
      `correct_answers_required` and any of these holds:
  - Finished questions have reached `maximum_questions`.
  - No unseen runnable sentence remains.
  - At least `minimum_questions` are finished, and even full marks (1 point) on every remaining unseen sentence could
    not reach `correct_answers_required`.
- [ ] The start and question screens show his points, the pass mark, and how many questions are finished toward
      `minimum_questions` and `maximum_questions`, such as points and "7 points to pass", without implying every
      runnable sentence will be asked. After a failure the page says the run is finished with his points and the pass
      mark, as today's failure screen does for a finished list.
- [ ] A run in progress keeps the sentences, difficulties, filter rows, and targets it started with after a policy
      edit. His next run uses the new settings.

## Review

- [ ] The parent attempt review for a parts-of-speech run still shows each asked sentence, his tries, and the answer,
      as in S006.4, for the rows he was given (filtered or per-sentence).

# Notes

Depends on S006.1–S006.4 for sentence shape, sorting, and review, and on S011's skip-counting end conditions as the
model for pass and fail. S031.2 and S031.3 replace the portal's inline sentence editor; until they are done, pools and
tasks are accepted through the policy files, `dw check`, and the child's quiz.

Storage hint: a dedicated directory of pool files with a stable id plus a display name, referenced from the task by
name or id, satisfies the load-only-what-is-needed rule if the loader opens only the pools named by tasks. Listing
available pools for the portal can read the directory without attaching every file to the policy. Nested root
`include` is the wrong tool for splicing sentences into a task body; today's `include` only merges top-level
namespaces.

A later per-pool weight should be a weight on each pool membership when building the draw set (or equivalent), not a
second copy of the quiz loop.

Out of scope: weights, Asset Administration, the task page picker, changing arithmetic or skip counting to share these
field names, and spelling under Assets (S032).

Sizing: 21. Migration and the loader rules are about 5. Filter rows, difficulty timeouts, and selection are about 8.
Pass, fail, early fail, and progress are about 8. It stays one story because the runnable size ties validation to the
quiz, and because shipping migration without the new quiz would leave the child unable to run.

## Change Summary

Sentence pools live under `parts_of_speech_pools/` beside the root policy file. Each file has a stable id as its name
and a user-visible `name` that tasks list under `body.pools`. The loader indexes every pool's display name so a
duplicate is a load error, then fully loads only the pools a task names. A task body no longer holds `sentences`. On
check or load with task data mounted and no overrides, any leftover inline sentences are rewritten into a new pool
named `<task name> sentences` (with a serial suffix when needed), a per-sentence `timeout` becomes
`level_of_difficulty`, and the task gets `pools`. Those file writes sit like other hand edits until `dw reload`,
`dw up`, or `dw restart` commits them when the config history is in use; `dw check` alone does not commit.

`correct_answers_required` defaults to `min(7, ceil(0.7 × size))`, with `minimum_questions` and `maximum_questions`
following the skip-counting model against the runnable size. A task may set `parts_of_speech` to fix the rows for every
question. Each new question is drawn uniformly from the unseen runnable set (`runs[].asked`), leaving room for a later
per-pool weight. Allowed time is `ceil(difficulty × task_timeout)` seconds. A run stores a snapshot of resolved
sentences and targets in `detail.settings` so a policy edit does not disturb a run in progress.

The portal's inline sentence editor is unchanged and out of scope until S031.2 and S031.3. Saving sentences from that
page is refused by the new load rules; pools and tasks are accepted through the policy files, `dw check`, and the
child's quiz until those stories land.

## Suggested Acceptance Testing

### Acceptance test cases for S031.1

1. **Migration of the sample tasks.** From a checkout that still had inline sentences (or restore the old shape briefly),
   run `dw check`. Confirm `config/parts_of_speech_pools/` holds one pool per former task, each task body has `pools`
   and no `sentences`, and a second `dw check` passes and writes nothing further. Covers Migration and Sentence pools.
2. **Pool load rules.** Point a task at an unknown pool name, at a pool file with no sentences, and at two pool files
   that share the same `name`. Each `dw check` fails naming the task or both places. Add an unused pool file with a
   unique name: check still passes and that pool is not required by any task. Covers Sentence pools and Task body.
3. **Task body fields.** Hand-edit a task with `timeout: 60s`, `parts_of_speech: [noun, verb]`, and counts; refuse
   `timeout: 0`, a filter duplicate by case, and `correct_answers_required` above the runnable size. Covers Task body.
4. **Filter rows and difficulty timeouts.** With the sample "Parts of Speech" pool at task `timeout: 60s`, set a pool
   difficulty of `1.5` and one sentence at `0.5`. Start a run and confirm those sentences get 90s and 30s. Set
   `parts_of_speech: [noun]` and confirm every question shows only a noun row, including empty when the sentence has
   none; words listed under other parts stay unsorted. Covers Filter and rows and Selection and timeouts.
5. **Selection and scoring.** Complete a run: each sentence appears at most once; wrong tries, red marks, the answer
   table, sounds, reload within the deadline, and give-up still work. Covers Selection and timeouts (inherited behaviour).
6. **Pass, fail, and progress.** With a small pool, confirm early pass at the minimum, early fail when the pass mark is
   out of reach, fail at `maximum_questions`, and the start/question screens show points against the pass mark and
   question progress toward min/max without implying every sentence will be asked. Covers Pass and fail.
7. **Snapshot across a policy edit.** Start a run, change the pool or pass mark in the files, reload the policy, and
   continue the open attempt: the same sentences and targets remain. Start a new run and see the new settings. Covers
   Pass and fail (snapshot).
8. **Review.** Open a finished parts-of-speech attempt in the parent review: each asked sentence, his tries, and the
   answer for the rows he was given are still there. Covers Review.
