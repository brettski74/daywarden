# User Voice

As a parent, I want to change the household's rules from the parent portal, such as the revision count needed before
the evening opens or what bedtime says, without editing `policy.yaml` by hand.

# Behaviour

## Rule set list

- [ ] Rule Sets, in the Policy sidebar group from S007.2, opens `/parent/policy/rule-sets`. It lists every rule set
      with how many rules it has and what uses it: `entry`, quotas, and the rules of other rule sets. Each name is a
      link to that rule set's page, and each user is a link to its page.
- [ ] New Rule Set asks for a name in a `NameDialog`, then writes an empty rule set at once, commits it as
      `created rule set <name>`, and opens its page. A name already in use, or one the loader refuses, keeps the
      dialog open with the reason under the box.

## Rule set page

Each rule set has its own page, `/parent/policy/rule-sets/<name>`, which shows its rules in order and what uses it.

- [ ] Every rule set in `config/policy.yaml` shows on its page as written, including rule sets in included files and
      inline lists. Changing a field and changing it back writes nothing.
- [ ] Save, Ctrl+S, the checks, the refusal, the commit, and the leave prompt work as on the S007.2 pages. The commit
      reads `saved rule set <name>`.
- [ ] Each rule has a condition, from a pull-down of `time_window`, `site_group`, `client_group`, `tasks_required`,
      `time_remaining`, `volume_remaining`, and `always`, and the parameters that condition takes. Windows and groups
      are chosen from many-option pull-downs of that namespace, and the group pull-downs include `default`. Quotas
      are chosen from a pull-down of every quota, and `required` is a whole number. Changing the condition clears
      the parameters that the new condition does not take.
- [ ] One chosen window or group is written as `window` or `group`, and several are written as `windows` or `groups`.
- [ ] Each rule has a True action and a False action, each from `continue`, `allow`, `deny`, `redirect`, and
      `evaluate`. Deny needs a message. Redirect takes `revision_task` or an `http` or `https` URL. Evaluate takes a
      rule set from a pull-down, or Inline rules. An `always` rule shows no False action.
- [ ] An action left as `continue` is left out of the file. A rule written with no `when_false` shows `continue`.
- [ ] An evaluate of a named rule set shows a link to that rule set's page. With unsaved changes, following it asks
      first, as any link does.
- [ ] Inline rules are shown indented beneath their action, with the same rule editor, at any depth. They fold open
      and closed. Choosing Inline rules on an action starts with one empty rule.
- [ ] Beside each inline list, Make Named Rule Set asks for a name in a `NameDialog`. The list then becomes a new rule
      set with that name, and the action becomes an evaluate of it, with a link to its page. This is part of the next
      save, which writes both rule sets in one commit, such as `saved rule set younger, created rule set
      younger_reading`. Until the save, the new name is shown without a link, because its page does not exist yet. A name used by
      another rule set, including one made this way on the page and not yet saved, keeps the dialog open with the
      reason. An inline list nested inside the converted one moves with it and stays inline.
- [ ] *Changed in implementation:* the parts of speech filter list has move buttons and no drag, so the handle uses the
      browser's own drag events within one list. Add rule (Alt+N) adds a rule at the end. Each rule has Insert above, Delete, and a drag handle. Alt+Up and
      Alt+Down move the focused rule within its own list. The rule numbers on the page match the numbers in
      `dw check`'s reasons and in the decision log.
- [ ] Changing a rule changes the next decision. For example, with `tasks_required` changed from 2 to 1 in
      `entertainment_evening`, YouTube opens in the evening after one pass rather than redirecting to the revision
      task.
- [ ] A save that makes an `evaluate` cycle or leaves a deny with no message is refused with `dw check`'s reasons.
- [ ] Delete Rule Set asks first, with Cancel as the default, and deletes at once. It is not part of the next save.
      While `entry`, a quota, or another rule names the rule set, Delete Rule Set is refused, and the refusal names
      each user as in S036.3.

# Notes

Depends on S007.2 for the sidebar group, the page conventions, and the extended `PolicyChanges`. A rule set page saves
its rule set through `PolicyChanges`, and adds a create for each rule set made with Make Named Rule Set, all as one
change. The new rule set goes where S036.3 puts a new item. Rule actions are written on one line, as S036.3 writes them.

Reorder by drag and by keyboard as the parts of speech filter list on the task page does. Do not add a second
drag-and-drop.

Sized at 13: one recursive rule editor with seven conditions and five actions, reordering, inline lists, and the list
page. The checks already exist in `dw check`.

# Implementation

## Files Added

- `policy/portal/src/ruleSets.ts`: the rule model, reading a rule from the file's form and writing it back, change detection, the save request, and moving rules.
- `policy/portal/src/pages/RuleSets.tsx`: the Rule Sets list, a rule set's page, and the recursive rule editor.
- `policy/portal/src/ruleSets.test.tsx`: the rule conversions and both pages in jsdom.
- `tests/test_rule_set_pages.py`: the data address, saves, commits, refusals, and deletes.

## Files Changed

- `policy/policy_admin.py`: a `rule-sets` page that returns each rule set's rules as written, its users, and the names the pull-downs offer. Its save names each commit by what it did. A rule set that already holds the rules sent is skipped, which fixes a failed save of an unchanged rule set.
- `policy/portal/src/pages/Policy.tsx`: `PolicyFrame` is exported, with a heading, a parent crumb, and extra buttons.
- `policy/portal/src/policy.ts`, `routes.tsx`, `components/Fold.tsx`, `styles/layout.css`: the page entry and routes, a `Fold` that can start open, and the rule styles.
- `docs/parent-portal.md`: the Rule Sets pages.

## Change Summary

Both pages read and save through `/parent/api/policy/rule-sets`, on `PolicyChanges` as the other policy pages do. A save sends the rule set only when its rules changed, then each rule set made with Make Named Rule Set, so one commit reads `saved rule set younger, created rule set younger_reading`. New Rule Set and Delete Rule Set are a one-item create and a one-item delete, committed as `created rule set <name>` and `deleted rule set <name>`.

A rule keeps the text the file has for it while it means the same thing, so a rule written `groups: [school]` is not rewritten by a save that changed another rule. A changed rule is written with `window` or `group` for one name and `windows` or `groups` for several, and a continue action is left out. A deny with no message and an evaluate cycle are not held on the page. The service refuses them with `dw check`'s reasons. A rule set made on the page is dropped from the save when nothing evaluates it any more.

Reordering uses the browser's own drag events and Alt+Up and Alt+Down, within one list. `word_sort.js` is not used because it sorts words into cells.

### Acceptance test cases for S007.5

1. **Rule set list** (Rule set list). Open Policy, Rule Sets with the sample policy. Check each count, and that names and users link. Use New Rule Set with a name in use, then a new name, and check `git log` in `config` for `created rule set <name>`.
2. **Rule set page** (Rule set page). Open `entertainment_evening`. Check the rules are numbered as in `dw check`, change a field and change it back, then save a change and check only that rule set's lines changed with `saved rule set entertainment_evening`.
3. **Conditions and actions** (Rule set page). Change `tasks_required` from 2 to 1 and check YouTube opens in the evening after one pass. Change conditions and check parameters clear. Choose one window, then two, and check `window` and `windows`. Set an action to continue and check it is gone from the file. Check a deny with no message and an evaluate cycle are refused with reasons.
4. **Inline rules** (Rule set page). Choose Inline rules on an action, nest another list inside, and fold each. Use Make Named Rule Set, with a name in use first, and check the name has no link until the save, then both rule sets are in one commit.
5. **Ordering** (Rule set page). Use Add rule (Alt+N), Insert above, Delete, the drag handle, and Alt+Up and Alt+Down in a nested list, and check the numbers and Save.
6. **Delete** (Rule set page). Delete a rule set no one uses, check Cancel is the default and the commit is `deleted rule set <name>`. Delete `entertainment_evening` and check the refusal names each user.
