# User Voice

As a parent, I want to see how much time was spent on Classroom and on YouTube, and when, so that I can tell whether the limits match real use.

# Use Cases

- Open a page, choose a client and a site group, and see recent days.
- Each day shows the counted buckets, the time those buckets represent, and the clock times they covered.
- The page works for a group that has no quota, such as school work.

# Acceptance Criteria

- [x] After observations have marked buckets, the page shows those buckets on the correct local day for that client and group.
- [x] A day with no traffic is shown as no usage, not as an error.
- [x] The times displayed are in the household timezone.
- [x] The page is only available to a signed-in parent once S007.1 exists. Until then it is acceptable to protect it with the same temporary password mechanism S007.1 will replace, or to bind it to a note in the story that it must not be left open to the child. The story is not done if the child can open the report with no barrier at all.
- [x] Byte totals for each bucket are visible, so we can later judge whether a volume cap is worth building.

# Notes

Depends on S002.1 and S001.1. The sign-in story may land later. Do not skip the barrier.

S008.4 widens this report so it can be sliced by site group, client group, or quota, including the implicit `default` group. The criteria above are the report that was built.

The temporary barrier is `PARENT_PASSWORD` on the decisions service and a `parent_session` cookie for `/usage`. The password is not stored in SQLite. When it is unset, the page stays closed and shows no usage. S007.1 replaces this cookie. The report port also reaches the decision API, which does not show the report and does not edit policy.

## Change Summary

`GET /usage` on the decisions service is the parent report. It lists the last 14 household-local days for one client and one site group. Each day shows the buckets that contained traffic: the clock times they covered, the length stored on that bucket, and the byte total. A bucket that has not ended is listed and left out of the counted time. A day with no rows says no usage. School work, and any other group with no quota, is listed the same way. Times are the household-local values already stored on the ledger. A UTC observation is shown on the local day and clock, not the UTC clock.

The page stays closed until `PARENT_PASSWORD` is set in the environment that starts `decisions`. With no password, the response is the closed page and contains no client names and no buckets. With a password, a visitor sees a password form and no report. A wrong password does not set a cookie. The right password sets an `HttpOnly` session cookie that ends when the browser closes, and the next `GET /usage` shows the report. A password in the query string does not. `POST /v1/decisions` is unchanged and does not use the cookie.

The decisions service is published on `REPORT_PORT` (8090 in `.env`) so a parent can open `http://<this machine>:8090/usage`. Test stacks publish a free port instead, so they can run while the household stack holds 8090.

- Export `PARENT_PASSWORD` and run `docker compose up -d decisions`. Open `http://<this machine>:8090/usage`. The password form should show no client names and no buckets.
