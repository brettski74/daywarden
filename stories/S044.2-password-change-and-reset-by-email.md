Title: Password Change and Reset by Email

# User Voice

As a parent with a Daywarden account, I want to choose my first password, change it, and reset it from a link sent to
my email address, so that I am the only person who knows it, and I never need whoever runs the host to type one for me.

# Scenarios

## A new reviewer

The admin runs `dw-account add --email nana@example.net nana`. Nana gets a welcome email with a link to the sign-in
screen. A week later she opens it, presses Forgot password, types `nana`, and chooses her password from the link that
arrives.

## A forgotten password on a phone

A month later Nana cannot remember her password. She presses Forgot password on her phone, opens the emailed link, and
types a new password twice. The tab she left signed in on the laptop now has to sign in again, and a second email
tells her that her password was changed.

# Behaviour

## Settings in .env

Email is on when `SMTP_HOST` is set, and off when it is not. Every setting is read at startup, so a change needs
`dw restart`. An email setting that is set but wrong stops the service at startup with a message that names it, in
the same way a bad `PARENT_IDLE` does today.

- [ ] `.env` and `README.md`'s Configuration table describe each new setting and its default:
  - `PARENT_RESET_LIFETIME`: how long a reset link works, as a duration like `PARENT_IDLE`. Defaults to `60m`.
  - `SMTP_HOST`, and `SMTP_PORT`, which defaults to `465`.
  - `SMTP_SECURITY`: `tls`, for TLS from the first byte, as on port 465, or `starttls`, as on port 587. Defaults to
    `tls`. There is no setting for plain text.
  - `SMTP_USERNAME` and `SMTP_PASSWORD`. For forwardemail.net these are the alias and its generated password.
  - `MAIL_FROM`: the sender, such as `Daywarden <daywarden@example.net>`.
- [ ] `PARENT_IDLE` still sets the idle limit of a parent session as before. With `PARENT_IDLE=2m` and a restart, a
      session left alone for 3 minutes must sign in again.
- [ ] With `SMTP_HOST` set and `MAIL_FROM` missing, or with `SMTP_SECURITY=plain`, `SMTP_PORT=abc`, or
      `PARENT_RESET_LIFETIME=0m`, `dw restart` stops with a message that names the setting, and the service does not
      start.
- [ ] Every connection to the mail server is encrypted, and the server's certificate is checked against the system's
      trusted authorities and `SMTP_HOST`. With `SMTP_SECURITY=starttls` against a server that does not offer
      STARTTLS, or a server whose certificate does not match `SMTP_HOST`, nothing is sent, and the username and
      password are never sent. The test email below reports the failure.
- [ ] `SMTP_PASSWORD` is never printed. `dw logs`, `dw-account`'s output, and its error messages do not show it.
- [ ] The code that sends mail is written so that another way of sending, such as a provider's HTTP API, can be added
      without changing the code that writes the emails. `docs/parent-portal.md` says where a new one goes.

## Email from dw-account

- [ ] `dw-account test-email ada` sends a short test email to Ada's address and prints that the mail server accepted
      it. With email off, an account with no address, or a failure, it prints why, such as "Email is off: SMTP_HOST is
      not set" or the mail server's refusal, and exits with status 1. Against forwardemail.net, both
      `SMTP_SECURITY=tls` on 465 and `starttls` on 587 deliver. `dw-account help` describes it.
- [ ] `dw-account add --email nana@example.net nana`, without `--password`, sends nana a welcome email and says so.
      With `--password`, no welcome email is sent. With email off, or when the welcome email fails, the account is
      still added. The command says so with the reason, says that `update --password` sets a password now, and exits
      with status 1.
- [ ] The welcome email is plain text from `MAIL_FROM` with the subject "Your Daywarden account". It names the
      username and role, links to the sign-in screen at `https://<first name in PARENT_NAMES>:<POLICY_PORT>/parent/login`,
      and says to press Forgot password and enter the username to have a link sent for choosing a password. It holds
      no reset link and no password.

## Changing your own password

- [ ] The signed-in line at the bottom of the sidebar, such as "Signed in as ada (admin)", links to the Account page,
      `/parent/account`. It shows the username, the role, and the email address or "No email address. Ask whoever
      runs Daywarden to add one with dw-account." There is nothing to edit on it except the password.
- [ ] Admins and reviewers can both use the Account page. `docs/parent-portal.md`'s Access control lists changing
      your own password as a reviewer write, and says that a reviewer cannot use it to change another account.
- [ ] Change password asks for the current password and the new password twice. A wrong current password, a new
      password left empty or longer than 200 characters, or two new passwords that differ is refused with a message
      on the page, and nothing changes. A current password longer than 200 characters is refused as a wrong one. On
      success the page says "Your password was changed". *Changed in implementation:* both messages are in the status
      bar, where every portal page confirms or refuses its last action, and the three fields are cleared after each.
- [ ] After a change, every other session of that account must sign in again, and the tab that made the change stays
      signed in. The MCP connections the account approved end, and the MCP page's activity log shows why: "the
      parent's password was changed". Other accounts are not affected.
- [ ] The service checks the current password with the same work, and refuses it with the same delay, as a sign-in.
      Repeated wrong current passwords end nothing and change nothing.
- [ ] For the avoidance of doubt, password resets are available to all users, regardless of role.

## Forgotten password

- [ ] With email on, the sign-in screen has a Forgot password link to `/parent/forgot`. With email off, there is no
      link, and `/parent/forgot` says that resetting by email is not set up and to ask whoever runs Daywarden.
- [ ] The Forgot password page asks for a username. After Send link it always says "If that account has an email
      address, a link to reset its password is on its way. It works for 60 minutes." The minutes come from
      `PARENT_RESET_LIFETIME`. The answer and its timing are the same for an unknown username, an account with no
      address, an account in its cooldown, and a mail server that fails. Only the account's own address ever gets a
      link.
- [ ] The email is plain text from `MAIL_FROM`, with the subject "Reset your Daywarden password". It names the
      account, holds the link, says when the link stops working in the household's time, and says that if the parent
      did not ask for it, they can ignore it and nothing changes.
- [ ] The link is `https://<name>:<POLICY_PORT>/parent/reset#<token>`. The token is in the fragment, so a browser never
      sends it to a server in a request line or a Referer. The name is the one the Forgot password page was opened
      with when it is one of `PARENT_NAMES`, so a request from `https://garden:8084/` sends a link to `garden`, and
      from `https://192.168.1.5:8084/` a link to `192.168.1.5`. A request with any other Host header, such as one
      sent with `curl -H 'Host: evil.example'`, gets a link to the first name in `PARENT_NAMES`.
The Reset password page never says whether its link is valid. A valid link is one that was sent, is the newest for
its account, is within `PARENT_RESET_LIFETIME`, and has not been used. Any other link, such as one used already, one
replaced by a newer link, one whose account's password was changed by other means or whose account was removed, or a
token that was never issued, is not valid.

- [ ] Every `/parent/reset#…` link, valid or not, opens the same page: "Choose a new password", two password fields,
      and Save. It shows no username and nothing else about the account, and opening it does not use the link.
- [ ] Two passwords that differ, an empty password, or one longer than 200 characters is refused on the page, with
      a message that says which, whether or not the link is valid.
- [ ] Save with a valid link sets the account's password. It ends every session of that account and the MCP
      connections it approved, with "the parent's password was reset" in the activity log. It does not sign the
      parent in.
- [ ] Save with a link that is not valid changes nothing. The service still hashes the password, and the answer and
      its timing are the same as for a valid link. Either way, the sign-in screen opens with "If your link was still
      valid, your new password is saved. If you cannot sign in with it, ask for a new link with Forgot password."
- [ ] A link works once: after a Save with it, the same link saved again with another password changes nothing, and
      the account signs in with the first. A link saved after `PARENT_RESET_LIFETIME`, after a newer link was sent,
      after `dw-account update --password` or a change on the Account page, or after the account was removed,
      changes nothing in the same way.
- [ ] A second Send link for the same account within 5 minutes of the last one sends no email and shows the same
      answer. The service log notes the skipped request without the address. After 5 minutes a new link is sent, and
      the older link stops working.
- [ ] The data addresses behind the Account, Forgot password, and Reset password pages refuse a request body larger
      than 4 KB with 413 before reading it to the end, as sign-in does in S044.1, and change nothing.
- [ ] The Forgot password and Reset password pages work with no session, keep the portal's sign-in look, and are
      refused over plain HTTP like every parent address. With no parent account, they show the closed portal message
      as the sign-in screen does.
- [ ] For the avoidance of doubt, the forgotten password function is available to all users, regardless of role.

## Notices

- [ ] When an account's password is changed on the Account page, reset by email, or set with
      `dw-account update --password`, and the account has an address, it gets an email with the subject "Your
      Daywarden password was changed". It says which of the three it was and when, says to tell whoever runs
      Daywarden if the parent did not do it, and holds no link. A failure to send it is logged, and the change still
      happens. A reset that sets the first password of an account that had none sends no notice.
- [ ] *Added in implementation:* `dw-account update --password` says "ada was emailed that the password changed.", or
      says why the notice was not sent and still exits with status 0.

## Documentation

- [ ] `README.md`'s Parent accounts section describes the welcome email, choosing the first password through Forgot
      password, changing a password on the Account page, resetting one by email, and `test-email`. It shows a
      forwardemail.net example of the `SMTP_` settings for both ports. The installer's closing hint reads "add the
      first parent with dw-account add --role admin --email ADDRESS USERNAME".
- [ ] `docs/parent-portal.md` describes the Account, Forgot password, and Reset password pages and their data

# Notes

- Depends on S044.1 (`dw-account`, addresses, and accounts with no password), S043 (`REVIEWER_ADDRESSES` and Access
  control), and S036 (MCP connections that end with a password).
- Decided while refining:
  - Settings stay in `.env`, next to `PARENT_IDLE` and `PARENT_LIFETIME`, which already exist. There is no settings
    page. The SMTP password is not in `config/`, which has a git history.
  - Only the host sets email addresses. A portal page for managing accounts is out of scope, as in S043.
  - SMTP with TLS or STARTTLS is the one transport. A forwardemail.net HTTP API transport can be a later story behind
    the same interface. Its main advantage would be working on a network that blocks the mail ports.
  - A new account gets no reset link when it is made, because its parent may not be ready to use it. The welcome
    email only points to the sign-in screen.
  - A password change or reset ends the MCP connections the account approved, as `update --password` does.
  - The reset link uses the requested name only when it is in `PARENT_NAMES`, so a forged Host header cannot send the
    token anywhere else. The port is always `POLICY_PORT`.
  - The Forgot password page takes a username, not an address, because two accounts may share an address.
  - The Reset password page gives the same page and the same answer for every link, so it shows nothing about an
    account or a token. A parent whose link had expired finds out only when the new password does not sign in, and
    the answer tells them what to do then.
- Implementation hints:
  - Add a `password_resets` table holding the SHA-256 of a 256-bit token, the account, and the time it was made, with
    a foreign key to the account that cascades. Keep only the newest row per account. Remove the rows when the
    password changes. Check the lifetime when the token is used, not only when it is read.
  - Send the reset email after the response has been sent, in a background task, so the time of the answer does not
    show whether an email was sent.
  - The Reset password page reads the token from `location.hash`, POSTs it as JSON only on Save, and
    sends `Referrer-Policy: no-referrer`. Add the page's and the Forgot page's data addresses to those open without
    a session, and the Account page's to `REVIEWER_ADDRESSES`.
  - Use `smtplib.SMTP_SSL` and `SMTP.starttls` with `ssl.create_default_context()`, and fail if STARTTLS is not
    offered. Tests can run a local `aiosmtpd` server with a test CA, added to `requirements-dev.txt`.
  - `dw-account` runs in the decisions container, so `test-email` and the welcome email use the same settings as the
    service.
- Out of scope: sign-in throttling and lockout, a minimum password length, resets by an admin for another account,
  changing an address from the portal, HTML email, an email telling a parent their account was removed, and
  two-factor sign-in.
- Sizing: 21 points, full for one story, against S043's 13. It adds the SMTP transport with TLS, tested against a
  local server, the settings and their startup checks, three portal pages, reset tokens with a cooldown, and three
  emails. There are about 28 checks, but the transport, the token handling, and checking the pages in a browser with
  real email make it the larger child.

## Change Summary

Email is a small module with three layers. `mail_settings` turns `.env` into `MailSettings`, or None when
`SMTP_HOST` is not set, and raises `SystemExit` naming a bad setting, so the service stops at startup exactly as for
a bad `PARENT_IDLE`. Compose passes each unset setting as empty, which counts as unset, so the defaults live only in
`policy/mail.py`. `SmtpTransport` uses `smtplib.SMTP_SSL`, or `SMTP` with `starttls`, with
`ssl.create_default_context()`. It refuses before `login` when STARTTLS is not offered, and maps every failure to a
`MailError` in words, none of which can hold the password; `MailSettings` keeps the password out of its repr.
`Mailer` writes plain-text emails and never knows how they are sent.

A reset token is 32 random bytes, sent as hex in the link's fragment and stored as its SHA-256. `password_resets`
has the account id as its primary key, so a new link replaces the old one, and its foreign key cascades on removal.
Any password change deletes the row. The lifetime is checked at use, and a checked token is deleted whether or not
it was still in time.

The two open addresses answer before they touch the database or the mail server. `POST /parent/api/password-reset`
answers at once and does the lookup, the token, and the email in a Starlette background task after the response is
sent; the database part runs on the event loop, where the SQLite connection lives, and the SMTP part on a worker
thread. `POST /parent/api/password-reset/save` checks the two passwords, hashes the new one with Argon2 for every
request, answers, and then applies the hash if the token is valid. So neither the answer nor its time depends on
whether an account, an address, or a token exists. The notices go out the same way. The Account page's change runs
in the request, since its answer must say whether it worked; it checks the new passwords first and then the current
one with the same Argon2 work as sign-in.

`dw-account` reads the same settings in the decisions container. Its emails are sent in the command, and it trusts
the system's authorities, so the tests point `SSL_CERT_FILE` at the test CA. The notice's time is in the policy's
timezone, or the machine's when the policy names none or cannot be loaded.

`Referrer-Policy: no-referrer` is sent on every portal page rather than only the Reset page, since all are one
`index.html` and a client-side navigation keeps the first page's policy.

## Suggested Acceptance Testing

### Acceptance test cases for S044.2

1. **Email settings and test-email.** In `.env`, set the forwardemail.net settings for port 465 with `tls`, then
   `dw restart` and `dw-account update --email YOU ada`, then `dw-account test-email ada`. Repeat with 587 and
   `starttls`. Then try `SMTP_SECURITY=plain`, `SMTP_PORT=abc`, `PARENT_RESET_LIFETIME=0m`, and `SMTP_HOST` with no
   `MAIL_FROM`, each with `dw restart`; then `SMTP_HOST` set to a name the certificate does not cover, such as the
   server's IP address, with `test-email`. Check `dw logs decisions` for the password. Covers Settings in .env and
   test-email.
2. **A new reviewer.** `dw-account add --email YOU nana`, read the welcome email, open its link, press Forgot password,
   enter `nana`, open the reset link, choose a password, and sign in. Check that no password-changed notice came. Then
   `dw-account add --email YOU --password bee` (no welcome), and with `SMTP_HOST` removed and `dw restart`,
   `dw-account add --email YOU cara` (added, exit status 1). Covers Email from dw-account and the first password.
3. **Change password.** Sign in as nana in two browsers and as ada in a third; approve an MCP agent as nana. In the
   first, open the Account page from "Signed in as nana (reviewer)" and try a wrong current password, an empty and a
   201-character new one, and two that differ, then change it. Check the other nana browser, ada's browser, the agent,
   the MCP activity log, and the notice email. Covers Changing your own password and Notices.
4. **Forgotten password.** With email on, from `https://<name>:<POLICY_PORT>/parent/login` use Forgot password for an
   unknown name, an account with no address, and nana twice within 5 minutes; check the answer is the same each time,
   one email arrives, and `dw logs decisions` notes the skipped one without the address. Open the link, try two
   passwords that differ, then save; check the sign-in message, the notice, and that saving the same link again with
   another password changes nothing. Ask for links from two `PARENT_NAMES` and with
   `curl -k -H 'Host: evil.example' -H 'Content-Type: application/json' -d '{"username":"nana"}' https://<name>:<POLICY_PORT>/parent/api/password-reset`
   and check each link's host. Covers Forgotten password.
5. **Links that are not valid.** With `PARENT_RESET_LIFETIME=2m` and `dw restart`, use a link after 3 minutes; a link
   replaced by a newer one (after 5 minutes); one followed by `dw-account update --password`; one followed by an
   Account page change; one whose account was removed; and `/parent/reset#nonsense`. Each shows the same page and
   answer, and the password is unchanged. Covers the validity rule and the single-use check.
6. **Limits and edges.** `curl` each of the three POST addresses with a body over 4 KB (413), over plain HTTP
   (refused), and as a form (415). With `SMTP_HOST` unset, check the sign-in screen has no link and `/parent/forgot`
   says it is not set up. With no parent account, open `/parent/forgot` and `/parent/reset`. With `PARENT_IDLE=2m`, a
   session left 3 minutes must sign in again. Covers the 4 KB, HTTPS, closed-portal, and `PARENT_IDLE` checks.
7. **Documentation.** Read README's Parent accounts and Configuration, `docs/parent-portal.md`, `.env`, and the
   installer's closing hint. Covers Documentation and the transport check.
