# User Voice

As a parent, I want a way to cap how much data a site group can move in a day, so that downloading a pile of videos inside the time quota is not a way around the limit.

# Use Cases

- A group may set an optional daily byte limit beside its time quota.
- A new rule condition `volume_remaining` is true while today's observed bytes for that client and group are under the limit.
- The sample entertainment policy does not enable this condition until a parent turns it on. The first version of the household can run with time buckets only.

# Acceptance Criteria

- [ ] Bytes already stored by S002.1 are what the condition reads. There is no second metering path.
- [ ] A group with no byte limit makes the condition true.
- [ ] Crossing the limit makes a rule that denies on false return `403` with that rule's message.
- [ ] The usage report shows the day's byte total next to the limit when one is set.
- [ ] This story is implemented only after a parent has looked at real YouTube byte totals from S002.2 and chosen a starting limit. The story record notes the totals that justified the number.
