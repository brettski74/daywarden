# OPNsense rule tips

These are the attributes for the rule that blocks a direct path to the internet, so the alias has to use the proxy. They are field values, not a click-through of the UI.

- Group the machines in a Firewall Alias. That alias is the set of hosts forced through the proxy.
- Source and Destination match the IP addresses in the IP packet. They are independent of the route the packet would take through the firewall. Set Source to the alias. Set Destination to any.
- `Interface (rule)` is the interface the matching traffic passes through. On a household LAN, set it to that LAN interface and no other. A more exotic layout is outside these tips.
- Direction is relative to the interfaces listed in `Interface (rule)`. The traffic to block arrives at that interface from another machine, so Direction is `In`.
- Protocol and port can be any, or left blank.
- Version can be IPv4, or any, depending on whether the LAN uses IPv6. Most networks use IPv4. A LAN that already uses IPv6 is outside these tips. The setup note still says that host's IPv6 needs the same treatment when the LAN has IPv6, because an IPv4 reservation does not pin the IPv6 address.

## Change Summary

The parent setup note for the Arch computers names the CA file, the Compose host, and `PROXY_PORT`. It installs the PEM with the system trust tools, then points Firefox and Chromium at the explicit proxy. Firefox is told to turn on `security.enterprise_roots.enabled`, or to import the PEM into its own authorities, and to use a manual proxy for HTTP and HTTPS. The ticket records the OPNsense rule attributes for the direct-path block. Browser tests check that an HTTPS URL is visible to the proxy only after the CA is trusted.

## Suggested Acceptance Testing

- Run `python -m pytest tests/test_child_computer.py`.
- On an Arch computer, copy `data/ca/mitmproxy-ca-cert.pem` and run `sudo trust anchor` on it.
- In Firefox, set `security.enterprise_roots.enabled` to true, set a manual proxy for the proxy host and `PROXY_PORT`, tick "Also use this proxy for HTTPS", restart Firefox, and open an `https` page.
- Put `--proxy-server=http://<proxy-host>:<PROXY_PORT>` in `~/.config/chromium-flags.conf`, restart Chromium, and open an `https` page.
- On the proxy machine, confirm `docker compose logs decisions` shows that page's absolute URL, path included.
- Confirm a certificate warning appears if Firefox's preference is off and the PEM was not imported, and that the URL is missing from the decision log when the browser is not pointed at the proxy.
- Read the OPNsense rule tips and confirm Source is the alias, Destination is any, Interface (rule) is the LAN, and Direction is In.
