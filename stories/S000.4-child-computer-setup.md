# User Voice

As a parent, I want a short setup note for my child's computer, so that the browser trusts the proxy and actually uses it.

# Use Cases

- Install the PEM certificate from S000.1 into the Arch system trust store.
- Point Arch, or the browser on it, at the explicit proxy. Both children's computers run Arch Linux. The note is written for Arch only.
- Know which network paths this proxy cannot see. The household firewall is OPNsense, and the note names the jobs that box must already be doing for the younger child's host. It does not tell anyone how to click through the OPNsense UI.

# Acceptance Criteria

- [ ] The note lives in the repository and names the CA file, the proxy host, and the proxy port from S000.1.
- [ ] It assumes Arch Linux on the child computer. The CA is installed with the system trust tools (`trust anchor`, or a file under the ca-certificates anchors directory followed by `update-ca-trust`). It does not include steps for Windows, macOS, or another distribution.
- [ ] It says that Firefox keeps its own certificate store and does not use the system store unless that is turned on. Any other browser steps are limited to the browser actually in use on those machines.
- [ ] It names OPNsense as the firewall. For the younger child's reserved IP it lists three jobs that box is responsible for: the DHCP reservation, no direct path to the internet, and UDP/443 blocked so QUIC cannot bypass the proxy. It does not include firewall commands or screenshots of the UI.
- [ ] It says IPv6 for that host needs the same treatment when the LAN has IPv6, because an IPv4 reservation does not pin the host's IPv6 address.
- [ ] It says, in one sentence, that an OPNsense schedule is the wrong tool for bedtime. A schedule can only pass or block, and it cannot send him to a quiz.
- [ ] It says that a VPN, a phone hotspot, or IPv6 that does not use the proxy also bypasses the system.
- [ ] It says that applications which pin certificates will not work through the intercepting proxy, and that the intended client is a normal browser.
- [ ] Following the note on a test browser results in an HTTPS request that mitmproxy can see the URL of.
