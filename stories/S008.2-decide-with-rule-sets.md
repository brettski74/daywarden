# User Voice

As a parent, I want each request judged by nested rules, so that bedtime, the evening site list, and the revision requirement can differ by child.

# Use Cases

- Classify the site group by priority, lowest number first. The implicit group `default` is what remains after every configured group misses. It is not tried in between.
- Classify the client group by the single configured group that contains the address. Anything else is the implicit client group `default`.
- Walk `entry`. A rule has one condition. An omitted action is `continue`. `allow`, `deny`, and `redirect` are terminal at every depth. `evaluate` substitutes the child rule set's decision, including `continue`.
- A `continue` that reaches an access evaluation with no parent becomes deny, message "No rule granted access."
- `tasks_required` compares the classified client group's successes for the local date with one count. `time_remaining` and `volume_remaining` are strictly under that quota's limit for that client group. A limit of zero never passes. Grace is not added.
- `revision_task` is still replaced with an absolute URL before the answer leaves the service.

# Acceptance Criteria

- [x] The TOML rule engine is no longer on the decision path. A site group does not own a rule list.
- [x] Friday `14:00` to `14:00` contains Friday 18:00 and does not contain Saturday 14:00. Friday `14:00` to `14:00+1` contains Saturday 18:00 and does not contain Sunday 14:00. Saturday `22:00–07:00` contains Saturday 23:30 and Sunday 06:30, and does not contain Saturday 06:30. The end is exclusive.
- [x] A site that matches two groups is classified as the lower priority number. A site that matches none is `default`. A `site_group` condition sees only that classified name.
- [x] An address in no configured client group is `default`. A rule set that allows only a named client group denies that address with "No rule granted access."
- [x] `evaluate` of a set that allows school and otherwise continues lets the next rule in the caller run. A deny inside the child set denies the request. An `evaluate` cycle fails the load.
- [x] The Wednesday entertainment schedule, expressed as nested rules for one client group, denies at 06:30, redirects at 10:00 and at 16:00 when no task is complete, and denies at 20:00. At 16:00 with the required successes stored and time remaining, it allows. With the time limit exhausted, it denies with the quota rule's message.
- [x] A `volume_remaining` check on a quota whose byte limit was omitted takes the false branch.
- [x] The decision log names the client group, the site group, and the rule that decided.

## Change Summary

A request is classified once, then `entry` is walked. Site groups are tried lowest priority number first. The first pattern match wins, and a miss is the implicit site group `default`. The source address belongs to the one client group whose resolved addresses contain it, or to the implicit client group `default`. A `site_group` or `client_group` condition sees only that classified name. `policy.hierarchy.SiteGroup` has a name, a priority, and patterns. It has no rule list.

`allow`, `deny`, and `redirect` stop the walk at every depth. `evaluate` substitutes the child set's decision. A child `continue` runs the next rule in the caller. A `continue` that comes back to `decide`, which has no parent, is a deny with "No rule granted access." `evaluate` is the same walk for a caller that wants the raw decision, so a quota can still see `continue`. An `evaluate` cycle is still a load error.

A period includes its start and excludes its end. An equal start and end clock is 24 hours. An earlier end clock finishes the next day, and the weekday constraint is the day the period starts, so Saturday `22:00–07:00` covers Saturday night and Sunday morning. `+n` adds that many times 24 hours after that end.

`tasks_required`, `time_remaining`, and `volume_remaining` read a ledger. The default ledger is zero for every group and day. A stored count is per client group and household-local date. Ended seconds and stored bytes are per client group, quota, and date. Both remaining checks are strictly under the limit. A limit of zero, which is what an omitted limit is stored as, never passes. Grace is not added. `revision_task` is replaced with the household URL before the answer is returned. With no URL configured, the answer is a deny and the token stays inside the service.

The decision log records `client_group`, `site_group`, `rule_set`, and `rule_index`. The index counts from 1. An inline list is named by the path of the rule that contains it, such as `entry rule 1 when_true`. When a top-level continue became the deny, `continued` is true and the rule fields are empty.

`POST /v1/decisions` uses this walk when `POLICY_FILE` ends in `.yaml` or `.yml`. `config/policy.toml` is still loaded by the previous engine. S008.5 is the story that stops loading that file. Until S008.3 writes quota balances, and until S003 writes successes, the service ledger returns zero.
