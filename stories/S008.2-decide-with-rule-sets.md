# User Voice

As a parent, I want each request judged by nested rules, so that bedtime, the evening site list, and the revision requirement can differ by child.

# Use Cases

- Classify the site group by priority, lowest number first. The implicit group `default` is what remains after every configured group misses. It is not tried in between.
- Classify the client group by the single configured group that contains the address. Anything else is the implicit client group `default`.
- Walk `entry`. A rule has one condition. An omitted action is `continue`. `allow`, `deny`, and `redirect` are terminal at every depth. `evaluate` substitutes the child rule set's decision, including `continue`.
- A `continue` that reaches an access evaluation with no parent becomes deny, message "No rule granted access."
- `tasks_required` compares the classified client group's successes for the local date with one count. `time_remaining` and `volume_remaining` are strictly under that quota's limit for that client group. A limit of zero never passes. Grace is not added.
- `revision_task` is still replaced with an absolute URL before the answer leaves the service.

# Acceptance Criteria

- [ ] The TOML rule engine is no longer on the decision path. A site group does not own a rule list.
- [ ] Friday `14:00` to `14:00` contains Friday 18:00 and does not contain Saturday 14:00. Friday `14:00` to `14:00+1` contains Saturday 18:00 and does not contain Sunday 14:00. Saturday `22:00–07:00` contains Saturday 23:30 and Sunday 06:30, and does not contain Saturday 06:30. The end is exclusive.
- [ ] A site that matches two groups is classified as the lower priority number. A site that matches none is `default`. A `site_group` condition sees only that classified name.
- [ ] An address in no configured client group is `default`. A rule set that allows only a named client group denies that address with "No rule granted access."
- [ ] `evaluate` of a set that allows school and otherwise continues lets the next rule in the caller run. A deny inside the child set denies the request. An `evaluate` cycle fails the load.
- [ ] The Wednesday entertainment schedule, expressed as nested rules for one client group, denies at 06:30, redirects at 10:00 and at 16:00 when no task is complete, and denies at 20:00. At 16:00 with the required successes stored and time remaining, it allows. With the time limit exhausted, it denies with the quota rule's message.
- [ ] A `volume_remaining` check on a quota whose byte limit was omitted takes the false branch.
- [ ] The decision log names the client group, the site group, and the rule that decided.
