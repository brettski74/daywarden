# User Voice

As a parent, I want an agent to create and change tasks and parts of speech sentence pools, so that I can ask for a
new times table or a pool of verb sentences instead of filling in each page.

# Behaviour

## Writing

These rules apply to every write tool, here and in S036.3.

- [ ] Every write tool takes `dry_run`. With `dry_run: true`, the change is checked and the answer says what would
      change, as a diff of each file. Nothing is written, and the activity log shows it as Checked.
- [ ] A write runs the checks a portal save runs for the same change. A refused write lists every reason, writes
      nothing, and the activity log shows it as Refused with the reasons. `update_task` on an arithmetic task with
      `correct_answers_required: 0` is refused with the same reason the task page gives.
- [ ] A write is in force at once, as a portal save is, with no restart. It is committed to the config history with
      the approving parent and the agent in the message, such as
      `2026-11-17 20:15 -0500 ada via Claude Code: saved task arithmetic/times-7`, and the activity log shows it as
      Done.
- [ ] A write keeps the comments and layout of the rest of the file, as a portal save does.
- [ ] A successful write answers with the thing written, as its read tool would show it now.
- [ ] *Added in implementation:* A save the task page would ask about first, because a client group has already
      passed a task with a due date, is refused with the page's question and "Call again with confirmed: true once
      the parent agrees." The same call with `confirmed: true` is saved.

## Tasks

- [ ] `create_task` (tasks: create) takes a type, a name, and the task's settings, and makes the task as the new task
      page does in S027. The task is then in Task Administration with those settings. A name already in use is
      refused.
- [ ] `update_task` (tasks: update) changes only the fields it names. `{"pass_cooldown": 2}` on `arithmetic/times-7`
      leaves every other field as it was.
- [ ] `rename_task` (tasks: update) renames a task as in S027, and its attempts follow it.
- [ ] *Changed in implementation:* `retire_task` (tasks: delete) takes the task out of the policy, checked, reloaded,
      and committed as a save is. A file in `tasks.d` left with nothing in it is removed; in a file holding other
      tasks, only the task's own lines go. The task's attempts stay stored. The task page has no Retire for a task,
      so this is offered to agents only.
- [ ] A parts of speech task chooses its pools by id. An id that is not a pool is refused.
- [ ] A spelling task's settings and its choice of an existing directory can be changed. Making a directory, and the
      week's words, are not offered: a call that names `words` is refused with "A spelling task's words are set in the
      portal, where they are recorded."

## Sentence pools

- [ ] `create_sentence_pool` (sentence_pools: create) takes a name and sentences, each with its words marked by part
      of speech in the pool file's form, and makes a pool that is then listed under Parts of Speech Pools.
      *Changed in implementation:* it and `update_sentence_pool` also take the pool's `level_of_difficulty`.
- [ ] `update_sentence_pool` (sentence_pools: update) takes `add`, sentences to add, and `remove`, sentences to remove
      by their exact text, applied together. Changing a sentence is removing it and adding the new one. A marked word
      that is not in its sentence is refused, as on the pool page.
- [ ] `rename_sentence_pool` (sentence_pools: update) renames a pool as its page does.
- [ ] `delete_sentence_pool` (sentence_pools: delete) deletes a pool as its page does, and is refused with the page's
      reason while a task uses it.

# Notes

Depends on S036.1. Every tool here wraps the code the portal's task and pool pages already save through, so the
checks, the commits, and the reload after a save are reused, not rebuilt.

A portal page and an agent saving the same task at the same moment get no new handling beyond what two portal tabs
get today.

Sized at 8: eight tools over existing save paths, plus the shared write rules, dry run, and logging that S036.3 also
uses.

# Implementation

## Files Added

- `policy/mcp_writes.py`: the eight write tools. Each turns its arguments into the request the portal page sends and
  saves through the page's own code, then answers with the read tool's view, or a dry run's diff.
- `tests/test_mcp_writes.py`: every tool through `/mcp`, the dry run, refusals and their log entries, the commit
  message, comments kept, the due-date question, pools by id, and the spelling limits.

## Files Changed

- `policy/task_admin.py`: `Agent` and `acting`, which name the agent in a change's commit and stop a dry run after
  the checks. `change` takes the files a change removes, for the dry run's diff. New `file_changes`.
- `policy/task_create.py`: `TaskChanges.retire`, taking a task out of the policy as one checked change.
- `policy/task_edit.py`: `remove_task`, which removes a task's own lines and then an emptied type and `tasks`, and
  `has_entries`.
- `policy/pool_admin.py`: `create` also takes sentences and a level of difficulty, written and checked as a save's
  are. `delete` names its removed file for the dry run.
- `policy/mcp_tools.py`: `Writer`, `WriteRefused`, `WriteFailed`, a `write` flag on `Tool`, and `changes` in
  `Sources`.
- `policy/mcp_server.py`: write tools are run with the caller as their writer and logged as Done, Checked, Refused
  with every reason, or Failed. A write tool's bad argument is logged as Refused.
- `policy/mcp_store.py`: the `checked` outcome.
- `policy/app.py`: gives the MCP tools a `TaskChanges`.
- `policy/portal/src/pages/McpActivity.tsx`: shows `checked` as Checked.
- `tests/test_task_edit.py`: `remove_task`.

## Files Removed

None.

## Change Summary

No save path was rebuilt. `update_task` calls `TaskAdmin.save`, `create_task` and `rename_task` call `TaskChanges`,
and the pool tools call `PoolAdmin`, each with the request body the page would send. The tool reads the file's
version just before saving, so the agent never holds one. A task's settings arrive as one flat `settings` object by
field name, which the tool sorts into the page's `fields`, `settings`, `lists`, `directories`, and `pools`, refusing
every name the type does not have in one answer. Numbers and booleans are turned into the text a page's box would
hold, so the policy check stays the one judge of a value. A pool's sentences arrive in the pool file's form and are
turned into the page's word positions with the loader's own `entry_positions`, so a marked word not in its sentence
gets the loader's message.

The agent and the dry run reach `TaskAdmin.change`, the one place every task and pool save passes through, by a
context variable set for the length of the tool call, rather than a new argument threaded through about ten
methods the portal also calls. With a dry run, `change` runs every check, including the hand-edit check and the
due-date question, and returns before anything is written, moved, reloaded, or committed.

`retire_task` checks the policy with the task gone, so a task some other part of the policy still needs would be
refused with `dw check`'s reason. A file it empties is checked as an empty mapping and then removed.

## Suggested Acceptance Testing

### Acceptance test cases for S036.2

Connect Claude Code as in S036.1 with `tasks: [create, read, update, delete]` and
`sentence_pools: [create, read, update, delete]`, and keep the config directory under git.

1. **A new times table.** Ask the agent to read `arithmetic/times-6` and make `arithmetic/times-7` like it. Check it
   is in Task Administration with the same settings, the commit reads `... ada via Claude Code: created task
   arithmetic/times-7`, the activity log shows Done, and the answer showed the task as `get_task` does. Ask again
   and check the name is refused. Covers create_task and the commit, log, and answer checks.
2. **Changing one field.** Add a comment to a task file. Ask for `{"pass_cooldown": 2}` on a task and check only that
   line changed, the comment is still there, and the task page shows it with no restart. Ask for
   `correct_answers_required: 0` on an arithmetic task and compare the refusal with the task page's, then check
   nothing changed and the log shows Refused with the reasons. Covers update_task and the Writing checks.
3. **Dry runs.** Repeat a change and a retire with `dry_run: true`. Check the answer's diff, that no file changed,
   no commit was made, and the log shows Checked. Covers dry_run.
4. **Due dates.** Give a task a due date, let a group pass it, then ask for another change. Check the refusal asks
   for `confirmed: true`, and that the call with it saves. Covers the added due-date check.
5. **Renaming and retiring.** Rename a task with attempts and check its trend page under the new name. Retire a task
   alone in `tasks.d` and check its file is gone, and retire one from a file holding other tasks and check only its
   lines went. Covers rename_task and retire_task.
6. **Parts of speech and spelling.** Set a parts of speech task's pools by id, then name an id that is not a pool.
   On a spelling task, change `timeout` and choose an existing directory, then name `words` and a directory that
   does not exist, and check both refusals. Covers the pools-by-id and spelling checks.
7. **Pools.** Create a pool of verb sentences and check it under Parts of Speech Pools. Add one sentence and remove
   another in one call, then mark a word not in its sentence and check the refusal. Rename the pool and check the
   tasks using it follow. Delete a pool in use and check the page's reason, then delete an unused one. Covers the
   Sentence pools checks.
