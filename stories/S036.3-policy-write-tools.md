# User Voice

As a parent, I want an agent to change client groups, site groups, time windows, quotas, rule sets, and the household
settings, so that I can ask for a later weekend bedtime or a new blocked site without editing `policy.yaml` by hand.

# Behaviour

## Writing

- [ ] Every tool here writes as in S036.2's Writing area: dry run, the checks, the commit, the log, and the answer.
- [ ] A write is checked as `dw check` checks the whole policy, and a refused write gives the same reasons. Examples
      are a group named `default`, two site groups with one priority, one address in two client groups, a negative
      grace, an unquoted or impossible clock, and both `day` and `days` on one period.
- [ ] A change to something that lives in an included file is written in that file. The rest of `policy.yaml` is
      unchanged.
- [ ] *Added in implementation:* A new item is written in the file that defines the first item of its section, or
      in `policy.yaml` when the section has none. An included file left with no items by a delete keeps its comments
      and holds `{}`.
- [ ] A write never changes `config/bypass.txt`.
- [ ] The implicit `default` client group and site group cannot be created, changed, or deleted.
- [ ] Deleting something still in use is refused, and the reason names each thing using it, such as a rule set whose
      rule names the time window, or a task given to the client group.

## Tools

Each class has a create, an update, and a delete tool, named such as `create_site_group`, `update_site_group`, and
`delete_site_group`, needing that class's create, update, or delete permission. An update changes only the fields it
names, and a list it names, such as `patterns` or `periods`, replaces the whole list. Nothing is renamed: a new name is
a delete and a create.

- [ ] `create_client_group`, `update_client_group`, and `delete_client_group` take a name and `addresses`. After
      `update_client_group` adds a computer's address to `younger`, that computer's browsing follows `younger`'s rules
      without a restart.
- [ ] `create_site_group`, `update_site_group`, and `delete_site_group` take a name, `priority`, and `patterns`.
      After `*.minecraft.net` is added to `entertainment`'s patterns, a visit to `www.minecraft.net` counts against
      the entertainment quota on the usage graph and is blocked when the quota is spent.
- [ ] `create_time_window`, `update_time_window`, and `delete_time_window` take a name and `periods`, each with
      `start`, `end`, and `day` or `days`. An end such as `21:00+2` is accepted, and a period whose start equals its
      end is saved as a 24-hour period. Moving the Friday bedtime start later changes the next decision for a site
      that window blocks.
- [ ] `create_quota`, `update_quota`, and `delete_quota` take a name, `time`, `bytes` with `b`, `k`, `M`, `G`, or `T`,
      `grace`, and `ruleset`. *Changed in implementation:* the grace is `time_grace` and `volume_grace`, as the file
      and `list_quotas` name them, and `null` takes `time`, `bytes`, or a grace out. A `ruleset` that is not a rule set is refused. Raising `entertainment`'s `time` from
      45m to 60m lets entertainment sites through until 60 minutes are used that day, with no restart.
- [ ] `create_rule_set`, `update_rule_set`, and `delete_rule_set` take a name and `rules`, the whole ordered list. An
      action left out is stored as `continue`. `evaluate` names a rule set or holds a list of rules. A rule that names
      a group, window, quota, or rule set that does not exist is refused.
- [ ] `update_household` (household: update) changes `entry`, `timezone`, and `bucket_length`. An `entry` that is not
      a rule set, a timezone that is not an IANA name, and a bucket length that does not divide a day, such as `7m`,
      are refused. *Changed in implementation:* `null` takes `timezone` or `bucket_length` out, back to its default.
      A setting not yet written goes on the line after `entry` in the file that writes `entry`.

# Notes

Depends on S036.1, not on S036.2. S007.2's policy pages should be built on the write path made here, rather than a
second one.

The write path edits the YAML text in place, as `policy/task_edit.py` does for tasks, so comments and layout outside
the changed entry survive. Writing the loaded policy back out with a YAML dumper would lose them.

Renaming a group, window, quota, or rule set is out of scope. Usage and attempts are recorded under group names, and a
rename that rewrote every reference is better done with S007.2's pages.

Sized at 13: the YAML write path for six sections, reference checks for delete, and sixteen thin tools. The policy
checks themselves already exist in `dw check`.

# Implementation

## Files Added

- `policy/policy_admin.py`: `PolicyChanges`, the one write path for client groups, site groups, time windows, quotas,
  rule sets, and the household settings: create, update, delete, and `household`, each answering as a portal save
  does. Also the reference check for a delete.
- `policy/mcp_policy_writes.py`: the sixteen tools, each a thin wrapper over `PolicyChanges` that answers with the item
  as its `list_` read tool shows it.
- `tests/test_mcp_policy_writes.py`: every class through `/mcp`, with decisions posted at fixed times to show each
  change in force: dry run, refusals with `dw check`'s reasons, included files, `default`, deletes in use, quotas
  against stored usage, the Friday bedtime, and the household.

## Files Changed

- `policy/hierarchy.py`: `written()` and `Written`, which say which file writes each named item and setting, and what
  names an item (`Written.users`), read from the files on disk without resolving addresses or reading task data.
- `policy/task_edit.py`: `Quoted`, text always written quoted, for clocks; `Flow`, a mapping written on one line in a
  list item, for rule actions. A flow mapping whose change holds a list at any depth is now written again as a block.
- `policy/task_admin.py`: `TaskAdmin.change` takes no task key for a change to the rest of the policy, and then asks
  nothing about due dates.
- `policy/mcp_tools.py`: `policy_changes` in `Sources`.
- `policy/mcp_server.py`: serves the new tools.
- `policy/app.py`: gives the MCP tools a `PolicyChanges`.

## Files Removed

None.

## Change Summary

`PolicyChanges` builds the change as the nested mapping `task_edit.rewrite_root` already takes, so the YAML is edited
in place by the same code as a task save, and saves it through `TaskAdmin.change`. The hand-edit check, the whole-policy
load with the new text as an override, the dry-run diff, the reload of every service, and the commit naming the agent
are therefore the task path's own, not a second copy. S007.2's policy pages should call `PolicyChanges` too.

A value is written as it would be typed and the loader judges it, so a refusal is `dw check`'s reason word for word. A
clock given as text is always written quoted; one given as a number is written bare so the loader refuses it as
unquoted. A named list replaces the whole list, matched to the old list by place: an item that is the same at its place
keeps its text and comment, a changed one is written again in its place, and extra ones are added or removed at the
end. A plain list that is new or written in flow style, such as `addresses`, is written as one flow list. Rule actions
are written on one line, as the household file writes them.

A delete is refused before the check when anything names the item, listing each user from `Written.users`: tasks for a
client group, rules (inline ones too, such as `rule 3 when_true rule 1`), quotas, `evaluate` actions, and `entry` for a
rule set. The loader would refuse the same delete, but by file position rather than by name. `default` is refused
before the check for an update or delete; a create is left to the loader's own `'default' is reserved`.

## Suggested Acceptance Testing

### Acceptance test cases for S036.3

Connect Claude Code as in S036.1 with `create, read, update, delete` on `client_groups`, `site_groups`,
`time_windows`, `quotas`, and `rule_sets`, and `household: [read, update]`. Keep the config directory under git, and
move the quotas and their rule sets into an included file such as `policy.d/limits.yaml` with a comment in it.

1. **A later Friday bedtime.** Ask the agent to move Friday's bedtime start an hour later. Check only that period's
   lines changed in `policy.yaml`, the commit reads `... ada via Claude Code: saved time window bedtime`, the activity
   log shows Done, and a site the window blocks loads in the hour gained without a restart. Ask for a window ending
   `21:00+2`, and one whose start equals its end, and check both are saved. Covers the Writing checks and
   time windows.
2. **More entertainment time.** Ask to raise `entertainment` from 45m to 60m on a day when about 50 minutes are used,
   and check entertainment sites load again until 60 minutes are used. Check the change is in `policy.d/limits.yaml`,
   its comment survives, and `policy.yaml` is unchanged. Ask for a quota whose `ruleset` is not a rule set and check
   the refusal. Covers quotas and the included file and new item checks.
3. **A new blocked site.** Ask to add `*.minecraft.net` to `entertainment`. Visit `www.minecraft.net`, check it is
   on the usage graph under entertainment, and blocked once the quota is spent. Check `bypass.txt` is unchanged.
   Covers site groups and bypass.txt.
4. **A second computer.** Ask to add a computer's address to `younger`, and check its browsing follows `younger`'s
   rules at once. Ask to put the same address in another group, and check the refusal. Covers client groups.
5. **Refusals.** Ask for each of: a group named `default`, a site group with an existing priority, a negative grace, a
   clock such as `25:00`, a period with both `day` and `days`, a rule naming a window that does not exist, an entry
   that is not a rule set, timezone `Mars/Olympus`, and bucket length `7m`. Compare each reason with `dw check` on the
   same hand edit, check nothing changed, and the log shows Refused with the reasons. Ask to change and to delete the
   `default` client and site groups. Covers the refusal and `default` checks.
6. **Deleting.** Ask to delete the bedtime window, a client group a task is given to, and a rule set a quota uses, and
   check each refusal names every user. Delete an unused window and check it is gone. Delete the last item in an
   included file and check the file keeps its comments and holds `{}`. Covers the delete checks.
7. **Rule sets and household.** Ask for a rule set with an action left out and check `list_rule_sets` shows it as
   `continue`. Repeat one change with `dry_run: true` and check the diff, no file changed, and the log shows Checked.
   Change the timezone and bucket length with `update_household`, and check `get_household` and `dw check`. Covers
   rule sets, household, and dry run.
