# User Voice

As a parent, I want to give `cut-clips` several recordings at once and have it cut each in turn with the same settings, so that a week's words recorded over a few takes, or an alphabet re-recorded in pieces, can be named in one sitting without retyping the command and its options for every file.

# Use Cases

- `cut-clips words-1.m4a words-2.m4a sentences.m4a --out ~/daywarden/spelling/current` cuts the three recordings one after another, in the order given. Every option, such as `--out`, `--guard`, `--loudness`, `--threshold`, `--play`, and `--list`, applies to all of them.
- Each recording goes through the full S005.8 process on its own. Its loudness is measured and normalized over the whole recording, then its clips are found, cut with faded guards, and named. Normalizing each recording to the same target is what makes clips from different takes match.
- With more than one recording, each one's output starts with a heading such as `Recording 2 of 3: words-2.m4a`, followed by its loudness line, clip count, prompts, and summary. A blank line separates recordings. A final line totals the run: `Altogether: wrote 30 clips from 3 recordings, skipped 2.` With one recording, the output is unchanged.
- `--list` lists each recording under its own heading and writes nothing.
- Every recording is checked for existence before anything is cut. If any is missing, the tool names each missing file and stops, so a typo in the third file name is caught before the first is named.
- A recording that exists but that ffmpeg cannot read is reported, and the tool moves on to the next one. The exit status is then 1.
- Ctrl-C or end of input at any prompt stops the whole run, keeps the clips already written, and says how many recordings were not cut.
- The S005.1 pool warnings are checked once, after the last recording. A sentence clip from an early recording is not reported as having no word clip when the word comes in a later one.

# Acceptance Criteria

- [x] Two recordings given together are cut in order with the same settings. Clips from both are written to `--out`, and a `--guard` given once applies to the clips of the second recording too.
- [x] With several recordings, each has a `Recording n of N: <path>` heading, its own `Found ...` line and summary, and the run ends with an `Altogether` total. With one recording there is no heading and no total.
- [x] `--list` with several recordings shows each recording's clips under its heading and writes nothing.
- [x] A missing recording anywhere in the list stops the tool before anything is cut, naming every missing file.
- [x] A file ffmpeg cannot read is reported, the remaining recordings are still cut, and the exit status is 1.
- [x] End of input partway through the first recording stops the run, keeps the clips already written, and reports how many recordings were not cut.
- [x] A `rope.sentence` clip named from the first recording and a `rope` clip named from the second produce no warning. An orphan sentence clip is warned about once, at the end.
- [x] The README describes cutting several recordings in one run.

# Implementation

## Files Added/Changed/Removed

Added:

- `stories/S005.9-cut-several-recordings.md`: this story.

Changed:

- `policy/clips.py`: the `recording` argument takes one or more recordings. `main` checks that they all exist, then cuts each with the new `_cut`, which loads, normalizes, finds, and lists or names one recording and returns a `_Tally` of clips written and skipped, the exit status, and whether the run was stopped. `main` prints the headings and the total, stops on Ctrl-C or end of input, and checks the pool warnings once at the end. `_name_clips` takes the recording's path and no longer warns.
- `tests/test_clips.py`: new tests for cutting two recordings in turn with shared settings, `--list` headings, missing recordings, an unreadable recording among good ones, end of input stopping the run, and pool warnings waiting for the last recording. The single-recording test checks there is no heading or total.
- `README.md`: the "Recording spelling clips" section describes cutting several recordings.
- `stories/S005-spelling.md`: S005.9 is added to the child stories.

Removed: none.

## Change Summary

- The exit status is the worst of the recordings' statuses: 130 after Ctrl-C, 1 after end of input or any recording that could not be read or written, otherwise 0.
- A write failure, such as a full disk, ends that recording as before and moves on to the next one. Ctrl-C and end of input end the whole run, because there is nobody left to answer the prompts.
- Ctrl-C while a recording is being loaded or normalized now says `Stopped before any clip of <path> was written.` The old `Nothing was written.` was wrong once an earlier recording had written clips.

## Suggested Acceptance Testing

1. Record a week's words in two takes and the sentences in a third. Run `cut-clips words-1.m4a words-2.m4a sentences.m4a --out ~/daywarden/spelling/current --play`, name every clip, and check that the clips from all three takes are in the directory, the `Altogether` line adds up, and no warnings are printed.
2. Run `cut-clips a-to-m.m4a n-to-z.m4a --list` on an alphabet recorded in two halves. Each half should be listed under its own `Recording n of 2` heading with its own loudness line, and nothing should be written.
3. Run `cut-clips good.m4a typo.m4a --out /tmp/x`. The tool should name `typo.m4a` as missing and stop at once, with no prompts and no `/tmp/x` created.
4. Run `cut-clips take1.m4a notes.txt take2.m4a --out /tmp/x`. It should report that `notes.txt` could not be read, still cut both takes, and exit with status 1 (`echo $?`).
5. Start a three-recording run and press Ctrl-C at a prompt in the first. Clips already named should be kept, and the tool should say `2 recordings not cut.`
6. Name `rope.sentence` from the first recording and `rope` from the second. There should be no warning at the end. Then name only a sentence clip in a fresh directory and confirm the warning appears once, after the total.
7. Give `--guard 30 --loudness -20` with two recordings and confirm with `ffprobe` that clips from the second recording are about 60 ms longer than their speech, and that both loudness lines report about -20 LUFS.
8. Run `cut-clips` with a single recording and confirm the output looks as it did before, with no `Recording 1 of 1` heading or `Altogether` line.
