Title: Enforce allow, 403, and 302

# User Voice

As a parent, I want the proxy to do exactly what the authorization service says for each request: let it through, refuse it with a message, or send the browser to another URL.

# Use Cases

- The addon calls `POST /v1/decisions` with the client IP, method, absolute URL, and time.
- The decision is taken from the request headers, before any request body is forwarded.
- A bypass list of host globs never calls the decision API and is always allowed. This list holds the task site and the Classroom hosts that must work while the policy service is down.
- If the decision API cannot be reached, or returns something other than a recognized decision, the proxy answers `403` for every host that is not on the bypass list.

# Acceptance Criteria

- [ ] Given a test double that returns allow, a request through the proxy returns the origin response.
- [ ] Given a test double that returns deny with a message, the browser receives HTTP `403` and the response body contains that message. The origin sees no request.
- [ ] Given a test double that returns redirect with a location, the browser receives HTTP `302` and a `Location` header with that absolute URL. The origin sees no request.
- [ ] A host on the bypass list is forwarded even when the decision API is not running.
- [ ] A host not on the bypass list receives `403` when the decision API is not running.
- [ ] The addon does not try to answer the `CONNECT` itself with a `302`. The redirect is applied to the decrypted HTTP request.
- [ ] Automated tests cover the three decisions and both failure behaviours. A manual check through a browser is recorded in the story notes when this story is implemented.
