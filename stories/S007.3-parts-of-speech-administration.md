# User Voice

As a parent, I want to set up a parts of speech task's sentences on its task page by dragging each word into its part
of speech, the same way my son sorts them on his quiz page, so that writing new sentences or fixing a wrong answer
does not mean hand-writing YAML lists and occurrence brackets such as `dry[2]`.

# Scenarios

## Adding a sentence from the keyboard

The parent presses Alt+N and types "The cat sat on the mat.", then Enter. The first row's name, copied from the
sentence above, is selected, so typing "noun" replaces it. Enter, "verb", Enter. That was the last row, so the last
Enter added an empty one, and Enter in that empty row removes it. Then `cat` and `mat` are dragged into noun and `sat`
into verb, and Ctrl+S saves.

# Behaviour

## The page

- [ ] For a `parts_of_speech` task, `/parent/tasks/<name>` shows below the divider, in place of the "not built yet"
      message, the task's settings, then one block per sentence in the policy file's order, then Add sentence. The
      child still gets the sentences in a new random order on each run.
- [ ] The settings are Timeout (`timeout`) and Correct Answers Required (`correct_answers_required`), each label's
      title being its field name. Empty Timeout shows `90s` as its placeholder. Empty Correct Answers Required shows
      70% of the sentences now on the page, rounded up, and follows sentences being added and deleted.
- [ ] The status bar shows how many sentences there are, such as "10 sentences.", and how many have problems.
- [ ] Save, Ctrl+S, the unsaved-changes prompt, the refusal after a hand edit of the policy file, and the config
      history commit work as in S023.2.

## A sentence block

- [ ] Each block is a two-column table laid out like the child's. The top cell spans both columns and holds the
      sentence, in text larger than the rest of the page, with an edit button and a delete button. Below it is one row
      per part of speech, in the order written: on the left the name, in a text box that is always editable, and on
      the right the part's words as written in the sentence, separated by commas, in sentence order when loaded.
- [ ] Under the table are Add row and the sentence's own Timeout box, whose placeholder is the task's Timeout as shown
      on the page, or `90s`. Under those is the block's warning area, which takes no space when it is empty.
- Lucide icons: `square-pen` for Edit sentence, `trash-2` for Delete sentence, `square-plus` for Add row, and
  `square-minus` for Remove row. Each icon-only button's label and title are those words.

## Sorting with the mouse

Sorting works as on the child's quiz page, S006.2 UC3 to UC5, except as below. There is no timer, try, or feedback.

- [ ] A word in no row highlights with a grab pointer while the mouse is over it. Punctuation and spaces never
      highlight. While the sentence is being edited, none of its words highlight or drag.
- [ ] Hovering a sorted word, in the sentence or in its cell, highlights both. It can be dragged only from its cell.
- [ ] Only the right-hand cells of the word's own block take a drop, and the row under the pointer is highlighted.
      Name cells, the sentence cell, and other blocks never highlight or take a drop.
- [ ] Dropping on another row's right-hand cell adds the word to the end of it. Dropping on its own row flies it back
      and changes nothing.
- [ ] Dropping anywhere else flies the word back to the sentence. A word from a cell is then in no row. A word from
      the sentence is unchanged.
- [ ] The two `dry` words in "Dry the dishes with a dry towel." can be sorted into different rows.
- [ ] The child's quiz page looks and sorts exactly as before, as in S006.2 and S006.3, now that it shares its drag
      code with this page.

## Sorting with the keyboard

- [ ] Tab reaches each word the mouse could pick up: the words in no row in the sentence, and the words in cells. The
      focused word is visibly marked.
- [ ] Enter or Space on a word opens a menu beneath it of the block's row names, with a nameless row shown as "(no
      name)". A word in a cell also gets "Not sorted", and its own row is not offered. The menu opens and closes with
      the shared expand animation.
- [ ] The arrow keys move through the menu, Enter chooses, and Escape closes it without changing anything. Choosing
      does what the matching drop would, and focus returns to the word in its new place.

## Editing a sentence

- [ ] The edit button turns the sentence into a focused text box, with the cursor at the end.
- [ ] Enter, Tab, a click elsewhere, or anything else that takes the focus away keeps the text and leaves edit mode.
      Enter also moves the focus to the block's first row name with its contents selected, so typing replaces them. A
      block with no rows gets one empty row, and its name is focused.
- [ ] Escape puts back the text from before this edit, leaves edit mode, and focuses the edit button.
- [ ] After the text changes, each sorted word still in the sentence stays in its row, matched ignoring case and by
      which occurrence it is. The rest leave their rows, and the warning area names them until the page is saved or
      reloaded. Changing "The cat sat on the mat." to "The dog sat on the mat." keeps `sat` and `mat`, and says "No
      longer in the sentence, so taken out of the table: cat." Removing the second `dry` from "Dry the dishes with a
      dry towel." names "dry (2nd)" and leaves the first `dry` where it was.
- [ ] Leaving edit mode with the text cleared, empty or only spaces, when it had text before this edit, asks "Delete
      this sentence?" quoting that text, with Cancel as the default. Delete removes the block. Cancel puts back the
      text, leaves edit mode, and focuses the edit button.
- [ ] Leaving edit mode with the text blank when it was blank before this edit, as in a new block, removes the block
      without asking. Escape does the same.
- [ ] When a block is removed, focus moves to Add sentence.

## Rows

- [ ] Add row adds an empty row at the bottom of its block and focuses its name.
- [ ] Enter in a named row moves the focus to the next row's name with its contents selected, so typing replaces them
      and the arrow keys, Home, and End move the cursor. In the last row, Enter adds an empty row at the bottom and
      focuses it.
- [ ] Enter in an empty name removes that row and adds none. Focus moves to the row that took its place, selected, or
      to Add row when it was the last. A row with words asks "Remove this row? Its words go back to the sentence."
      first, with Cancel as the default. Cancel keeps the row and its focus.
- [ ] The remove button removes its row at once, without asking, and its words can be picked up from the sentence
      again.
- [ ] A row name cannot be typed longer than 20 characters.
- Rows cannot be reordered.

## Adding and deleting sentences

- [ ] Add sentence, or Alt+N anywhere on the page, even while typing in a box, adds a block at the end with its empty
      sentence in edit mode and focused, and scrolls to it. Its rows have the names of the block above, with no
      words. With no block above, it has one empty row. The button's title is "Add sentence (Alt+N)".
- [ ] Alt+N while a sentence is being edited first leaves it as a click elsewhere would, and adds nothing if that asks
      whether to delete the sentence. While a dialog is open, Alt+N does nothing.
- [ ] The delete button asks "Delete this sentence?" quoting the sentence, with Cancel as the default. Delete removes
      the block.

## Warnings and problems

A block's warning area shows warnings, which allow a save, and problems, which do not.

- [ ] A row name that is not a recognized part of speech warns, such as `"Subject" is not a recognized part of
      speech.` A name is recognized when, ignoring case and spaces at the ends, it is in the list below or is one with
      `s` added, so `Nouns`, `VERB`, and `proper nouns` are recognized.
- [ ] These are problems, each shown where it is: an empty row name, a sentence with no words such as one that is only
      punctuation, a sentence with no word sorted, and no sentences at all, shown under Add sentence. While any remain,
      Save is disabled and its title says to fix the problems marked under the sentences first. Ctrl+S says the same
      in the status bar.
- The recognized parts of speech, for review: noun, proper noun, pronoun, verb, participle, gerund, infinitive,
  adjective, adverb, article, determiner, preposition, conjunction, interjection.

## Saving

- [ ] Timeout and Correct Answers Required are written in the task's `body`, and a sentence's Timeout in that
      sentence's entry. Clearing one removes its line. A Correct Answers Required larger than the number of sentences
      is refused, naming the field.
- [ ] Only changed sentences are written again. Every other sentence keeps its text in the file exactly, comments and
      layout included. Comments inside a changed sentence are lost.
- [ ] A changed sentence is written as a block entry with `sentence`, `parts` with one list per row such as
      `noun: [fox, dog]`, and `timeout` when it has one. Words are written as in the sentence, in sentence order, with
      `dry[2]` for a later occurrence, quoted when YAML would read them as something other than text, such as `"yes"`,
      and `[]` for an empty row. `dw check` passes on the result.
- [ ] A new sentence is added at the end of the list, and a deleted sentence's lines are removed.
- [ ] Row names in a written sentence are tidied. A recognized name becomes the listed name, lower case and singular,
      so `Proper Nouns` is written `proper noun`. Any other name is lower-cased, with a plural kept, so `Subject` is
      written `subject`. Two rows that then share a name, such as `Nouns` and `noun`, are written as one row in the
      first one's place, holding the words of both.
- [ ] Until saved, a changed sentence text, row name, or right-hand cell is marked, and a new row or block is marked as
      a whole. After a save no marks remain, and the page shows the file as written, tidied names included.
- [ ] The child's next run asks the saved sentences with the saved answers. A run in progress keeps the sentences it
      started with.

# Notes

Depends on S023.2 for the task page, saving, the policy check, and the config history, and on S006.1 to S006.3 for the
task type, its loader rules, and the child's sorting.

The child's quiz page and this page share one drag-and-drop module, so the two cannot drift apart. The child's drag
code, now inline in `policy/parts_of_speech_page.py`, moves into a plain JavaScript file outside the portal, such as
`policy/static/word_sort.js`:

- The module holds what both pages do: the sorting model (place, remove, which row a word is in, and what a drop
  means), the press-and-move threshold, the copy that follows the pointer, pointer capture, finding the drop target
  under the pointer, the fly-back, highlighting a word with its twin, and blocking the browser's text selection and
  drag image.
- Each page supplies what differs: which elements can be picked up, which take a drop (any row on the child's page,
  only its own block's right-hand cells here), what a drop does, and the flight time. The child's red and blue marks
  stay in the child's page.
- It marks elements with `data-` attributes or calls back to the page, rather than adding classes, because React
  replaces an element's whole class list when it re-renders.
- The child's page inlines the file into its script as it does its own code now, so it still loads nothing else and
  `tests/page_harness.js` still runs it. The portal imports it, with a TypeScript declaration file, and the
  Dockerfile's Node stage copies it in. The file is written so it works both ways.
- Each page styles the shared markers with its own palette, so the child's page looks exactly as it does now. The
  keyboard menu and the sentence editing are the portal's own. `docs/parent-portal.md` says this module is the one
  piece of code the portal and the child's pages share.
- Vitest tests cover the module once. The child's existing page tests show its behaviour is unchanged. Matching words
  by occurrence after a sentence edit is portal code, with its own Vitest tests. The portal's colours are new role
  properties in the theme.

`policy/task_edit.py` rewrites a task's simple fields in place. This story extends it to replace, remove, and append
entries in the body's `sentences` list, keeping untouched text exactly as it was. A `sentences` list written in flow
style, which is unusual, may be written again as a block list as a whole.

Name tidying and row merging happen in the service when it writes a sentence, so they are tested in Python. The page
sends names as typed, and warns using the same list. The list is a portal convention, not a loader rule: `dw check`
does not warn about other names, and a hand-written file may still use any name.

`docs/parent-portal.md` gains two rules: any drag on a parent page has a keyboard way to do the same thing, and a
page's own keys use Alt with a letter, as Alt+N here and Alt+R in the recording dialog do. Browsers keep Ctrl+N,
Ctrl+T, and Ctrl+W for themselves, and Chrome never passes Ctrl+N to the page. `docs/hierarchical-policy.md` says that
saving from the portal tidies part names.

S007.3 was the placeholder for editing every other task type. It now covers parts of speech only. Editing arithmetic
and skip counting tasks, and creating and deleting tasks, are left for stories of their own.

Sizing: the drag-and-drop page alone is like S006.2, 8 points. Moving the child's drag code into the shared module
takes the place of writing a second copy for the portal, so it adds little. The keyboard sorting, sentence editing,
rows, adding and deleting sentences, problems, and the rewrite of the `sentences` list add about as much again as
S023.2's save path did, which makes 21, at the top of one story. It stays one story: it has 40 checks, and its risky
parts, the policy-file rewrite and the child's page moving onto shared code, are each guarded by tests that already
exist.
